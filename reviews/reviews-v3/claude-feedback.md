  - B1 (kimik) /add-source syntax inconsistency → CONFIRMED. commands.md line 111 says /add-source --type … --url … --tags … but 00-mvp.md line 84 says /add-source <url> --tags …. Real contradiction.
  - B2 (kimik) source identity drift → PARTIALLY VALID at spec level. schema.md (line 28) and architecture.md already commit to (kind, identifier, config). The issue lives in 00-mvp.md line 31 which still uses (fetcher, url). So at the spec layer  
  this is an MVP-vs-spec contradiction, not a spec-vs-design one.
  - B3 (kimik) phantom scope table in MVP → CONFIRMED. 00-mvp.md line 34 lists scope / scope_preferences; nowhere else in the spec does a scope table exist.                                                                                            
  - B4 (kimik) chat_memory TTL contradiction → PARTIALLY VALID. The spec is internally consistent (schema invariant 9, D37 both promise TTL). The conflict is with design notes, which is technically out of scope per the review boundary — but it's
  still real and should be reconciled.                                                                                                                                                                                                                  
  - F02 (deepseek) re-eval job → CONFIRMED. Referenced in security.md and verification.md but never specified as a mechanism.
  - F03 (deepseek) verification gaps → CONFIRMED. verification.md has no entries for /stop, /retry, asset commands, or periodic summaries — all explicit v1 commitments.                                                                                
  - F12 (deepseek) post TTL inconsistency → CONFIRMED. D33 says posts have a fixed retention horizon; schema.md invariant 6 only lists derived tables.                                                                                                  
  - F04 (deepseek) group timezone setting → CONFIRMED. schema.md says groups have a timezone; no command sets it; deployment.md is silent on a default.                                                                                                 
  - F01 (mimo) NOTIFY vs. high-water-mark ordering → CONFIRMED. architecture.md asserts the high-water mark is the correctness guarantee but never specifies idempotent processing or transaction boundary.                                             
  - F15 (mimo) multi-instance contract → CONFIRMED. The spec markets "independent scaling" but never says whether running >1 of either service is supported in v1.                                                                                      
  - F05 (deepseek) Nostr kind filter ordering → PARTIAL. D38 actually says: "every received event MUST pass signature verification against its claimed pubkey before Stage 1". The kind-filter-before-sig-verification language deepseek quoted is in   
  security.md, not D38, so the two disagree internally. Real, but not exactly as deepseek framed it.                                                                                                                                                    
  - F22 (mimo) /stop cancels /retry → REJECTED as a finding. D36 already says "any non-/retry input clears the anchor." /stop is non-/retry input. Behavior is unambiguous; just under-emphasized.                                                      
  - F06 (deepseek) translation cache side-channel → VALID but minor. Worth at most an "accepted v1 trade-off" sentence.                                                                                                                                 
  - M30 (kimik) Nostr id 2KB cap & hash fallback → DESIGN-ONLY ARTIFACT. Lives in 02-schema.md; spec is silent. Not a spec defect.

  4. Process recommendations (best practices)
                                                                                                                                                                                                                                                        
  These are not edits; they are habits to keep the spec rock-solid going forward.
                                                                                                                                                                                                                                                        
  1. Spec changes land with verification entries. Any new behavior commitment in docs/spec/* must add or update a row in verification.md in the same change. The reviewers found the gap precisely because later decisions (D35, D36, D38, D39) were    
  added to decisions.md without back-propagating to verification.md.
  2. One source of truth for entities. schema.md is the spec-level entity catalog. Every table that backs a spec-level behavior must appear there with at least its name and an invariant — even if its DDL lives in design. Design notes never         
  introduce a new entity; they realize one.                                                                                                                                                                                                             
  3. Decisions cite section files; section files cite decisions. Bidirectional cross-references catch drift early. Today: D38 says "before Stage 1"; security.md says "before sig verification." Bidirectional cross-links would have surfaced this.    
  4. The MVP is a strict subset, not a parallel universe. 00-mvp.md must use the same identity model and column names as the v1 spec. Any MVP-specific simplification is a projection of the v1 schema, not a different schema.                         
  5. Failure modes are first-class spec content. For every stage that can fail, the spec must answer three questions: (a) what counts as failure? (b) what is the user-visible effect? (c) what is the recovery path? This template alone would have    
  prevented half of the deepseek/mimo findings.      
  6. Concurrency claims need contracts. Every "race-safe," "idempotent," "high-water mark" claim must be backed by an explicit transactional or ordering contract. "Engineering A and Engineering B would build different things" is the smell test.    
  7. Quarterly drift audit. Run a focused review pass like this one (three independent reviewers, evaluator-of-reviewers afterwards) on every minor-version cut. The cost is low (this round's edits total ~9 hours of focused work) and the payback is 
  enormous compared to mid-implementation re-architecture.
