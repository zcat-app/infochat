# M1-658 friendly-error inbound-reflection baseline.
#
# Every ERROR-keyed template-interpolation site in infochat-provider that the
# InboundReflectionGuardTest census cannot auto-classify as trivially
# bot-authored must appear here, with a provenance justification of exactly one
# of three kinds:
#   - bot-admin-only reachable  (a raw echo whose reader is already a bot
#     admin; the gate that enforces it is cited by file:line)
#   - provably-constrained-at-parse  (the echoed value is validated at the
#     parse boundary, e.g. SummaryArgs)
#   - bot-authored  (a controlled-vocabulary / registry / typed / DB value,
#     not inbound-arbitrary text)
#
# Format (5 pipe-separated fields):
#   file | resolved.error.key | argIndex | normalizedArgumentExpression | justification
#
# The guard keys on the FIRST FOUR fields; changing what is interpolated at a
# site changes the fingerprint and invalidates its entry (forcing a conscious
# re-record). A line matching no current site fails noDeadBaselineEntries.
# The auto-classifier only clears shapes that are safe REGARDLESS of argument
# content or type (string/int literals, .size(), local static-final-String
# constants); content-dependent shapes such as String.join(...) and
# String.valueOf(...) are NOT auto-cleared (they can carry inbound text) and
# appear here with an explicit judgment.
# This baseline covers ERROR templates only; see the class Javadoc for the
# boundary and why success/reply paths are out of scope.
#
