OUT-OF-MODEL:
  - `/summary --short` deliberately skips the summarizer-post-cap (>50)
    gate (SummaryCommandHandler.java: the gate is now
    `if (args.form() != SHORT && result.posts().size() > summarizerPostCap)`),
    so a wide window (e.g. `-w 4w`) drives one CategoryRollupGenerator
    roll-up LLM call per category whose prompt (CategoryRollupGenerator.
    buildPrompt, lines 185-211) concatenates EVERY cluster's title/body/
    url — unbounded by the 50-post ceiling the other three forms degrade
    behind. NOT a violation of any §security.md commitment: §Rate
    limiting bounds the RATE of LLM-triggering ops (the per-user bucket
    and per-group backstop still apply to --short, which acquires the
    in-flight slot and draws from the bucket like the other forms), and
    no spec text bounds the /summary summarizer's per-call prompt
    magnitude — `summarizer-post-cap` is an implementation detail, not a
    §security.md promise. The retrieval cluster-cap
    (`infochat.summary.cluster-cap`) bounds the absolute prompt size, and
    the roll-up degrades gracefully on context-overflow (catch → empty →
    routes into the finding above's outage path). Flagged (as r1 opencode
    already flagged it, accepted-out-of-model in the ticket) only so the
    operator can decide whether to extend the model to bound summarizer
    prompt magnitude or apply a roll-up-specific input cap; both candidate
    fixes contradict pinned acceptance (item 2: the roll-up sees ALL
    clusters including past-cap ones).
