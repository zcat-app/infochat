OUT-OF-MODEL:
  - Within-scope cross-USER cache oracle in group scopes. The updated threat
    model (R2 fix, QueryTranslationCache.java:30-43) commits only to
    cross-scope isolation: 'no cross-scope cache state exists: a translation
    produced from one scope's query can never be served to another scope's
    search, and cache hit/miss latency cannot be a cross-scope oracle for
    another user's query text'. In a group scope, all members share the
    (scope_kind='group', scope_id=<groupId>) cache partition, which D58(b)'s
    determinism contract requires. A group member can therefore time repeated
    semanticSearch calls to distinguish hit (fast, no translator call) from
    miss (slow) for a candidate query text and learn whether another member of
    the SAME group previously searched that exact text — a cross-user oracle
    on user-authored query content (the presentation-cache precedent in
    security.md explicitly excludes that class). This sits inside the promised
    scope boundary, so it is not a FINDING against the current model; flagging
    it so the user can decide whether per-user cache partitioning for group
    scopes is worth a spec amendment.
