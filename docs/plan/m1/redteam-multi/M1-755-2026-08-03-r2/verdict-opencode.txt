RED-TEAM VERDICT: FINDINGS

FINDINGS:
  - CATEGORY: DOS
    SEVERITY: high
    PROMISE: >
      security.md §Rate limiting classifies /saved as a cheap command —
      "Parser-only + DB-read paginated commands — /help, /status,
      /list-sources, /get-sources, /get-tags, /saved, /audit, /export,
      /quarantine list and similar. One bucket; high cap; cheap." — while
      "LLM-triggering operations (chat replies + on-demand /summary +
      /retry re-rolls) — its own bucket, capped lower, profile-driven",
      and LlmRateCap's own contract states "a caller cannot bypass the
      cap by switching surfaces". The DOS category of this audit names
      "unbounded LLM calls" and "blocking-the-event-loop in the messaging
      adapter" as defended threats, and the D35 interruptible split
      (InboundRouter step 6) exists so "the transport's single dispatch
      thread is freed the moment intake ends".
    GAP: >
      SavedCommandHandler.buildReply (SavedCommandHandler.java:340-354)
      invokes translationPipeline.runForDisplayHit once per listed row —
      up to PAGE_SIZE=20 synchronous, blocking ModelTask.TRANSLATOR calls
      per /saved invocation. /saved is not in the D35 interruptible class
      (chat-mode, /summary, /retry), so this runs INLINE on the adapter's
      single transport dispatch thread (InboundRouter.java:884
      isInterruptible gate; "everything non-interruptible keeps the
      transport thread's arrival order"), and the diff adds no
      LlmRateCap consultation on this path (LlmRateCap is drawn only at
      chat-mode dispatch InboundRouter.java:1142 and in the /summary /
      /retry handlers), no per-group LLM backstop (group LLM bucket only
      on the chat path, InboundRouter.java:1156), and no per-call
      metering. The only meter is the cheap-command bucket
      (RateCapBucket.java:120, 30 invocations/min per (adapter,
      contactId)) — it charges INVOCATIONS, not the up-to-20 LLM calls
      each invocation makes. The remaining bounds are the 24h
      per-(user, lang) TranslationCache and the profile save cap
      (infochat.save.cap=1000) — both process-local (the cache resets on
      every Provider restart). The diff does not reclassify /saved in
      §Rate limiting, does not draw the LLM bucket, and contains no
      disclosed-exception note of the kind the M1-746 query-anchoring
      leg carries; the "cheap, high cap" promise is silently made
      false.
    REPRO: >
      (1) An invite-gated user sets /lang cs (cs is enabled today — the
      standing posture per security.md §Rate limiting) and fills their
      library to the 1000-save cap (each /save at the 60/min transport
      cap). (2) The user issues /saved: buildReply renders 20 rows whose
      headlines carry source_language 'en' (the V76 default) differing
      from the cs scope, so each row makes a cache-miss translator call
      — up to 20 sequential blocking HTTP calls to the TRANSLATOR
      backend (local llama3.1:8b or a remote provider, both permitted by
      security.md §Rate limiting "may be remote"), on the adapter's
      single dispatch thread. Every other user's inbound on that adapter
      queues behind the call chain for tens of seconds to minutes per
      page. (3) Walking pages 1..50 (30 cheap-command tokens/min permit
      ~600 translator calls/min) burns ~1000 LLM calls per 24h per user,
      unmetered by the per-user LLM bucket (10/min), and re-arms on
      every cache TTL (24h) or Provider restart. A single account turns
      the spec's cheapest command tier into a 20x-amplified,
      LLM-bucket-bypassing generator of synchronous generative calls on
      the transport's dispatch thread.
    SUGGESTED-FIX-CLASS: rate-limit

  - CATEGORY: INFO-LEAK
    SEVERITY: low
    PROMISE: >
      security.md §Secrets handling commits that switch-llm.sh "prints a
      per-task privacy disclosure naming exactly which generative tasks
      now call a remote provider and what each exposes", and characterizes
      the presentation translation legs as bot-prose-only: the M1-746
      query-anchoring leg "is not the bot-prose-only exposure the
      presentation and ingest translation legs imply". §Trust boundaries
      item 9 treats the configured LLM endpoint as potentially hostile,
      and D13 makes saved_post per-user state ("never returns another
      user's saves").
    GAP: >
      The /saved display-hit leg (SavedCommandHandler.java:351-353) sends
      each saved-post HEADLINE — derived from the user's bookmarked post
      title/body (D13 per-user selection) — to ModelTask.TRANSLATOR,
      which the spec permits to be remote. This makes the §Secrets
      handling "bot-prose-only" characterization of the presentation legs
      inaccurate, and no spec text or switch-llm.sh disclosure names this
      payload class: the pending M1-758 disclosure is scoped to the M1-746
      query-anchoring leg. The translated headlines are also retained in
      the shared 24h TranslationCache (per-user partition), which /forget
      does not drain. The diff updates neither the threat model nor the
      disclosure.
    REPRO: >
      An operator runs prod/switch-llm.sh and routes the translator task
      to a remote provider (permitted and disclosed for the M1-746
      query-anchoring leg). Every cs-scope user who then runs /saved
      transmits their saved-post headlines — the user's private bookmark
      profile (the D13-per-user state the /saved cache partition exists to
      isolate) — to that remote provider. The operator's informed
      decision (the entire purpose of the disclosure) covers chat and the
      query-anchoring translator but not this surface, so the exposure
      happens without the spec-committed naming of "what each exposes".
    SUGGESTED-FIX-CLASS: trust-boundary-tightening

OUT-OF-MODEL:
  - >
    /forget does not drain the /saved leg's per-user TranslationCache
    entries: a user's deleted-library headlines stay in the in-memory
    cache up to the 24h TTL after the privacy purge. security.md
    §Secrets handling explicitly accepts this exact residual for the
    M1-746 query cache ("/forget clears chat memory, not this cache...
    accepted for v1 because the store is process-local, never persisted,
    and bounded"), so the /saved leg inherits a documented acceptance
    rather than violating a commitment; flagged so the user can decide
    whether the presentation legs' per-user headline cache warrants a
    /forget drain as a follow-up.
