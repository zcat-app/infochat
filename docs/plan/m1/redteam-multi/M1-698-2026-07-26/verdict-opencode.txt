    GAP: OutboundChokepointArchTest.java:214 gates every flagged call on
         `MESSAGING_ADAPTER.equals(target.getOwner().getName())`. ArchUnit
         takes a method call's target owner from the bytecode
         INVOKEINTERFACE/INVOKEVIRTUAL constant-pool entry, which carries the
         STATIC declared type at the call site — not the dispatched method's
         declaring interface. The guard therefore only fires for call sites
         whose receiver is declared as `MessagingAdapter`. A seventh call site
         written against a concrete adapter subtype — e.g. a provider class
         that holds/injects `app.zcat.infochat.messaging.impl.simplex.
         SimpleXAdapter` (a real public class; confirmed present under
         infochat-messaging-adapter/.../impl/simplex/SimpleXAdapter.java) and
         writes `simplexAdapter.send(msg)` — compiles to `INVOKEVIRTUAL
         ...SimpleXAdapter.send`, whose target owner is `SimpleXAdapter`, so
         the owner test at line 214 is false, the call is `continue`d at line
         215, and the violator is never recorded. The guard passes green. The
         two existing allowlisted callers happen to use `MessagingAdapter`-
         typed locals (OutboundDelivery.java:143/154/190/221/234;
         DigestDelivery.java:172/204/207), so they are the ONLY shape the test
         can see today. A second evasion of the same detection-model limit:
         reflective invocation
         (`MessagingAdapter.class.getMethod("send",...).invoke(adapter,msg)`)
         is recorded by ArchUnit as a call to `java.lang.reflect.Method.invoke`,
         whose owner is not `MessagingAdapter`, so it is equally invisible.
         Both contradict "a direct `adapter.send` from a seventh call site ...
         is therefore unlandable in CI": such a call site — concrete-typed or
         reflective — IS landable in CI with the build green. Because
         `OutboundDelivery.neutralizeLinkSyntax` (OutboundDelivery.java:142/
         153/189/219/232) is the sole place `](` adjacency is broken, any
         direct (non-chokepoint) send ships an unbroken `](`, re-opening the
         link-syntax smuggling vector M1-691's chokepoint exists to close.
         (Not currently exploitable: grep of infochat-provider/src/main for
         .send(/.update(/.finalizeMessage( returns only OutboundDelivery and
         DigestDelivery, both interface-typed; the gap is in the guard's
         coverage of FUTURE call sites, which is the guard's entire purpose.)
