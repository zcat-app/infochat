RED-TEAM VERDICT: FINDINGS

FINDINGS:
  - CATEGORY: INJECTION
    SEVERITY: low
    PROMISE: "Every prompt that includes user-derived text is wrapped in a delimiter block whose marker contains a per-call random value. Attackers cannot pre-guess the marker and therefore cannot forge a closing tag inside the body." (docs/spec/security.md §Prompt-injection defenses) and the amended semanticSearch row: "**Query anchoring (M1-746, D58):** when the scope declares a non-English `/lang`, the query text is first translated to the corpus anchor language (English, D29) by a generative `ModelTask.TRANSLATOR` call (decoded greedily — temperature 0 on the wire; language-only prompt; ...)" (docs/spec/security.md tool-allowlist row).
    GAP: The r5 root cause — "PROMPT_TEMPLATE carries a LITERAL `...` between the markers" — is only half-removed. QueryAnchorTranslator.java:131 still renders the instruction prose `<<<UNTRUSTED_CONTENT id="{{id}}">>> ... <<<END id="{{id}}">>>` with the literal ellipsis, and after substitution that illustrative pair carries the SAME per-call uuid as the real constructed block at QueryAnchorTranslator.java:141 (`{{WRAPPED_QUERY}}`). The prompt therefore contains two same-id marker pairs: the first (named by the instruction, "Translate the search query inside the ... wrapper") contains only `...`; the second contains the user's query. The unit test (QueryAnchorTranslatorTest.java:223-236) pins only that a constructed pair containing the query exists — it cannot detect which pair the model anchors on. Because the model is an untrusted black box per the threat model's own assumption, the r5 failure shape (instruction referencing an empty wrapper → hallucinated reply becomes the anchored search text) survives as an anchoring ambiguity, and D58 (b) then freezes the wrong result: the hallucinated/empty translation is cached under the real query's hash for 24h, making the wrong grounding deterministic.
    REPRO: A registered user runs `/lang cs` in a DM (any non-banned, non-probation user can; `/lang` is in the probation ALLOWED set). They then send a chat turn; the D28 pre-fetch dispatches semanticSearch, whose translate() builds the prompt. A model that anchors on the FIRST marker pair it is instructed about — the same-id pair containing `...` — replies with a translation of the ellipsis (or a hallucination), which becomes the anchored query for BOTH arms and is cached under the real query's SHA-256 for 24h. Subsequent identical searches return the same wrong grounding by construction (D19/D58 (b)), byte-identical to the r5 failure consequence — without the query ever being absent from the prompt. The system should not allow this because D58 (d)'s "language-only" anchoring promise is about converting the USER's query, and the delimiter convention (D21) is supposed to make the user text the only delimited block the model is told to translate.
    SUGGESTED-FIX-CLASS: other (prompt hygiene: drop the illustrative `...` pair from the instruction prose so exactly one marker pair exists in the prompt, or describe the wrapper without emitting a second same-id open/close pair; a test asserting the prompt contains exactly one occurrence of the marker pair would pin it)
  - CATEGORY: DOS
    SEVERITY: low
    PROMISE: "the translation leg is cached per (scope, query, language) so repeated queries cost nothing" (docs/spec/security.md §Rate limiting, "Query-anchoring translation (M1-746, D58)" bullet) and the R2 commitment "no cross-scope cache state exists" (ticket redteam_findings R2; QueryTranslationCache javadoc).
    GAP: The R2 fix partitioned the cache's KEY space — (scope_kind, scope_id, hash, lang) in QueryTranslationCache.java:90-94 — but the underlying store is a single process-wide Caffeine cache with one shared capacity budget: `Cache<QueryKey, String> ... expireAfterWrite(24h).maximumSize(10_000)` (QueryTranslationCache.java:66-69). No per-scope capacity exists, so one scope's churn evicts another scope's entries (Caffeine W-TinyLFU protects only frequently-used keys). R2 is delivered as a data/isolation property but not as a capacity property: an evicted scope re-pays a generative TRANSLATOR call and its latency on the next identical search, contradicting "repeated queries cost nothing" across scopes.
    REPRO: Adversary in a cs-declared DM scope issues many DISTINCT queries (each admitted turn's pre-fetch plus model-elected calls; volume bounded by the transport rate cap and the per-turn tool-call cap — so this is a slow, sustained churn, not a burst). Each distinct query inserts a new entry into the shared 10,000-entry cache. Over hours, cold entries of other scopes are evicted; a victim scope's next search of previously-translated text takes a cache miss, fires a fresh ~100-token generative call and pays the latency the cache was promised to eliminate. No confidentiality breach (R2 holds), but a bounded cross-scope cost-interference channel that survives the R2 fix.
    SUGGESTED-FIX-CLASS: rate-limit (per-scope cache capacity or per-scope entry budget, or accept-and-document as residual: the interference is bounded by the adversary's own rate caps and W-TinyLFU's frequency bias — low current impact)

OUT-OF-MODEL:
  - The unbucketed generative TRANSLATOR calls on the D28 pre-fetch (one per admitted turn for a non-en scope) draw no per-user LLM bucket token. This is disclosed and accepted in the amended §Rate limiting ("draw NO per-user bucket token... the bucket counts turns, not generative calls inside them... accepted v1 posture, stated rather than hidden"), so it is not a finding — but the model's own text flags the follow-up: a "tool-path-shaped rate limit (the bucket lives on the inbound router's per-turn path) is a follow-up decision when usage warrants." If the user wants a per-user generative-cost lever on this leg before `cs` usage grows, that is a model extension decision.
  - Trust-boundary-9 endpoint steering with 24h persistence: a hostile or compromised translator endpoint (operator-configured, in scope per trust boundary 9) can return an arbitrary "translation" that is served verbatim to both arms, cached per (scope, query, language) for 24h, and thereby steer which posts within the caller's world surface for that scope. Bounded to the caller's own world (D59 predicates inside the arms) and disclosed ("its outputs are never shown to the user — they enter the retrieval arms only"), so it is not a finding under the current model; listed so the user can decide whether the model should bound it (e.g., translation-output plausibility checks) as a spec amendment.
