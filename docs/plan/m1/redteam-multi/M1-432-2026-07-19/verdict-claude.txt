    The new WARN at
    infochat-llm-adapter/src/main/java/app/zcat/infochat/llm/routing/LlmRouterStartupGuard.java:415-417
    interpolates `reachableLanguages` — derived verbatim (split on ',', trimmed,
    lowercased) from the operator-supplied languages property at
    LlmRouterStartupGuard.java:870-887 — into a startup log line with no newline
    or control-character stripping. A value such as `cs%0aFATAL: <forged line>`
    would emit attacker-chosen text that reads as an additional log record.
    This is OUT-OF-MODEL, not a finding: the sole source is MicroProfile Config
    (properties / env / system properties), which the threat model classifies as
    trusted — "**Operator-set config** (properties files, bootstrap JSON) is
    trusted" (§Threat model). No adversary-reachable path writes this key, and
    the pre-existing FATAL branch at LlmRouterStartupGuard.java:326-334 already
    interpolates the same value into the same logger, so the diff does not widen
    the surface. Flagged only so the user can decide whether log-record integrity
    against a misconfigured-operator (not adversarial) input is worth a model
    extension.
