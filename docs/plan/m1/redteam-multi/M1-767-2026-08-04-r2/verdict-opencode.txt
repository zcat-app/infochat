    it breaks no spec promise — nothing in security.md guarantees
    replay availability during budget exhaustion — so it is flagged

    replay branch is meant to stay available (it draws nothing), the
    carve-out belongs in M1-769 with the exact-draw work, since that
    ticket already distinguishes replay (draws nothing) from fallback
    re-run (draws exactly).

    sits in the same accepted class as the per-user rate-cap reply
