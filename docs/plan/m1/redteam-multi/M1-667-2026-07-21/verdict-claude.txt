OUT-OF-MODEL:
  - Log-forgery of a user-influenced timezone value in a non-exception
    log line. DigestScheduler.warnBadTimezoneOnce
    (infochat-provider/.../digest/DigestScheduler.java:339-341) logs the
    raw group timezone via a plain SLF4J `LOG.warn("Group {} has invalid
    timezone '{}' ...", groupId, timezone)` — NOT through SafeLog — so
    SafeLog.stripControls() (which exists precisely to neutralize CR/LF /
    ANSI-CSI / bidi log-line forgery, the Trojan-Source class) is never
    applied to `timezone`. `timezone` is a command argument set via
    `/group-timezone`; a value that fails ZoneId parsing (which is exactly
    the branch that reaches this log) but still contains a control
    character (e.g. 0x9B CSI or ESC — chat-intake normalization step 1.7
    strips bidi + zero-width but NOT general C0/C1 controls) would land
    verbatim in the operator log stream and could forge a second log line
    or inject a terminal escape.

    Why OUT-OF-MODEL rather than a FINDING: the threat model's control-
    character / log-integrity commitment is scoped to "Exception messages
    and stack traces emitted via the application logger" (§Secrets handling
    — User content in exceptions) and to the SafeLog caller-message
    surface. This is a plain warning with no Throwable and a timezone is
    not "user-authored prose" in the §User-content logging (D37) sense
    (chat_memory content, saved_post bodies, inbound chat-mode message
    bodies). No spec bullet promises control-char stripping on ordinary
    (non-exception) log lines carrying user-influenced values, so there is
    no PROMISE for the diff to fail. The surface is also pre-existing —
    the diff only converts the printf `%s` placeholders to SLF4J `{}` as a
    mechanical consequence of the JBoss->SLF4J logger swap; it does not
    introduce or widen the vector. Surfaced so the user can decide whether
    to extend the model to non-exception user-influenced log values (e.g.
    route this line through SafeLog.stripControls or an equivalent).
