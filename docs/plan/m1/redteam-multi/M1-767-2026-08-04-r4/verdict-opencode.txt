RED-TEAM VERDICT: CLEAN

Audit scope: re-audit (round 5) of M1-767 with the round-4 root cause
remediated. New surface per the round-5 brief: the PRE-CHARGE probe in
RetryCommandHandler.handleDigestRetry (DigestRetryService.retryLeg +
SystemLlmBudget.canStartRender), the retryLeg method itself, and the
REMOVED post-charge paths (fallbackRerun gate, RetryResult.SYSTEM_BUDGET_REFUSED,
refund arm). Verified against the working tree (diff.patch + source files).

Findings: none. The round-4 root causes are structurally closed and the
new surface holds. Audit trail against each focus area of the brief:

1. Probe correctness (same reads as retryDigest? leg flips? clock usage?)
   retryLeg (DigestRetryService.java:329-345) performs byte-identical
   reads and the same decision logic as retryDigest's leg branch
   (DigestRetryService.java:129-152): findLatestCacheEntry ->
   lookupGroupForReplay -> expiresAt.isAfter(clock.instant()) ->
   sectionRepository.findOrderedSections. Same injected Clock (no
   two-clock split, M1-444); same expiry boundary semantics (isAfter, so
   expiresAt == now is FALLBACK on both paths). The probe deliberately
   does not mirror the cooldown/in-flight gates; its javadoc scopes the
   claim to "latest cache row + persisted-section presence" accurately,
   and a cooldown/in-flight retry that is instead refused pre-charge is a
   no-charge refusal either way. Leg flips are bounded and documented in
   the retryLeg javadoc: REPLAY->FALLBACK (row expires between probe and
   run) is caught by the worker's executeSlot gate when the window is
   exhausted and otherwise spends within budget; FALLBACK->REPLAY (a
   concurrent render persists sections) only ever refused a retry the
   user can re-issue.

2. Refusal ordering (audit row, no charge, no cooldown, service untouched)
   RetryCommandHandler.java:553 writes the DIGEST_RETRY audit row first;
   the pre-charge gate at 567-572 fires BEFORE the per-user LLM token
   draw (584), the D47 per-group draw (587), the cooldown stamp (inside
   retryDigest/fallbackRerun, never reached) and before retryDigest is
   called (591). Refusals are therefore audit-visible (hammering stays
   visible, matching the other gates), draw no per-user token, no D47
   token, stamp no cooldown, and never touch retryDigest. Pinned by
   RetryDigestCommandTest.retryDigest_refusedPreChargeWhenFallbackAnd
   SystemBudgetExhausted (callCount == 0, per-user token still
   acquirable, group bucket untouched).

3. Any path that still refuses or burns tokens AFTER a charge?
   None. The fallbackRerun gate is removed (DigestRetryService.java:
   231-256 contains only the explanatory comment); SYSTEM_BUDGET_REFUSED
   is gone from the RetryResult enum (347-354) and from the handler's
   switch (592-605); the refund arm is gone. The only admission decision
   on the shared path is DigestWorker.executeSlot's gate
   (DigestWorker.java:232-233), which DEGRADES — never refuses — and the
   digest still goes out (test:
   execute_systemBudgetExhausted_degradesScheduledSlot). The after-charge
   outcomes that remain are (a) the pre-existing conservative
   non-render-result convention (tokens drawn before retryDigest even for
   RATE_LIMITED / ALREADY_IN_PROGRESS / NO_PRIOR_DIGEST — documented at
   RetryCommandHandler.java:574-583) and (b) the residual degrade race.
   During steady-state exhaustion the pre-charge probe refuses
   deterministically BEFORE any charge, so the round-4 deterministic D47
   drain (opencode low) is closed; the residual race now requires the
   window to be marginally below the ceiling at probe time and to cross
   it before the worker gate — a narrow transient, not the deterministic
   drain the round-4 findings rested on.

4. Replay leg refused in any state?
   No. The gate requires retryLeg == FALLBACK; a REPLAY probe skips it
   entirely (RetryCommandHandler.java:567), pinned by
   retryDigest_replayLegProceedsDespiteExhaustedSystemBudget. The replay
   path (replayMissing) never reaches the worker gate. The round-3
   finding class (zero-LLM replay refused on the strength of the
   deployment-wide counter) is closed: the only refusal of a REPLAY-leg
   retry would require the probe to mis-classify it, and the probe's leg
   decision is identical to retryDigest's, so the mis-classification
   cases are bounded (row expiry, section persistence races — both
   documented, both re-issuable).

5. Residual degrade-after-charge path's honesty in the docs?
   Honest, in six places: RetryCommandHandler.java:561-566 (worker gate
   "DEGRADES (never refuses after a charge)... conservative non-render
   convention"), DigestRetryService class javadoc (43-52), fallbackRerun
   comment (233-243), retryLeg javadoc (320-327), ticket acceptance item
   1c (the interval "spans retryDigest's cache and metadata reads and the
   worker's post collection — NOT millisecond-scale, round-4
   correction"), and application.properties (M1-767 block). No load-
   bearing claim is false; the round-2 "only scheduled-route-only entry
   point" error is corrected in all four places it previously appeared.

Cross-check of the removed paths: SYSTEM_BUDGET_REFUSED appears only in
historical docs (redteam_audits/redteam_findings), never in main source;
retryDigest's only production caller is RetryCommandHandler.java:591,
which sits after the pre-charge gate — no production path reaches
fallbackRerun ungated.

OUT-OF-MODEL:
  - The budget window is in-memory and per-JVM (SystemLlmBudget.callTimestamps):
    a restart, redeploy or crash-loop resets a 24-hour control to zero, and a
    future multi-instance Provider would silently multiply the ceiling by the
    instance count. The spec already accepts in-memory state for the circuit
    breaker; process restarts are not an external-adversary lever here. Flagged
    for the spec owner, not filed.
  - The residual fill-in-the-window race (probe passes under the ceiling, the
    window crosses it before DigestWorker.executeSlot's gate): the re-run
    degrades, reports SUCCESS, and the already-drawn per-user + D47 tokens and
    the cooldown stamp are retained. Accepted and documented as the
    conservative non-render convention (round-4 disposition; codex finding's
    deterministic component removed). Narrow transient only — during steady-
    state exhaustion the probe refuses pre-charge — and the audit trail +
    cooldown bound the repeat rate.
  - The pre-charge refusal path costs DB work per attempt during exhaustion
    (1 audit INSERT + the probe's 3 SELECTs + the notifier's coalesced-but-
    per-call UPSERT) and the distinct refusal string is a cross-tenant load
    oracle for group admins ("The deployment's digest LLM budget is
    exhausted..."). Both bounded by the D47 per-group command sub-bucket and
    the transport cap; admin-tier metadata. Accepted as filed in rounds 3-4.
  - The meter remains an admission-only approximation: draws at
    DigestRenderer.renderSections count a proxy for provider calls (over-count
    on outage/breaker-OPEN/cancellation legs, under-count on the non-en roll-up
    TRANSLATOR leg and cache-eviction races), and an admitted render's spend is
    bounded only by the M1-763 slot window. All legs named in
    SystemLlmBudget's javadoc and application.properties; the per-call bound,
    per-group share and exact accounting are M1-769's scope, not this diff's.
  - Operator sizing: the default ceiling (3000/PT24H) equals the documented
    daily capacity with zero headroom for the meter's error legs; operators at
    capacity must scale the ceiling. Documented plainly in §Measurement and
    application.properties. Operator-set config is trusted per §Threat model.
