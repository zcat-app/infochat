OUT-OF-MODEL:
  - In-memory, per-JVM budget window. `SystemLlmBudget.callTimestamps`
    (SystemLlmBudget.java:~140) lives in the process, so a restart, redeploy or
    crash-loop resets a 24-hour control to zero, and a future multi-instance
    Provider would silently multiply the effective ceiling by the instance count.
    The threat model already accepts in-memory state for the circuit breaker
    ("State is in-memory only — a restart resets to CLOSED", §Failure handling),
    and process restarts / deployment topology are operator actions, not
    external-adversary levers in this model. Flagged for the spec owner, not filed.
  - Scope note (not an attack): the accounting and fairness residuals reported in
    earlier rounds are unchanged in this diff and ship as documented residual
    risk, so they are deliberately NOT re-reported as findings here. They are:
    (a) the meter charges nominal cost for renders that issue zero HTTP requests
    (unresolvable SUMMARIZER router, breaker OPEN, empty-prompt roll-up skip);
    (b) the M1-763 slot-window cancellation charges a discarded render's whole
    loop (~211 calls at `cluster-cap`); (c) the non-`en` roll-up spends two
    provider calls and draws one, and the `appendClusterProse` cache probe can
    lose an eviction race; (d) the gate is consulted once per render, so an
    admitted render's spend is bounded only by the slot window, and the
    deployment-wide ceiling carries no per-group share. All four are now named in
    `SystemLlmBudget`'s class javadoc (SystemLlmBudget.java:44-105), in
    `application.properties` (the M1-767 operator block), and in the ticket's
    `out_of_scope`, and are carried by the filed follow-up M1-769 (blocked on this
    ticket, present in the diff). The verifier should treat them as accepted-with-
    documented-residual-risk, not as closed.

Audit scope and negative results (round 5 — the new surface only):

  - PRE-CHARGE PROBE ORDERING. `RetryCommandHandler.handleDigestRetry`
    (RetryCommandHandler.java:522-591) runs: DM reject → actor resolve →
    bot-admin OR group-admin check (:536-540) → `digest_enabled` check (:549) →
    audit write (:553) → the new pre-charge refusal (:567-572) → per-user
    `llmRateCap.tryAcquire` (:584) → D47 `tryAcquireGroupLlm` (:587) →
    `retryDigest` (:591). The refusal therefore sits AFTER authorization and
    AFTER the audit row (a hammering admin stays audit-visible — no
    AUDIT-EVASION) and BEFORE every charge: no per-user token, no D47 draw, no
    `lastRetryAt` cooldown stamp (stamped only inside
    `DigestRetryService.replayMissing`:218 / `fallbackRerun`:254, neither of
    which is reached). Verified no charge precedes it.

  - PROBE CORRECTNESS. `DigestRetryService.retryLeg` (DigestRetryService.java:
    329-345) performs the same reads as `retryDigest` (:119-156):
    `findLatestCacheEntry` → `lookupGroupForReplay` → `expiresAt.isAfter(now)`
    → `sectionRepository.findOrderedSections(...).isEmpty()`, with the same
    injected `clock` both sides (no app-vs-DB clock split). The only ordering
    difference is that `retryDigest`'s cooldown and in-flight gates precede its
    reads, which can only change WHICH refusal message a caller sees, never
    whether a charge happens.

  - REPLAY LEG CAN NEVER BE REFUSED. The gate fires only on
    `RetryLeg.FALLBACK` (RetryCommandHandler.java:567). `REPLAY` and `NO_PRIOR`
    bypass it entirely; the round-3 regression is pinned by
    `retryDigest_replayLegProceedsDespiteExhaustedSystemBudget`. A probe→run
    flip toward FALLBACK cannot convert into ungated spend either:
    `DigestWorker.executeSlot`'s admission gate (DigestWorker.java:232-235) is
    on the only path that reaches `DigestRenderer.renderSections`, and it
    DEGRADES rather than refusing after the charge.

  - NO POST-CHARGE REFUSAL, NO REFUND ARM LEFT. `fallbackRerun`
    (DigestRetryService.java:231-256) carries no gate; the removed
    `SYSTEM_BUDGET_REFUSED` constant leaves the `RetryResult` switch
    (RetryCommandHandler.java:592-605) exhaustive; the only token refund
    (:588) is the pre-existing D47-rejection refund. No path draws a token and
    then refuses.

  - SPEND SURFACE CONTAINMENT. `renderSections` has exactly one caller
    (`DigestWorker.executeSlot`, DigestWorker.java:245), and `DigestWorker.
    execute` exactly two (`DigestScheduler`'s channel and
    `DigestRetryService.fallbackRerun`:249), so the new draws cannot meter
    `/summary`, chat, saves or the personal `/retry` re-roll into the
    system-initiated budget, and no generative digest path escapes the
    admission gate.

  - CONTROLS PRESERVED ON THE REROUTED PATH. A budget refusal reroutes the
    render to `degradedRenderer.render(...)` — the same non-generative path the
    pre-existing slot-window timeout uses, which carries the per-title
    `LlmOutputSanitizer` pass and the `OutboundDelivery` `](`-adjacency
    chokepoint (§LLM output sanitizer). `isDegraded` is still set, the cache row
    is still written, and the digest still goes out (pinned by
    `execute_systemBudgetExhausted_degradesScheduledSlot`). The new bundle value
    `error.retry.digest_system_budget` interpolates no tokens and no inbound
    bytes, in all five bundles.

  - REFUSAL COST. A refused retry costs the probe's SELECTs plus one
    `ThrottledAdminNotifier.notifyOnce` UPSERT (ThrottledAdminNotifier.java:
    234-244, coalescing suppresses the emission, not the round-trip) and draws
    no token. Considered as a DOS lever and rejected: the audit INSERT at
    RetryCommandHandler.java:553 already preceded every rate-limit draw before
    this diff, so the pre-cap work on this path was already bounded only by the
    intake transport cap (§Authorization model step 1.5) and the D47 per-group
    command cap; the diff adds a small constant factor to an already-bounded,
    group-admin-only path, and the spec's coalescing promise is about
    notification MESSAGES, which stay coalesced. Not filed.

  - BUDGET MONOPOLIZATION VIA `/retry --digest`. Tested and rejected as a
    standing denial: a successful fallback re-run persists sections
    (DigestWorker.java:285-299 path with `renderedSections != null`), which flips
    the group's next probe to `REPLAY` (zero LLM), while a re-run that degrades
    spends nothing. A single group therefore captures at most about one
    render's worth of the shared ceiling per slot cycle, bounded further by the
    per-user LLM bucket, the D47 sub-bucket and the PT2M cooldown. The absence
    of a per-group SHARE of the ceiling remains the deferred M1-769 residual
    recorded above.
