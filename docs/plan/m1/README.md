# Milestone 1 (M1)

The v1 vertical-slice build of infochat. M1 takes the project from greenfield to a deployable system that satisfies the spec end-to-end on at least one stack profile.

The **procedure** for running M1 — ticket lifecycle, reviewer behavior, escalation, commit conventions — is universal and lives in [`docs/process/workflow.md`](../../process/workflow.md). The always-loaded summary lives in `CLAUDE.md` §M1 workflow. This README is for M1-specific framing only.

## What's M1-specific

- **Ticket-ID prefix:** `M1-NNN`.
- **Branch token:** `m1/M1-NNN-<slug>`.
- **Driver skill:** [`/m1-tick`](../../../.claude/skills/m1-tick/SKILL.md).
- **Tickets:** drafted under [`tickets/`](tickets/).
- **Status board:** [`STATUS.md`](STATUS.md) (auto-generated by `/m1-tick status`; do not hand-edit).
- **Greenfield framing.** M1 has no prior version to be backwards-compatible with. The "no defensive code for impossible scenarios" rule (canonical rules §7) applies in its strongest form: feature flags and compatibility shims are forbidden because there is nothing to be compatible with.
- **Stack-specific rules.** The Postgres + pgvector test-integrity rule (canonical rules §8 stack-specific) is in force from M1 onward — no H2/in-memory substitutes.
