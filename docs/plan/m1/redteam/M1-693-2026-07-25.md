  - Pre-M1-693 rows are not backfilled. The 200-char cap and the
    blank->"untitled" replacement apply only to NEW inserts through
    PostPersister.persist; post.title rows written before M1-693 retain
    their prior representation (bidi/zero-width/control-stripped, but
    uncapped and possibly the empty string ""). The threat model makes
    no backfill promise and this is a one-time data condition rather
    than an adversary-reachable ongoing path: the only production
    writer of post.title is the PostPersister INSERT (verified — every
    other title reference in main source is a rs.getString READ or a
    render-side LlmOutputSanitizer.sanitize call; all other INSERT INTO
    post are test fixtures), and the DB is internal (security.md SS
    Trust boundaries item 3), so an external attacker cannot amend an
    existing row. Flagged for operational awareness only.
  - NFKC is not applied to title at the write boundary (pre-existing,
    unchanged by this diff). IngestTextNormalizer.stripMetadataField
    removes bidi-control, zero-width, ISO-control, and U+2028/U+2029
    line/paragraph separators but does NOT NFKC-fold, whereas the
    render-side LlmOutputSanitizer matches the canonical form (NFKC +
    bidi/zero-width strip — security.md:452-454). A fullwidth-solidus
    command token (e.g. the ／grant-admin form security.md:457 itself
    cites) therefore survives ingest stored as-is and is caught only at
    render. No threat-model promise is violated: security.md commits
    NFKC to the body at Stage 1 only (SS Ingest pipeline), and
    command-shape redaction of titles is explicitly a render-side
    control (SS LLM output sanitizer) that runs on every surface that
    interpolates a title (/saved reply, /summary, degraded digest).
    Noted because this diff newly documents the title's write-side
    representation in schema.md (SS Posts and derivatives, "title
    normalization") without referencing the NFKC gap to the render
    canonical form — the same class of representation asymmetry that
    motivated the sanitizer's canonical-form-matching amendment,
    present here in milder form (the render pass closes it). Not
    introduced by M1-693; recorded so a future change that moves
    command-shape checking toward the write boundary does not assume
    the stored title is already canonical.
