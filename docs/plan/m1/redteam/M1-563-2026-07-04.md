FINDINGS:
  - CATEGORY: PERM-ESCAL
    SEVERITY: medium
    PROMISE: schema.md §Identity and access (Group membership), the file
             security.md §Authorization model names as the enforcement
             mirror ("Invariants (also enforced in `schema.md`)"), still
             promises the departed-group-admin defense verbatim:
             "When the messaging adapter signals that a user has left a
             group (a `user_left_group` adapter event, or a permanent
             send failure to that specific user surfaced by the adapter),
             the row is **soft-cleared** ... the soft-clear **also clears
             `is_group_admin`** ... A user who left and rejoins as a
             regular member does **not** automatically reclaim
             `is_group_admin`; the slot is refilled by the standard
             mechanisms." (docs/spec/schema.md:141-162)
    GAP: This diff narrows that commitment in two spec files but leaves
         schema.md carrying the pre-narrowing promise, so the spec set is
         now internally contradictory and schema.md over-promises a
         privilege-retention defense the amended threat model says does
         not exist on either v1 adapter.
         (1) docs/spec/schema.md:143 still lists "a permanent send failure
             to that specific user surfaced by the adapter" as a
             leave-cleanup trigger — the exact branch the diff DELETED from
             docs/spec/messaging.md:396-401 and docs/spec/security.md:438
             on the ground that a group-scope send carries no per-user
             delivery-failure carrier, so that trigger can never fire.
         (2) docs/spec/schema.md:160-162 promises a rejoining former admin
             does NOT reclaim `is_group_admin`; the diff's own new text at
             docs/spec/security.md:445-449 states the opposite for both v1
             production adapters: "If that departed admin later rejoins,
             they **silently resume group admin**, because their row was
             never cleared."
         The delivered behavior matches the amended security.md (no
         cleanup, silent resume); schema.md is the stale file promising a
         defense the system does not deliver.
    REPRO: An operator or implementer reading schema.md §Group membership
           builds/operates on the belief that a group admin who leaves is
           soft-cleared (slot freed, auto-promote can refill) and cannot
           silently reclaim admin on rejoin. On both v1 production adapters
           (supportsMembershipEvents=false) none of that happens: user A,
           the group admin, does something warranting removal and leaves
           the group; no left-group signal and no per-user PERMANENT send
           failure ever fires, so A's `is_group_admin` row persists and
           auto-promote never refills the slot for a legitimate member B.
           A rejoins with the same contact_id and silently resumes group
           admin. schema.md said this could not happen; security.md now
           says it does. The only remediation (bot-admin `/demote`) is
           documented in security.md/messaging.md but absent from the
           schema.md text that still asserts the automatic protection.
    SUGGESTED-FIX-CLASS: other
