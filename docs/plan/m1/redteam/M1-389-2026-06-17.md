OUT-OF-MODEL:
  - Operator-pasted secret values containing a literal double-quote (").
    The diff writes every value to secrets.env as KEY="value"
    (prod/scripts/2-secrets.sh:52, 4-llm.sh:217, 6-adapter.sh:101). A value
    that itself contains a " could prematurely close the quoted field under
    compose's dotenv parser, corrupting the bootstrap-admin id or API key.
    This is not a FINDING: the only sources of these values are
    operator-pasted config (SimpleX queue address, API key) and
    openssl-generated hex passwords, and the threat model
    (security.md §Threat model: "Operator-set config (properties files,
    bootstrap JSON) is trusted") places operator config inside the trust
    boundary. No in-model adversary (messaging-app user, feed publisher,
    LLM) can influence secrets.env content. Flagged so the operator can
    decide whether to add quote-escaping as accident-resistance.

  - Compose ${...} interpolation inside env-file values. Newer
    docker-compose performs variable interpolation on values read from an
    --env-file in some versions; an operator-pasted value literally
    containing ${OTHER} could expand unexpectedly. Same disposition as
    above: source is operator-trusted config, outside the documented
    threat actors. The prior shell-source mechanism this diff removes was
    strictly worse (it would execute embedded $(...) / backticks at wizard
    runtime), so the change is a net hardening even before considering the
    out-of-model residue.

  - Supply-chain / operator-infrastructure compromise (an attacker who can
    write to the host's runtime/secrets.env or the compose file directly).
    Explicitly out of scope per security.md §Threat model ("supply-chain
    attacks on operator infrastructure" listed as out of scope for v1).

NOTES:
  - The sensitive-surface inventory reports "(none touched)" for
    authentication, authorization, input validation, ban handling, and
    audit-log writes; the diff confirms this — it touches only the
    deployment wizard's secret-delivery plumbing (prod/scripts/*.sh,
    prod/setup.sh) plus the matching design-prose update
    (docs/design/07-deployment.md §7.7.2) and ticket/STATUS bookkeeping.
  - The change is a security improvement against the documented model: it
    eliminates the shell `source` of secrets.env (prod/setup.sh removed
    load_secrets, lines 372-388 of the diff), which would have evaluated an
    operator-pasted $(...) / backtick at wizard runtime and truncated a
    value at its first '#'. All docker compose invocations across the seven
    scripts now pass --env-file "$SECRETS_FILE"; a repo-wide grep confirms
    no residual `.`/`source` of secrets.env remains. The
    "secrets stay in the environment, never in a mounted config file"
    commitment (design §7.3) is preserved — secrets reach the containers
    via compose interpolation/passthrough, and only non-secret adapter
    values are written to the mounted application.properties.
