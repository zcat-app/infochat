RED-TEAM VERDICT: CLEAN

The diff under audit (M1-115) adds the three group-admin command tokens
`/approve-group`, `/reject-group`, `/list-groups` to
`LlmOutputSanitizer.CLOSED_LIST` plus one strip-assertion test each, and
updates ticket/STATUS metadata. It was checked against the only spec
promise it touches — the §LLM output sanitizer "Match-set derivation"
commitment that the sanitizer set equals the closed privileged-tier list
in `commands.md` §Permission model, with CI failing on mismatch.

What was verified:

- The runtime `CLOSED_LIST`
  (infochat-provider/src/main/java/app/zcat/infochat/provider/llm/LlmOutputSanitizer.java:87-118)
  now contains all 22 bot-admin entries and all 6 group-admin entries
  from the spec closed list (docs/spec/commands.md:1015-1025).
  Element-by-element comparison: exact match in both directions. The
  three added tokens are precisely the ones the spec's bot-admin tier
  lists that were previously absent.
- The CI completeness test `matchSetEqualsSpecClosedList`
  (LlmOutputSanitizerTest.java) genuinely parses commands.md and asserts
  set equality in both directions, so the spec's "CI fails on a mismatch
  in either direction" promise is backed by a real test, not a comment.
- Falsifier on the spec parser: `/quarantine list --all` (the flag
  example at commands.md:998, under the same `## Permission model`
  heading) is NOT spuriously pulled into the parsed set — the parser
  only enters bullet-group mode on `**Bot-admin only:**` / `**Group-admin`,
  and the `**Admin-only flags...**` bullet matches neither, so the parsed
  spec set stays at the 28 canonical tokens the runtime list mirrors.
- Falsifier on the new tokens' boundary matching: literal
  `Pattern.quote(token)` plus the `(?=$|[^a-zA-Z0-9\-])` lookahead strips
  the new tokens identically to existing ones; the three new tokens have
  no prefix-overlap with each other or with `/list-sources` that would
  mask a match. Markdown-strip-first ordering cannot smuggle a new token
  past the closed-list pass any more than it could the pre-existing ones.

The diff closes a prior gap (three privileged group-admin commands were
leakable through LLM output) and introduces no new one. Audit emission,
per-occurrence WARN logging, and fail-closed-on-audit-failure behavior
are pre-existing and untouched.

OUT-OF-MODEL:
- The sanitizer strips only literal, contiguous command tokens; an
  LLM-emitted string with inserted whitespace or punctuation (e.g.
  `/approve- group`) would not match. This is consistent with the spec's
  stated intent (strip recognizable, copy-pasteable command strings;
  admin dispatch still requires `is_admin=true` via the deterministic
  path) and is not a documented promise the diff fails — flagged only so
  the user can decide whether obfuscated-token matching is in scope for a
  future hardening pass. Not counted as a finding.
