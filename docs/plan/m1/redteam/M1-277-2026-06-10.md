RED-TEAM VERDICT: CLEAN

The diff (M1-277, SSRF perf-hardening) was audited in full against
docs/spec/security.md §"SSRF and outbound connections", §"Per-source
trust boundaries", and the trust-boundary commitments. Every
security-relevant change is a strengthening or a behavior-preserving
refactor; no threat-model promise is weakened.

Audit reasoning (why no finding was raised):

1. IpBlocklist new ranges (IpBlocklist.java:226, 265-291, 300-327).
   The diff ADDS blocks (TEST-NET-1/2/3, IETF protocol-assignments
   192.0.0.0/24, benchmarking 198.18.0.0/15, class-E 240.0.0.0/4,
   NAT64 local-use 64:ff9b:1::/48, explicit Alibaba 100.100.100.200
   and AWS IMDSv2 fd00:ec2::254). All spec-mandated ranges remain:
   169.254.0.0/16 still covers 169.254.169.254 (line 246), RFC-1918,
   CGNAT, loopback, multicast, link-local v6, unique-local v6 all
   intact. The spec's "blocklist of private, loopback, link-local,
   multicast, CGNAT, and cloud-metadata ranges (notably
   169.254.169.254 and IPv6 equivalents)" is satisfied with strictly
   more coverage, not less.

2. Shared HttpClient (SsrfGuardedHttpClient.java:451, 467-470, 391).
   One client per wrapper, never closed, with connection pooling
   across get() calls. Audited against the TOCTOU promise ("DNS is
   re-resolved after every redirect; the IP blocklist re-applies each
   hop"). Each hop and each get() call still runs resolveAndValidate
   (line 375) + pin before send. Connection reuse only occurs after a
   fresh validation passes; if an attacker flips DNS to a blocked IP
   between calls, resolveAndValidate throws before any send. A reused
   pooled socket's peer IP was validated when the socket was
   established and DNS cannot rebind an open socket — the pin/validate
   gate is preserved per hop. No weakening of the DNS-rebind defense.

3. PinnedDnsResolver fast-path (PinnedDnsResolver.java:254-270).
   The forwarding resolver now probes the live PINS map directly
   instead of composing an ephemeral PinnedDnsResolver over a
   snapshot. Semantics are identical: no-pin fast path, then
   canonicalize-before-get (M1-026 Finding 2 preserved at line 257-265),
   then delegate to builtin. Same canonical key, same pin answer, same
   delegation. Behavior-preserving.

4. Cross-origin header scrub widened (SsrfGuardedHttpClient.java:422-431,
   isCredentialHeader removed at old line 677). Previously only
   Authorization/Cookie/Proxy-Authorization were stripped on a
   cross-origin redirect; now ALL caller-supplied headers are dropped
   (hopHeaders.clear()). This is a strict tightening — fewer
   caller-injected headers cross origins. Wrapper's own
   Accept/User-Agent defaults still ride every hop. No INFO-LEAK
   introduced; one closed.

5. HostInterfaceSet.java:200-205 dropped the defensive Set.copyOf and
   returns the freshly-built mutable set. The set is built per
   isBlocked/firstBlocked pass and read only within one validation
   pass; no shared mutable state escapes. Consistent with the project
   No-defensive-code rule. No security impact.

6. Test sentinel swap (IpBlocklistTest.java: 203.0.113.5 ->
   11.22.33.44) is forced because 203.0.113.5 (TEST-NET-3) is now
   range-blocked; 11.22.33.44 is public, unreserved (11.0.0.0/8 is
   globally routable, in no blocked range), so the host-interface seam
   tests stay non-vacuous. No assertion direction reversed; the
   transition-form hex encodings were recomputed to match. Test
   integrity preserved.

OUT-OF-MODEL:
  - Arbitrary operator-chosen NAT64 prefixes (other than the RFC 8215
    local-use 64:ff9b:1::/48 and the RFC 6052 well-known 64:ff9b::/96
    decode) remain undetectable. The diff's own comment
    (IpBlocklist.java:310) acknowledges this. The spec does not commit
    to blocking operator-private NAT64 translators, so this is not a
    finding — flagged only so the user can decide whether to extend
    the model.
  - 11.0.0.0/8 used as the new test sentinel is US DoD-allocated space
    that is globally routable but rarely seen in practice. If a future
    spec amendment ever blocks DoD/bogon space, these host-interface
    tests would turn vacuous again. Not a current threat-model gap;
    noted for sentinel-selection hygiene only.
