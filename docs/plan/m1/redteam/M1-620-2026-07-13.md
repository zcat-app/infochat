RED-TEAM VERDICT: CLEAN

The diff adds `/invite bot-contact [--adapter <name>]`, a bot-admin, DM-only
command that returns the bot's own shareable onboarding contact (SimpleX
live contact URL / Signal number), plus the supporting SPI method
(`MessagingAdapter.connectContact()`), the SimpleX `/show_address`
codec round-trip, and the bundle/command surface. Audited against every
commitment in docs/spec/security.md.

Checks performed and passed (no gap between promise and delivery):

1. Authorization → execution (Trust boundary 3, §Authorization model
   steps 6-9). InviteCommandHandler.handle() gates group scope
   (ERROR_COMMAND_DM_ONLY) BEFORE resolving the caller, then applies the
   bot-admin gate (`!actorOpt.get().isAdmin` → ERROR_ADMIN_ONLY) BEFORE
   dispatching to handleBotContact. The expensive live-query path
   (connectContact()) is unreachable without a passing admin gate; a
   non-admin never triggers a SimpleX WS query. Deterministic Java,
   no LLM in the path.

2. §LLM output sanitizer / §Match-set derivation. `/invite bot-contact`
   is added to the bot-admin closed list (commands.md §Permission model,
   diff line ~139) AND to LlmOutputSanitizer.CLOSED_LIST
   (LlmOutputSanitizer.java:113). Parity holds — CI would fail on a
   one-sided addition; both sides are present.

3. Trust boundary 5 (LLM tool surface). connectContact() is an adapter
   SPI method, not a member of the closed LLM tool registry
   (searchPosts/semanticSearch/getPost/getReferences/recallMemory/
   listSaves). No LLM exposure of the bot's address.

4. §Secrets handling / §User-content logging / D37 "never logged or
   persisted". Traced every sink of the contact value:
   - SimpleXMessageCodec.decodeUserContactLink emits a fixed sentinel
     ("userContactLink-without-link") on the error leg, never the link.
   - SimpleXWebSocketClient.dispatch completes the pending future with
     the link but logs only corrId, never the value.
   - InviteCommandHandler.handleBotContact interpolates the value only
     into the reply body; nothing is logged.
   - OutboundDelivery.execute logs channel + byte count only
     (OutboundDelivery.java:196-199), never sendMsg.text();
     InboundRouter logs adapter/scope only, never reply.text().
   The "outbound path omits reply bodies from logs" claim is verified
   true; the value reaches the admin DM and nothing else.

5. corrId trust / frame-confusion. A `userContactLink` frame is
   actionable only when it carries a corrId, and corrId is stamped by
   the local simplex-chat process on responses to the bot's own
   commands (codec comment + D10 trust boundary) — a remote peer never
   controls the bot-API envelope. decodeUserContactLink returns Ignored
   when corrId is absent, so a remote-influenced frame cannot complete
   a pending future or hijack a pending send-ack.

6. Failure handling / no-crash promise. requireConnected() /
   sendCommand() throw MessagingException on transport failure/timeout;
   handleBotContact catches it → ERROR_INVITE_BOT_CONTACT_UNAVAILABLE.
   Empty Optional → ERROR_INVITE_BOT_CONTACT_UNSUPPORTED. Unknown
   --adapter → ERROR_INVITE_BOT_CONTACT_UNKNOWN_ADAPTER naming valid
   choices. No uncaught path.

7. Audit (Schema Invariant 7 / §Authorization step 8). The command is a
   pure read of the bot's OWN non-secret address with no mutation and no
   other-user data — the same un-audited posture as `/invite list`
   (which the diff correctly cites and which the codebase does not
   audit). Invariant 7 binds mutations and user-data reads; the
   threat model does not require auditing this read. Not an
   AUDIT-EVASION violation.

8. Cross-adapter --adapter posture. Matches the explicitly-permitted
   cross-adapter `/invite create` carve-out (§Per-adapter admin threat
   profile): discloses only the bot's own onboarding address on the
   named adapter, which grants neither registration nor elevation
   (DM access still gates on an invite code; SimpleX admin still gates
   on the claim-token). Actor admin status is resolved on the inbound
   adapter; the target adapter is a flag only.

OUT-OF-MODEL:
  - Availability: SimpleXAdapter.connectContact() performs a synchronous
    blocking WS round-trip (sendCommand with ACK_TIMEOUT=30s) on the
    single SimpleX inbound-dispatch thread (SimpleXWebSocketClient.java
    comment at the ContactAddress case explicitly acknowledges "the
    single inbound-dispatch thread blocked in sendCommand"). In the
    worst case (no ack) this stalls ALL inbound processing for that
    adapter — including the ban check — for up to 30s, during which the
    bounded inbound queue can shed legitimate traffic (QUEUE_FULL). This
    is bounded (30s cap, and in practice a local-subprocess reply
    returns in milliseconds) and reachable ONLY behind the bot-admin +
    transport-rate-cap gates. Bot admins are trusted principals under
    the threat model (§Trust boundaries — operator-set config trusted;
    admin is the trust anchor), so this is admin-triggered self-inflicted
    availability degradation, not an adversary-reachable path. Flagged so
    the user can decide whether to move the live query off the dispatch
    thread; it is not a violated threat-model commitment.
