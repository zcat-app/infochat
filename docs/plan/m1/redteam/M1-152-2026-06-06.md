# Red-team audit — M1-152 (--in-progress)

RED-TEAM VERDICT: CLEAN

The diff comprises three changes:
1. `V36__schema_hardening.sql` — a `CHECK` constraint closing
   `post.stage2_verdict` over `('BENIGN','INJECTION','MALWARE','UNKNOWN')`
   plus a composite index `idx_post_source_published` on
   `post(source_id, published_at DESC)`.
2. `AuditAction.java` — adds the `D47_GROUP_ONLY_PREBAN_CONVERSION` enum
   member so the V27-written audit verb is represented in the
   application-layer closure.
3. `SchemaHardeningIT.java` — behavioral tests over all three.

Each was checked against the relevant spec promises:

- **stage2_verdict CHECK** matches the Stage 2 closed label set verbatim
  (security.md §Failure handling: `BENIGN`/`INJECTION`/`MALWARE`/`UNKNOWN`),
  correctly allows `NULL` (Stage 2 not-run / infra-failure), and correctly
  excludes the `INFRA_FAILURE` member that never writes the column. A
  constraint can only tighten writes, not open a hole. Delivers.
- **AuditAction closure** fixes a real audit-integrity gap: V27 already
  wrote `D47_GROUP_ONLY_PREBAN_CONVERSION` to `audit_log.action`, but the
  enum lacked it, so a read-path doing `AuditAction.valueOf()` would have
  thrown on those rows. The diff closes that gap rather than creating one.
  The lack of a DB `CHECK` on `audit_log.action` is pre-existing and by
  design (V5, enum-as-closure); the actor cannot write audit rows
  (INSERT-only role, application-mediated), so AUDIT-EVASION
  "writable by the actor" is not violated.
- **Index** is a read-path optimization; it changes no behavior.

OUT-OF-MODEL:
  - Cursor-poisoning of the Nostr since-cursor (advisory, NOT a diff
    finding). The new `idx_post_source_published` index is explicitly added
    to serve the reconnect cursor query
    `SELECT MAX(published_at) FROM post WHERE source_id = ?`
    (NostrStreamSource.java:461). For Nostr sources `published_at` is the
    attacker-controlled event `created_at` (NostrEvent.java:85), set
    verbatim from the relay payload with no clamp to wall-clock. A single
    malicious event with `created_at` far in the future poisons
    `MAX(published_at)`, pushing the `since` filter past now, so on the next
    reconnect the relay replays nothing and the bot goes blind to that
    source (an ingest-availability DoS). Flagged advisory only because:
    (a) the cursor read and the un-clamped `created_at`→`published_at`
    mapping are pre-existing code outside this diff — the diff merely
    indexes the query, it does not introduce or promise to fix the
    behavior; and (b) the threat model makes no explicit per-source ingest
    -availability commitment for Nostr (it accepts relay-slice blindness as
    a v1 trade-off). Suggested follow-up: clamp Nostr `created_at` to
    `LEAST(created_at, now())` before it becomes the cursor source, in the
    NostrEvent/PostPersister path, NOT in this migration.
