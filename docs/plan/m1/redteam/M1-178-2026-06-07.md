RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - Deferred contact-id format validation. `AdminBootstrap` treats the configured `infochat.adapters.<name>.admin` value as an opaque string (javadoc lines 56-63 of AdminBootstrap.java), so a malformed SimpleX queue address / Signal ACI seeds a `users` row that no real inbound identity can ever match. This is operator misconfiguration of trusted config, not an adversary-influenced input; the threat model declares operator config trusted and does not mandate bootstrap-time parsing. Flag only if the user wants config-boundary hardening (a malformed admin row silently yields an unusable admin, which last-admin protection could then pin in place).
  - Promote-in-place over ban/probation/preban rows. The `ON CONFLICT DO UPDATE SET is_admin = TRUE WHERE users.is_admin = FALSE` arm (AdminBootstrap.java:82-87) promotes an existing row regardless of `is_banned`/`registration_state`, producing states like a banned-but-admin or preban-but-admin row if the operator points the config at such a contact id. Inert under the model (intake ban check precedes any admin action; only operator-controlled, cryptographically-anchored contact ids reach this path) and therefore not a finding, but worth an explicit operator note if the spec wants bootstrap to refuse promoting banned/preban rows.
