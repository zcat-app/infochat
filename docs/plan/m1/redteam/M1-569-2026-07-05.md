RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - Floating image tag as root with host bind-mounts. Both scripts pin
    IDENTITY_TAR_IMAGE="pgvector/pgvector:pg16" (pack.sh:51, restore.sh:69) — a
    mutable registry tag, not a digest — and run it via `docker run --rm -u 0:0`
    with the host adapter identity dirs bind-mounted (pack.sh:178-179 read-only;
    restore.sh:308-309 read-WRITE at the absolute host path). A poisoned
    `pgvector/pgvector:pg16` in the registry would execute as root with write
    access to the restored Signal/SimpleX identity stores. This is a supply-chain
    attack on operator infrastructure, which security.md §Threat model places
    explicitly out of scope ("Out of scope for v1: ... supply-chain attacks on
    operator infrastructure"); an operator running docker already holds
    root-equivalent on the host. Flagged only so the operator can decide whether
    digest-pinning the tar image is worthwhile hardening.
  - Tampered migration bundle. The restore path (restore.sh untar, and the
    integrity/allowlist gates preceding it) trusts the bundle produced by pack.sh
    on a trusted source host. A hand-edited/tampered bundle is a supply-chain
    concern the diff's own comments (restore.sh:291-292) and security.md place out
    of scope. The M1-568 allowlist + writable-mount-only-allowlisted design bounds
    even that out-of-model case (extra members land in the ephemeral container `/`,
    never the host), so no in-model exposure exists; noted for completeness.
