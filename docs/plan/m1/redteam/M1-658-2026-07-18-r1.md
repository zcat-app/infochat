    SEVERITY: low
    PROMISE: commands.md §Discovery / security.md §LLM output sanitizer — the
             guard mechanically enforces "any friendly error reachable below
             bot admin must not reflect inbound text".
    GAP: The auto-classifier's NUMERIC_CONV and JOIN_CALL shapes used .find()
         on ^-anchored patterns, degrading to a prefix match. String.valueOf(X)
         returns X.toString() unchanged, so String.valueOf(rawInboundToken) was
         auto-classified trivially-safe and dropped before the baseline check;
         the prefix match also admitted concatenations like
         Integer.toString(x) + rawInboundToken. Both contradict the classifier's
         own stated contract. The live tree was clean (all baseline residue
         verified honest); this was a future-regression blind spot, not a live
         reflection.
    REPRO: A future below-admin error handler returns MessageFormat.format(
           bundleLoader.get(BundleKeys.ERROR_FOO, lang),
           String.valueOf(args.rawUserToken())); mvn verify stays GREEN — the
           site is auto-classified and never demands a baseline entry.
    SUGGESTED-FIX-CLASS: trust-boundary-tightening

Disposition: fixed in round 2 — isTriviallySafe tightened to only whole-
expression shapes safe regardless of argument value/type (single string/int
literal, .size(), local static-final-String constant); String.valueOf /
String.join / sortedJoin / commaList removed from the auto-classifier and their
16 error-keyed sites moved into the baseline with explicit justifications
(34 -> 50 entries). Re-audited CLEAN on this point in r2.
