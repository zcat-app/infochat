RED-TEAM VERDICT: CLEAN

Audited the M1-292 log-hygiene diff against docs/spec/security.md (read in
full, both pages). The diff touches four redaction surfaces named in the
threat model's §Secrets handling and §"User content in exceptions"; every
change tightens a leak path the threat model demands and none of them opens
a new gap, regresses an existing defense, or weakens a test.

Surfaces examined and why each delivers the promise:

1. Redactor.isLoggable timeout arms (infochat-core/.../log/Redactor.java
   :122-180). §Secrets handling commits stdout logs to fail-closed on
   regex-watchdog timeout. Pre-diff, only the thrown-chain arm dropped the
   throwable; a timeout on the message scan (:126) or parameter scan (:150)
   set message+params to the sentinel and returned WITHOUT scanning or
   dropping record.getThrown(), so the console formatter would render the
   raw unscanned thrown graph — the exact place secrets live. The diff adds
   record.setThrown(null) to both arms (:134, :155), closing the gap. This
   is a genuine fix, not a regression. Tests in RedactingLogFilterTest drive
   each arm with a zero-ms budget and assert the secret-bearing thrown is
   null after each.

2. UrlRedactor path collapse (infochat-ssrf/.../UrlRedactor.java :77-81).
   §Secrets handling requires URL secrets stay out of logs. Pre-diff the
   path (getRawPath) was appended verbatim, leaking path-borne webhook
   tokens (Slack/Discord) into WARN logs while redacting only the query.
   The diff collapses path AND query into a single /[REDACTED], preserving
   only scheme/host/port. Verified the bare-host and userinfo-only-no-path
   cases (https://user:secret@host -> https://host, userinfo dropped, no
   spurious suffix). All 11 callers use UrlRedactor solely for
   log/exception sanitization; none feeds it into an SSRF allowlist
   decision (those run on the resolved IP), so collapsing the path weakens
   no security check. The two collector caller-tests are in files_scope and
   retain their no-userinfo/no-token leak assertions.

3. Upstream-byte hygiene (AssetSnapshotFetcher.java :281-, :320;
   KrakenSnapshotSource.java :141-). §"User content in exceptions" and the
   untrusted-feed-content trust boundary. KrakenSnapshotSource error arrays
   and FetchException cause messages are now SafeLog.stripControls'd
   (full C0+DEL+C1 sweep, incl. 0x9B single-byte CSI) and truncated to 200
   chars before reaching exception text, WARN logs, or admin notifications.
   recordFailure no longer hands the raw Throwable to the formatter (no
   stack-trace leak). The WARN line still transits the JUL Redactor filter
   for API-key catalogue redaction; the control-strip is an additional
   measure. Tests pin the strip+truncate+null-to-empty shape.

4. LlmHttpSupport non-2xx body (LlmHttpSupport.java :150-160). LLMs are
   black boxes that can emit attacker-chosen output; provider error bodies
   can echo request fragments. The diff drops the body preview from the
   non-2xx WARN log and exception message, keeping only provider/status/
   host. The IOException/InterruptedException branches (:144,:147) still
   embed the full operator-configured base URI, but that is trusted config
   per the threat model ("Operator-set config is trusted"), and any
   api-key/token/bearer-adjacent secret in it is caught by the Redactor JUL
   filter on log; pre-existing and within the trust boundary. The preview()
   helper still echoes 2xx parse-failure bodies (<=200 chars) at three
   OpenAi/Embedding call sites — pre-existing, out of this ticket's scope,
   and not forbidden by the threat model (the catalogue redactor still runs
   on any logged form).

5. LinkingJob (LinkingJob.java :143-160). Routed through SafeLog.warn,
   which drops the message body and emits only class names; the only
   interpolated value is d.id() (a post UUID, not user prose). Confirmed no
   remaining direct LOG.* call in the file.

No test was weakened: the embedding/anthropic/shared-pipeline tests flip
from "preview present" to "marker ABSENT + host/status present", a
deliberate behavior change matching U-13, and add positive assertions for
the surviving triage fields. No cross-module drift introduced (audit_log
writer and the API-key catalogue are untouched, preserving the
"two cannot drift" invariant).
