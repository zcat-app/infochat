RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
- `DigestCommandHandler.resolveGroupInTx` throws `IllegalStateException` when the group row is absent at handler time, which the router maps to the fixed `INTERNAL_ERROR_REPLY`, while a present-but-unauthorized caller gets `ERROR_DIGEST_NOT_ADMIN`. In principle this reply difference is a group-existence oracle, but it is unreachable in normal operation: a group-scope `/digest` only reaches the handler after the router's step 3.5 approval gate and step 6 `lookupGroupId` have already confirmed an active group row, so the throwing branch corresponds to a group-removed-mid-dispatch race rather than an attacker-driven probe. Flagging only so the user can decide whether to collapse the two replies for uniformity; not a threat-model commitment.
