RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - The `jsonEscape` helper in BootstrapAssetsLoader.java (lines ~395-407 in the new file) only escapes `\\`, `"`, `\r`, `\n`. Control characters (U+0000–U+001F other than \r\n) or non-BMP surrogates in the bootstrap file path would land as raw bytes in `details_json` and either produce invalid JSON (Postgres `::jsonb` cast rejects, aborting the load and Collector boot) or, depending on path source, leak unescaped bytes into the audit log. Operator-trusted input per the threat model ("Operator-set config (properties files, bootstrap JSON) is trusted"), so this falls outside the documented threat surface — flagged only as a robustness/portability advisory if the user later widens the model.
  - The `attribution_url` for the `kraken` sub-verb is built by concatenating `entry.id()` twice without URL-encoding into the public attribution URL stored on every asset_config row. An operator-typo asset id containing URL-unsafe characters would produce a broken bare URL surfaced to users via `/zcash`/`/monero` replies. Operator-trusted input; cosmetic rather than security per the threat model's "asset commands … reply names its data source and includes the source URL bare" — the bare-URL promise is about formatting (no markdown link syntax), not about character-set validation of operator inputs.
