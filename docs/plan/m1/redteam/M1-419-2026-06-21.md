RED-TEAM VERDICT: CLEAN

The diff adds a deterministic /unfollow-source command handler that deletes
only the caller scope's source_subscription row, audit-before-effect on a real
deletion, with a per-scope/per-(user,scope) isolation model. Audited against
docs/spec/security.md commitments: authorization-before-execution (§Authorization
model), per-(user,scope) isolation, audit-log coverage of real mutations
(Invariant 7 / §Failure handling intent-logging), the LLM tool boundary
(§Prompt-injection defenses — no mutation tool exposed), the ban / probation /
rate-cap chain (router steps 1.5/4/7), and the determinism boundary. No
commitment is left undelivered:

- Permission gate runs BEFORE the <id> parse, so an unauthorized group caller
  cannot probe parse behavior; group branch requires group-admin or bot-admin,
  DM branch is the caller's own scope only (handler lines 336-355). PERM-ESCAL:
  none — scope_id is server-resolved from (adapter, contactId)/groupDbId, never
  caller-supplied.
- Scoped DELETE binds scope_kind + scope_id + source_id; a DM caller can delete
  only scope_id = own user id, a group admin only scope_id = the inbound group's
  db id. Per-(user, scope) isolation holds (test
  unfollowDeletesOnlyCallerScopeSubscriptionNotOtherScopes).
- All SQL is parameterized PreparedStatements (no string concatenation of user
  input). INJECTION: none.
- Real deletion writes exactly one UNFOLLOW_SOURCE audit row before the delete,
  same transaction, via AuditLogWriter + RedactionHook.AuditRow; a not-subscribed
  no-op writes no row, matching the established no-effect-doesn't-audit pattern.
  AUDIT-EVASION: none — the destructive operation is always logged.
- /unfollow-source is excluded from the probation allowed-set
  (unfollowSourceIsNotAllowedDuringProbation), so the router step-5/7 gate blocks
  probation callers upstream; the handler correctly trusts the router for the
  ban/probation/rate-cap chain per the documented trust boundary (steps 1-9 are
  the determinism boundary in InboundRouter, not the handler).
- Input is bounded: parseSourceId trims, splits on whitespace, and parses a
  single UUID token; no unbounded loop or LLM call. DOS: none.
- No LLM tool is added; the command is dispatched only by the deterministic
  command path, consistent with §Prompt-injection defenses "Never exposed".

OUT-OF-MODEL:
  - Source-existence oracle: a registered caller sending a well-formed but
    non-subscribed source UUID receives REPLY_UNFOLLOW_SOURCE_NOT_SUBSCRIBED,
    whereas an absent source UUID receives ERROR_UNFOLLOW_SOURCE_UNKNOWN_ID
    (handler lines 358-365). This lets any caller distinguish "source exists
    globally but I'm not subscribed" from "no such source." The threat model
    declares source rows GLOBAL state (§Source URL visibility, D7) with no
    commitment that a source's existence is hidden from registered users, and
    source ids are unguessable random UUIDs, so this is not a documented
    confidentiality boundary. Flagged so the user can decide whether to collapse
    the two replies (mirroring /remove-source's behavior) for defense-in-depth.
