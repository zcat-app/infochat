RED-TEAM VERDICT: FINDINGS

FINDINGS:
  - CATEGORY: DOS
    SEVERITY: low
    PROMISE: §Threat model / §Authorization model — the determinism boundary
             ("Steps 1–9 never call the LLM. This is the determinism boundary")
             and the §"User content in exceptions" / boundary-validation posture
             require that argument parsing at a system boundary (the command
             parser, step 6) reject malformed input deterministically rather than
             throw. The §DOS category explicitly covers "blocking-the-event-loop
             in the messaging adapter." Adversarial framing: "assume any
             unvalidated input will be malicious."
    GAP: The new `-w` window parser validates *shape* but not *magnitude*. The
         numeric group `([0-9]+)` in WINDOW_PATTERN is unbounded
         (AuditCommandHandler.java:267 / QuarantineCommandHandler.java:477).
         parseWindow only guards `Long.parseLong` with try/catch
         (AuditCommandHandler.java:307-323 / QuarantineCommandHandler.java:517-533);
         it does NOT guard the subsequent `Duration.ofHours(n)` /
         `Duration.ofDays(n)` / `Duration.ofDays(n*7)`. For a value that fits in a
         long but overflows the Duration's internal seconds field (e.g.
         `999999999999999d`, ~1e15 days > Long.MAX/86400 ≈ 1.06e14),
         `Math.multiplyExact` inside `Duration.ofDays` throws an uncaught
         `ArithmeticException`. Even when the Duration constructs, the downstream
         `clock.instant().minus(args.window)` (AuditCommandHandler.java:233-234 /
         QuarantineCommandHandler.java:426) throws `DateTimeException` when the
         result leaves Instant's supported range. Neither exception is caught in
         the handler; it propagates out of `handle(...)`. The `w` unit also does an
         unchecked `n * 7` (silent long overflow → negative Duration → a cutoff in
         the future that silently returns an empty audit/forensic view, a quiet
         correctness failure rather than a throw).
    REPRO: A bot admin (the per-adapter admin threat profile explicitly
           contemplates a *compromised* admin via SIM-swap / port-out on Signal)
           sends `/audit -w 999999999999999d` (or `/quarantine list --all -w
           999999999999999d`). The format passes the regex and `Long.parseLong`,
           then `Duration.ofDays` throws `ArithmeticException` that is never caught
           in the handler. Depending on the (out-of-diff) dispatcher's error
           handling, this either surfaces an error/stack trace to the actor or, if
           the handler runs on the adapter's event loop without a catch-all,
           degrades that processing path. A correct boundary validator would reject
           the over-range window with the same friendly usage error it already
           returns for `-w abc`.
    SUGGESTED-FIX-CLASS: input-sanitization

OUT-OF-MODEL:
  - The change makes a bare `/audit` default to a 24h window
    (AuditCommandHandler.java:264, DEFAULT_WINDOW = 24h), so an admin doing a
    casual audit sees only the last day unless they pass `-w`. This is a
    deliberate, documented decision (D53, ADMIN_GUIDE.md, design/03-commands.md)
    and the data remains reachable via a wider `-w`, so it is not a threat-model
    gap — flagged only so the user can confirm the forensic-completeness
    trade-off (a casual auditor under-scoping their view) is acceptable.
