RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - corrId-based direction discrimination relies on the local simplex-chat
    subprocess being honest about stamping corrId on send results and omitting
    it on received async events (SimpleXMessageCodec.java:332-340). The
    subprocess is inside trust boundary 7 (SimpleX local transport, trusted
    while loopback), so a subprocess that mis-stamps corrId — causing a self-
    echo loop (send result decoded as Inbound) or silent inbound drop
    (received event decoded as SendAck) — is not an adversary-reachable path
    under the documented threat model. Flagged only so the user can decide
    whether the codec→client direction contract deserves an explicit invariant.
  - First-only decode (SimpleXMessageCodec.java:323-340): a batched received
    newChatItems event carrying more than one item silently drops items beyond
    the first. This is a message-delivery/availability gap, not a security
    property the threat model commits to (the DOS category covers resource
    exhaustion, not best-effort delivery). Dropping items removes them from all
    processing, so it cannot be used to slip a message past the ban check or
    rate caps. Noted as a functional-coverage caveat the implementer already
    documented in-code, not a finding.
