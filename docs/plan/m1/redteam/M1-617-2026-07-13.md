RED-TEAM VERDICT: CLEAN

No findings. The diff extends the `semanticSearch` chat tool with a lexical
full-text arm fused with the existing semantic arm by Reciprocal Rank Fusion
(all in one parameterized SQL statement), adds a STORED generated tsvector
column + GIN index (V58), and appends a deterministic retrieval-provenance
notice to every successful chat reply. Every security commitment the threat
model attaches to this surface is preserved:

- Scope isolation: both fused arms carry `status='READY'` + the
  `source_subscription` predicate INSIDE the arm before its LIMIT
  (SemanticSearchTool.java queryFusedPosts, the FULL OUTER JOIN branches),
  so no over-fetch-then-filter path can surface an unsubscribed or non-READY
  post — matching security.md §Prompt-injection defenses ("Returns READY
  posts visible in the calling (user, scope) only"). Exercised by
  SemanticSearchToolHybridIT.lexicalAndFusedPathNeverSurfaceUnsubscribedOrNonReadyPosts.
- No SQL/prompt injection: the model-supplied query reaches
  `plainto_tsquery('english', ?)` only as a bind parameter; RRF_K is a Java
  int constant; all 13 placeholders are parameterized and correctly ordered
  (SemanticSearchTool.java). The provenance notice interpolates the integer
  count only via MessageFormat — never feed-derived uids/titles — so no
  attacker-influenced text enters the deterministic surface (D31 honored).
- D19 determinism: fusion is SQL-only with a total order
  (`fused_score DESC, post_id ASC`); regconfig pinned to 'english' on both
  column and query side. The LLM never picks the set.
- D5 / D54: embeddings stay local; raw vector never emitted; lexical-only
  rows emit `"similarity":null` rather than a fabricated number.
- LLM output sanitizer / D43: the reply is sanitized (ChatAgent.java step 8)
  before InboundRouter.dispatchChat appends the notice; the notice is a
  deterministic en/cs bundle string taking the bundle path (never the
  translator) and cannot carry admin-command strings.
- Ban / invite / admin-tier gates: untouched. The router change lives
  entirely in dispatchChat, downstream of every authorization step.
- DoS: the fused query is bounded by per-arm LIMIT + outer LIMIT +
  statement_timeout (cancellationService.armToolConnection); the per-turn
  tool cap and the tool-input length cap are unchanged.
