OUT-OF-MODEL:
  - Phantom-admin vs. last-admin-protection interaction under operator
    misconfiguration. canonicalizeContactId extracts the bare queue id from
    the operator-pasted SimpleX contact link via extractQueueAddressId
    (SimpleXAdapter.java:224-227). If the embedded SMP queue id does not
    byte-match what simplex-chat later reports as that contact's inbound
    contactId (SimpleXMessageCodec.decodeNewChatItem reads
    chatInfo.contact.contactId, line 330), AdminBootstrap seeds an admin row
    no inbound message can ever match. That row still counts toward the global
    last-admin protection count (SELECT COUNT(*) ... is_admin=true AND
    is_banned=false, security.md §Authorization model), so a real admin could
    in principle be /revoke-admin'd down to only the unreachable phantom,
    locking the deployment out of admin while the protection trigger believes
    one live admin remains. This is NOT a diff-introduced security gap: the
    input is operator-set config (explicitly trusted by the threat model),
    the same divergence risk existed pre-diff if an operator mistyped a bare
    id, and the diff arguably REDUCES it by reusing the single bot-identity
    extractor instead of hand-extraction in 6-adapter.sh. Flagged only so the
    user can decide whether bootstrap should later assert the seeded id is
    reachable; no adversary-controlled path exists within the documented model.
