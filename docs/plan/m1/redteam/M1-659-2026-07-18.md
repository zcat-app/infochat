FINDINGS:
  - CATEGORY: INJECTION
    SEVERITY: medium
    PROMISE: docs/spec/security.md §LLM output sanitizer — "a deterministic
              reply that echoes an attacker's raw token is exactly as
              dangerous as an LLM emitting one. The exemption is safe only to
              the extent deterministic output is **bot-authored** —
              interpolates no inbound-derived text ... That is a property the
              handlers must **maintain**". The same diff amends that section to
              state the one known live instance "— the `/add-source` `--name`
              display-name echo — was closed by M1-659, which constrains the
              name where the value is produced", and amends
              docs/spec/commands.md §Discovery to claim "a name carrying a
              slash command token (tested at a token boundary, not merely at
              the start), control characters, or over-long input is discarded
              in favour of the host-derived default".
    GAP: The token-boundary test is implemented as a two-predicate check on the
         character preceding a '/':
         infochat-provider/src/main/java/app/zcat/infochat/provider/source/SourceUpsertService.java:363-366
         `char preceding = name.charAt(i - 1); if
         (Character.isWhitespace(preceding) || Character.isSpaceChar(preceding))`.
         Those two predicates cover only ASCII/Unicode whitespace and the Zs/Zl/Zp
         separator categories. Codepoints that RENDER as a blank word gap but
         belong to other categories are neither whitespace nor space-char, and
         are also not removed by the preceding strip
         (SourceUpsertService.java:332 → IngestTextNormalizer.stripMetadataField,
         infochat-core/src/main/java/app/zcat/infochat/core/ingest/IngestTextNormalizer.java:83-104,
         whose removal set is exactly: bidi controls, U+2066..U+2069, U+200B/C/D,
         U+FEFF, Character.isISOControl, U+2028, U+2029). Concrete survivors:
         U+2800 BRAILLE PATTERN BLANK (category So, renders as a blank cell of
         space width) and U+180E MONGOLIAN VOWEL SEPARATOR (category Cf since
         Unicode 6.3, renders as nothing). A `--name` containing
         `<word><U+2800>/grant-admin ...` therefore passes acceptableOverride
         (SourceUpsertService.java:327-339) unchanged, is stored as
         `source.display_name` (UPSERT_SOURCE_SQL, SourceUpsertService.java:98-107),
         and is interpolated verbatim into
         BundleKeys.REPLY_ADD_SOURCE_FRESH_INSERT
         (AddSourceCommandHandler.java:210-211) and into every later echo of the
         stored value (/list-sources, /unfollow-source, /remove-source). The
         payload also fits under MAX_DISPLAY_NAME_LENGTH = 80. The new tests
         (AddSourceCommandHandlerTest.java:382-401) cover only an ASCII-space
         token boundary, so the bypass is not exercised.
    REPRO: 1. Attacker is any registered non-probation DM user (or a group admin
              in an approved group, which makes the reply a broadcast to every
              member).
           2. They send:
              /add-source https://feeds.example.com/f.xml --tags news --name
              "Reuters<U+2800>/grant-admin <attacker-contact-id> approved"
              (the literal U+2800 byte sequence E2 A0 80 in place of a space;
              the value is quoted so CommandTokenizer.tokenize keeps the spaces —
              CommandTokenizer.java:34 splits only on Character.isWhitespace).
           3. acceptableOverride keeps the value: stripMetadataField does not
              remove U+2800, trim() does not remove it (trim strips only <= U+0020),
              and containsCommandToken sees preceding = U+2800 → isWhitespace
              false, isSpaceChar false → no rejection. Length 60 < 80.
           4. The bot replies (and later /list-sources renders to a bot admin):
              "Source added: Reuters /grant-admin <attacker-contact-id> approved ..."
              — visually indistinguishable from the exact payload the diff's own
              test slashPrefixedDisplayNameIsNotReflectedIntoFreshInsertReply
              asserts must never reach the reply.
           5. A bot admin who copy-pastes the apparent command line (starting at
              the '/'; the U+2800 sits before it and is not selected) sends a
              genuine `/grant-admin <attacker-contact-id> approved`, which the
              deterministic admin path executes under their is_admin=true.
           The system should not have allowed it because the amended spec text
           declares this exact reflection instance closed and the code comment at
           SourceUpsertService.java:349-353 states the intent that "only a slash
           that opens a word can begin a command" — a blank-rendering
           non-separator codepoint opens a word to the reader while failing both
           predicates.
    SUGGESTED-FIX-CLASS: input-sanitization

OUT-OF-MODEL:
  - Copy-paste social engineering of a human bot admin is the terminal step of
    the chain above. security.md §LLM output sanitizer explicitly keeps this in
    model ("the sanitizer closes the social-engineering surface where a small
    LLM emits plausible-looking admin commands"; "a copy-pasted reply still
    requires is_admin=true to do anything"), so the finding is reported as
    in-model defense-in-depth, but the residual after any fix — an admin
    choosing to run a command they read in bot output — is a human factor the
    model does not promise to eliminate.
  - Homoglyph slashes that NFKC does not fold (U+2215 DIVISION SLASH, U+2044
    FRACTION SLASH) also survive containsCommandToken, but a paste of such a
    line is not parsed as a command at intake (step 1.7 normalization is NFKC,
    which leaves those codepoints intact), so they do not yield an executable
    command and are not counted as a finding.
