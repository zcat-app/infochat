Audit notes (no findings; recorded for the user's confidence):

The M1-294 diff is entirely hardening or no-op refactor against the
threat model in docs/spec/security.md. Each security-relevant change was
checked against the relevant commitment and found to TIGHTEN, not weaken,
the defended surface:

1. SimpleXMessageCodec.classifyError (substring match -> exact include
   list, simplex/SimpleXMessageCodec.java:464-486). The old matcher
   promoted any tag CONTAINING "ratelimit/tryagain/timeout/temporary/
   unavailable/connectionerror" to TRANSIENT; the new code promotes only
   the four exact members of TRANSIENT_ERROR_TAGS and classifies
   everything else PERMANENT. This moves strictly toward the spec's
   fail-closed default (messaging.md/security.md "cannot tell ->
   PERMANENT"). The only theoretical regression is a genuinely-transient
   tag now classified PERMANENT (non-retried), which the spec explicitly
   sanctions as the safe direction. No infinite-retry DOS is introduced;
   one is removed (a permanent tag containing "temporary" no longer loops
   the Provider retry forever).

2. closedForGood terminal latch (simplex/SimpleXAdapter.java:297, 360,
   383). Replaces the close()-resets-`reconnecting` approach with a
   volatile latch checked BEFORE the reconnecting branch in
   requireConnected. A close() that races an in-flight reconnect now
   classifies post-close sends PERMANENT rather than stale TRANSIENT.
   Strict improvement to the existing PERMANENT-on-close behavior; no
   promise depends on the removed line.

3. SimpleXAdapter.start() identity gate (simplex/SimpleXAdapter.java:
   213-329). Tightens the bot-queue-address check from isBlank() to
   SimpleXIdentity.isWellFormed(), reaching parity with the Signal ACI
   startup check and closing the forged-empty-mention class the spec
   forever excludes (security.md "What's intentionally NOT in v1" ->
   display-name/forged mention). Stronger boundary, no weakening.

4. maxInboundMessageBytes single-sourcing (Signal + SimpleX adapters and
   codecs). The advertised capability now reads the codec's
   MAX_INBOUND_TEXT_BYTES constant (value unchanged at 16_384). Decode-time
   enforcement at SimpleXMessageCodec.java:367 (and the group path) is
   intact and unchanged. Pure single-source refactor; no behavioral delta.

5. Test/IT changes (MultiAdapterProductionIT bot-queue-address literals
   widened to >=43-char well-formed values; new SimpleXStartIdentity-
   ValidationTest; classifyError exact-list test). Adapt callers to the
   stricter gate and pin the new behavior; no production trust boundary is
   relaxed by the test edits. The audit_log trigger DISABLE/ENABLE in the
   IT teardown (MultiAdapterProductionIT.java:176-192) is a test-only
   cleanup wrapping a DELETE; it is not reachable by the runtime Provider
   role, which retains INSERT-only on audit_log (security.md DB roles).
