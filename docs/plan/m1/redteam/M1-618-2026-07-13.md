RED-TEAM VERDICT: CLEAN

Audited M1-618 (chat conversational-refinement recovery) against
docs/spec/security.md. The diff adds a fixed similarity cutoff constant,
two fixed bot-instruction directives (CLARIFY_DIRECTIVE,
AFFORDANCE_DIRECTIVE), a SemanticPreFetch record, and isMarginalGrounding
to ChatAgent, plus the paired commands.md / design-note prose. No
threat-model commitment is left undelivered:

- Prompt-injection defense (security.md §Prompt-injection defenses): the
  per-call random UUID marker on the UNTRUSTED_CONTENT wrapper is
  preserved (ChatAgent.java:527). The new directives are fixed constants
  appended strictly AFTER the wrapper close delimiter
  (ChatAgent.java:382, order userPrompt + semanticBlock +
  refinementDirective) — in the trusted tail, never inside the wrapper,
  never quoting or listing feed-derived text. The determinism-guard test
  refinementDirectiveIsAppendedWithoutAlteringTheRetrievedSet asserts the
  directive sits after the close delimiter. No untrusted text escapes the
  wrapper.

- LLM output sanitizer (security.md §LLM output sanitizer): the
  clarify/affordance prose the model writes still passes through
  outputSanitizer.sanitize(finalText) on every path (ChatAgent.java:418);
  admin-command stripping and its per-occurrence audit are unchanged.

- Determinism / D19 (semanticSearch tool row): isMarginalGrounding only
  READS the similarity value from the tool's own JSON output; it does not
  alter which posts are retrieved, their order, or retrievedPostUids.
  semanticBlock still folds success.content() in verbatim. The confidence
  signal is computed in Java, never by the LLM.

- Tool allowlist + scope isolation (Trust boundary 5, tool table):
  AFFORDANCE_DIRECTIVE only OFFERS the already-registered,
  subscription-isolated getReferences tool; it is an offer, not an
  auto-fetch (D28 pre-fetch deliberately not extended), so no new tool is
  exposed and the fixed per-turn tool-call cap is unaffected.

- Audit (Authorization step 8): writeAuditRow (CHAT_MODE) fires at
  doHandle step 2 (ChatAgent.java:314) before the refinement logic; a
  clarify turn is still audited like any chat turn.

- DOS: isMarginalGrounding iterates the already-capped result set once;
  no unbounded loop; the pre-fetch still runs at most once per turn and is
  skipped when the M1-606 breaker is open.

- Provenance null on clarify turns (D31/D43 constraint): the clarify path
  interpolates nothing into the deterministic notice — strictly safer than
  the "count only, no feed-derived text" rule — and the paired commands.md
  amendment documents the third notice state.

Fail-open branches in isMarginalGrounding (return false on
unparsable/non-array/lexical-only payload) affect only whether a UX
clarifying question is asked; no authorization, isolation, or disclosure
boundary depends on the signal. The clarify gate is steerable by
prompt-injected retrieved content, but bypassing it only reverts to
pre-M1-618 weak-grounding answers, which remain wrapped and sanitized —
fully within the accepted "LLMs are black boxes" trust model with all
existing defenses preserved.
