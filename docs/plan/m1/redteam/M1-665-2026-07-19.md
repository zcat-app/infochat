RED-TEAM VERDICT: CLEAN

The diff implements decision D67 (M1-665): a deterministic trigger in
ChatAgent.doHandle that probes the doc_embedding command-intent corpus
(M1-664) against the caller's inbound text BEFORE the LLM is called and,
on a match above a conservative 0.70 similarity threshold, appends the
matched command's usage+examples block to the chat reply AFTER
sanitize+translate. Audited against docs/spec/security.md commitments:

- Delivery-ordering contract (§LLM output sanitizer, path a): the
  *whether* (lookupIntentForDelivery in step 3c, before the LLM call)
  and the *what* (HelpCommandHandler.composeUsageBlock over CATALOGUE
  bundle keys) are both deterministic end-to-end, driven by the caller's
  own inbound text — the same trust grade /help runs on. The model's
  tool elections cannot influence delivery: modelElectedHelpLookupNever-
  TriggersDelivery and injectedToolCallCannotDeliverAdminUsage pin that
  the r2 INJECTION regression (post-sanitize model-elected append) is
  structurally dead under this design.

- Tier-filter-before-return (§Prompt-injection defenses, D66 invariant
  2): visibleTargets is computed via the same HelpCommandHandler.visible
  predicate /help applies (now factored as visibleCommandNames) and
  bound as target_ref = ANY(?) INSIDE the WHERE of the shared
  CommandIntentIndex.lookupCommand. An invisible command's name can
  neither match nor be composed.

- Match-not-assert (D66 invariant 1): only the command NAME crosses the
  SQL boundary; the usage body is composed at delivery time from the
  runtime CATALOGUE. A stale or attacker-edited intent row can degrade
  a match but cannot produce wrong syntax.

- Defense-in-depth at composition: composeUsageBlock re-checks
  visible(entry, caller) before composing. The TOCTOU window between
  step 3c's resolveCallerTier and step 9b's resolveCallerTier can only
  fail safe (a demotion between the two calls causes composeUsageBlock
  to return empty — no block). adminUsageNeverDeliveredToNonAdmin pins
  this against a simulated SQL-tier-filter bypass.

- No inbound-derived text in deterministic output: the appended block
  is the fixed bundle key CHAT_HELP_DELIVERY_HEADER plus the byte-
  identical output of composeUsageBlock (the same method /help <cmd>
  invokes). No byte of userMessage is interpolated. The header is
  gated behind usageBlock.isPresent(), so a defense-in-depth refusal
  suppresses the header too.

- Single authorized post-sanitize accretion: deliveredCommandName comes
  from a single LIMIT 1 probe; at most one block is composed and
  appended per reply (atMostOneUsageBlockPerReply pins this against a
  model that makes multiple helpLookup calls).

- Bundle completeness (D43): reply.chat.help_delivery.header is added
  to both en and cs bundles. The block is composed via composeUsageBlock
  in scopeLanguage and bypasses TranslationPipeline per the D43 two-path
  rule (deterministic = bundle).

- Breaker gating + failure mode: the trigger is skipped when the chat
  breaker is OPEN (same posture as the D28 semantic pre-fetch); embed
  or SQL failures are caught, logged at WARN with userId only (D37 — no
  user prose), and degrade to no block delivered. The trigger does not
  arm pg_cancel_backend and is bounded by statement_timeout on the
  pgvector probe and infochat.embeddings.timeout-ms on the embed call,
  matching the accepted D28 pre-fetch cost shape.

- Input bounding + SQL safety: the query is truncated to
  SEMANTIC_QUERY_MAX_CHARS before embed; CommandIntentIndex.lookupCommand
  uses parameter binding exclusively (setString/setArray/setDouble) with
  a ?::vector cast; toVectorLiteral formats Java floats via
  StringBuilder.append(float) — no attacker-controlled characters can
  enter the SQL text.

- Constructor surface: the two new @Inject params (EmbeddingProvider,
  HelpCommandHandler) are resolved by CDI in production; tests that do
  not exercise delivery pass null and override lookupIntentForDelivery
  (package-private test seam) so the nulls are never dereferenced.
