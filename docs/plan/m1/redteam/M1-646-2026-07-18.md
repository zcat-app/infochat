OUT-OF-MODEL:
  - Group-scope advertisement of DM-only bot-admin commands. `HelpTier.BOT_ADMIN`
    is scope-agnostic (HelpCommandHandler.java:348), so a bot admin running
    `/help` (or `/help recover-pool`) inside a group renders the new entries —
    whose own usage text says "DM only" — into a multi-party scope where every
    member reads them. This is pre-existing and not introduced by the diff:
    `/ban`, `/unban`, `/vouch`, `/audit`, `/quarantine`, `/invite`,
    `/grant-admin` and `/revoke-admin` are all DM-only handlers (they return
    `ERROR_COMMAND_DM_ONLY`) already carried at `BOT_ADMIN` tier, and there is
    no `DM_ONLY` tier in the enum even though the inverse case (`GROUP_ADMIN` =
    "never shown in DM") is modelled. security.md makes no confidentiality
    commitment about privileged command NAMES, so this is a design question for
    the user rather than a threat-model violation.
  - Direct-invocation existence oracle. A non-admin who sends `/recover-pool`
    in a DM receives `ERROR_ADMIN_ONLY`
    (RecoverPoolCommandHandler.java:104-105), and in group scope receives
    `ERROR_COMMAND_DM_ONLY` from a check that runs BEFORE the admin gate
    (RecoverPoolCommandHandler.java:94-95) — either reply confirms the command
    exists. The spec's "no admin-command existence leak" clause
    (`commands.md` §Discovery line 226) is scoped only to `/help <unknown>`
    fuzzy suggestions, which the diff honors correctly. Pre-existing dispatch
    behavior, untouched by this diff; flagged only so the user can decide
    whether the property should be widened beyond the `/help` surface.
  - Unbounded echo of the requested token. `unknownCommandReply`
    (HelpCommandHandler.java:268-289) interpolates the caller-supplied first
    token back into the reply with no length cap at that site, so
    `/help <very long token>` is an outbound-size amplifier bounded only by the
    step-1.5 transport rate cap and the §commands.md command-body input cap.
    Pre-existing (M1-573), no added line in this diff touches it; the
    MessageFormat use is argument-position so it is not a format-string
    injection.
