OUT-OF-MODEL:
  - The cap-hit signal travels via a static `ThreadLocal` consumed only on the `FetchScheduler` success path (`consumeCapHit()` is not called in the `catch` block). With the current Bluesky/Reddit fetchers this is safe because `signalCapHit()` is invoked only immediately before a clean `return`, so no fetcher can throw while the flag is set. A *future* fetcher that signals saturation mid-pagination and then throws would leave a stale `TRUE` on the dispatch thread, misattributing one saturation tick to the next source ticked on that thread. This is an operational-accuracy fragility of the admin saturation signal, not an exploitable security-model violation, and is noted only so the latent coupling is on record.
