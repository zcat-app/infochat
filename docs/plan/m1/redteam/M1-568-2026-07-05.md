OUT-OF-MODEL:
  - Tampered-bundle residual (the whole ticket sits here). The diff's own
    stated purpose — "Defense-in-depth on an out-of-model threat (a tampered
    bundle is a supply-chain concern docs/spec/security.md places out of
    scope)" (prod/scripts/restore.sh:273-274) — matches the threat model:
    security.md line 27 ("Operator-set config ... is trusted") and lines
    29-30 ("Out of scope for v1: ... supply-chain attacks on operator
    infrastructure"). restore.sh is an operator-run recovery script consuming
    a pack.sh bundle built on operator infrastructure; a tampered bundle
    requires compromise of that infrastructure, which the spec explicitly
    excludes. No in-model commitment (authorization order, ban check, invite
    gate, quarantine, LLM tool surface, DB-role least-privilege, rate
    limiting, audit-log integrity) runs in this path, so nothing in the
    threat model is under-delivered. The change is a strict tightening
    (extract-all -> extract-only-allowlisted at prod/scripts/restore.sh:286,
    plus the empty-array abort at :280-285) and introduces no in-model
    regression.

  - Residual weaknesses in the added defense (all out-of-model, noted only so
    the user can decide whether to widen the model to cover restore-bundle
    integrity):
      1. Full-bundle tamper still writes arbitrary system paths. The allowlist
         (identity_rel_paths) is derived from INFOCHAT_*_DATA_DIR values read
         from the bundle's OWN secrets.env (restore.sh:238-250). An attacker
         controlling the whole bundle simply sets INFOCHAT_SIGNAL_DATA_DIR to
         e.g. /etc/cron.d and includes a matching etc/cron.d/ member in
         identities.tgz; the consistency gate (grep -qF "$rel/") passes and
         tar -C / writes there. The allowlist only blocks EXTRA members
         appended to an otherwise-honest bundle, not a coherently-tampered
         one. (Also game-over regardless: that same tampered secrets.env
         becomes the deployment's DB passwords and admin token.)
      2. Symlink-follow inside the allowlisted subtree. Naming a directory
         member extracts it recursively; a symlink member inside $rel pointing
         outside, followed by a file member through it, can redirect writes
         beyond the data-dir. GNU tar's own default symlink-traversal
         protections mitigate this, but the allowlist adds nothing against it.
      3. Consistency gate is a substring match (grep -qF "$rel/"), not an
         anchored/exact match — noted for completeness; only reachable via a
         tampered bundle.
    All three require a tampered bundle (supply-chain), so none is a
    threat-model violation. If the operator wants restore-bundle integrity to
    become an in-model guarantee, that is a spec-amendment decision (e.g. sign
    pack.sh bundles and verify in restore.sh), not a gap in this diff.
