  - Within-post token split across the anchor and original lines. The diff makes
    `/saved` render two feed-derived lines per row (`SavedCommandHandler.java:442-446`,
    `:522-526`): the English anchor in the primary slot and the publisher's own words
    bracketed beneath. Each takes its OWN `LlmOutputSanitizer.sanitize` call inside
    `DisplayHeadline.derive` (`DisplayHeadline.java:260-267`), which correctly preserves
    the M1-697 one-author's-field unit. The consequence is that a privileged command word
    on one of the two lines and its flag on the other is neither redacted nor audited —
    e.g. a feed title whose ingest translation carries `/list-sources` while the original
    carries a bare `--all` mid-string, since the bracket only wraps the first and last
    tokens. This is NOT a new exposure class: `docs/spec/security.md` §"Flag position
    mirrors the parser's own scan" already accepts exactly this residual ("a privileged
    command split ACROSS two posts' fields ... is neither redacted nor audited ... bounded
    by dispatch still requiring `is_admin=true`"), and a 20-row `/saved` page already put
    20 separately-sanitized author fields in one message before this diff. Noted so the
    user can decide whether the spec's residual sentence should be widened from "two
