## Verbatim verdict

RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - Lower-bound (past-dated) `published_at` is not clamped: a malicious
    source can claim an arbitrarily old publish time. This is not in the
    threat model (the spec commits only to a `<= fetched_at` upper clamp,
    and a past-dated claim sorts to the bottom of `ORDER BY published_at
    DESC`, so it neither dominates `searchPosts` windows nor advances the
    `MAX(published_at)` reconnect cursor). It could let an attacker suppress
    their own post from short recent-window queries, but visibility-
    suppression of attacker-controlled content is not a defended asset.
    Noting only so the user can decide whether a sanity floor is worth
    adding; not a finding.

## Adversary reasoning (verbatim)

`PostPersister.persist` is the single persistence sink for RSS, Bluesky,
and Nostr `NormalizedPost`s, so the clamp applies uniformly with no bypass
path. The Nostr path clamps to `LEAST(created_at, fetchedAt)` already in
`NostrEvent`, then the same `PostPersister` clamp re-applies (idempotent).
RSS and Bluesky parsers produce `NormalizedPost` with raw source times,
then go through `PostPersister`. The reconnect cursor `MAX(published_at)`
at `NostrStreamSource.java:474` reads from `post`, which is now clamped —
so the cursor cannot be pushed past now. The comparison direction is
correct; the clamp is total (fetchedAt non-null per SPI; null publishedAt
preserved as NULL). The diff touches none of the auth, ban, audit-log,
LLM-tool, or input-intake surfaces (consistent with the sensitive-surface
inventory). The promise added to `schema.md` §Posts and derivatives is
delivered by the implementation. No gap between threat-model promise and
delivery.
