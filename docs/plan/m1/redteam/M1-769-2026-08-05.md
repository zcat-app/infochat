            `if (LlmCallBudget.isBound() && !Thread.currentThread().isInterrupted() && !LlmCallBudget.current().tryDraw())`.
            When the calling thread carries an interrupt, NO draw is taken
            and the call is STILL delegated (line 81
            `return delegate.generate(...)`). The justification (javadoc
            lines 43-50) is that "M1-764 pins that an interrupted caller
            sends no request".
          - infochat-llm-adapter/src/main/java/app/zcat/infochat/llm/impl/LlmHttpSupport.java:181-195
            contains no such check. `sendForBody` calls
            `http.send(request, ...)` directly and only handles
            `InterruptedException` after the fact (line 190). The
            "no request" property therefore depends entirely on
            `java.net.http.HttpClient.send` testing the caller's interrupt
            flag before issuing the request — an implementation detail of
            the JDK, not a contract its javadoc states.
          - The result is asymmetric in the unsafe direction: if any provider
            impl (a future non-HTTP provider, a JDK whose `send` issues
            first, or a caller-side retry harness that re-issues after the
            flag is consumed) does reach the wire on an interrupted thread,
            those calls are spend that the budget never sees. This is the
            same M1-763 cancellation leg the diff cites as "M1-767's largest
            named over-count leg, at up to ~211 phantom calls per timeout"
            (SystemLlmBudget.java:1065-1069) — now driven to an under-count
            of zero instead of being bounded.
    REPRO: 1) A group's content produces enough clusters that the FULL render
            overruns its slot window (M1-763), so `renderFuture.cancel(true)`
            interrupts the render thread (DigestWorker.java:283).
          2) The render loop continues to completion by design
            (DigestWorker.java:279-282). Every remaining
            `provider.generate` passes `BudgetedLlmProvider` with the
            interrupt armed, skips the draw, and is delegated.
          3) If the delegate issues the request — which nothing in this
            repository enforces — those calls are real spend that never
            charges the ceiling. Repeatable every slot by keeping the render
            just over its window.
          The system should not have allowed it: an exemption from the only
          digest cost control should be enforced by a check the codebase
          owns, not inferred from a downstream library's current behaviour.

OUT-OF-MODEL:
  - `SystemLlmBudget.recordCalls(int)` (SystemLlmBudget.java:280-283) is
    retained as a PUBLIC, UNGATED, unattributed write path with, by its own
    javadoc, "no production caller left". It bypasses the ceiling entirely
    and its draws carry a null groupId so they count toward the aggregate but
    toward no group's reserve. Not adversary-reachable today, but it is a
    live API that silently defeats both new bounds if a future caller picks
    it up.
  - A budget-truncated render returns a non-null section list, so
    `DigestWorker` persists `digest_section` rows and a later
    `/retry --digest` takes the REPLAY leg and re-delivers the prose-less
    bytes rather than re-rolling (proved by
    `DigestBudgetScopingTest.retryReplayLegDrawsNothing` /
    `retryFallbackRerunDrawsItsExactCalls`). This weakens §Failure handling's
    "`/retry` after recovery re-rolls the prose with the original frozen post
    selection" for cost-driven degradation. Flagged out-of-model because the
    same shape pre-dates this diff (any per-cluster degradation, e.g. an OPEN
    breaker, already persisted sections); the diff adds a new route into it
    rather than creating it.
  - Refused headlines on the M1-756 display-hit leg fall into
    `TranslationPipeline.fallbackWithNote` (TranslationPipeline.java:334-337),
    i.e. they render untranslated WITH a note. §Rate limiting (M1-756) states
    over-budget headlines "render untranslated and unbracketed". A cosmetic
    divergence in the degraded shape, no security consequence; noted so the
    user can decide whether the spec sentence needs widening.
  - Cross-group timing/observation channel: whether group B's digest carries
    prose now depends on group A's spend within the same 24h window. This is
    aggregate metadata only, self-evident from a degraded digest, and sits in
    the same class as the accepted translation-cache timing side-channel
    under §What's intentionally NOT in v1.
