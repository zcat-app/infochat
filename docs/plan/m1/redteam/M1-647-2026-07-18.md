FINDINGS:
  - CATEGORY: INJECTION
    SEVERITY: low
    PROMISE: security.md §LLM output sanitizer: "the candidate output
             is passed through a deterministic outbound regex pass that
             strips or refuses output containing admin command strings
             (`/grant-admin`, `/ban`, `/promote`, `/remove-source`,
             etc.) ... It does **not** apply to deterministic command
             output (`/help`, `/status`, `/list-sources`, etc.)
             because that text never passes through an LLM. ... the
             sanitizer closes the social-engineering surface where a
             small LLM emits plausible-looking admin commands across
             any of the surfaces above."
    GAP: The exemption for deterministic command output rests on the
         premise that such output is bot-authored. The diff converts
         the bare unknown-slash reply from a zero-interpolation fixed
         string into an attacker-interpolating one. Before the diff,
         InboundRouter.handleSlash's terminal branch returned
         bundleLoader.get(BundleKeys.ERROR_UNKNOWN_COMMAND, ...) with
         no arguments (InboundRouter.java:1445). After the diff,
         HelpCommandHandler.slashMissSuggestion
         (HelpCommandHandler.java:332-334) renders
         ERROR_HELP_UNKNOWN_COMMAND with the RAW, un-normalized
         `commandName` as argument {0}, and InboundRouter.java:1435-1439
         returns it. The gating condition is permissive: similarity()
         scores `query.contains(candidate)` at 0.8, above the 0.6
         MATCH_THRESHOLD (CommandIntentSynonyms.java:339-341), so ANY
         token that merely contains a visible command name as a
         substring passes and gets echoed in full — up to the 8192-char
         command body cap. This surface carries no sanitizer pass, by
         the spec's own exemption. A narrower form of the primitive
         already existed pre-diff on the `/help <arg>` path (the old
         unknownCommandReply also echoed `requested`), so the diff
         broadens reach rather than creating the capability — which is
         why this is scored low rather than medium.
    REPRO: 1. Attacker is any registered, non-probation, non-banned
              member of an approved group (the D47 gate is satisfied by
              a normal user; no privilege needed).
           2. Attacker sends one group @mention with the body
              `/summary/grant-admin` — a single whitespace-free token.
           3. handleSlash finds no handler named
              "summary/grant-admin" and no matching asset, then calls
              slashMissSuggestion. similarity() returns 0.8 because the
              query contains the visible command "summary", so a
              suggestion exists and the reply is rendered.
           4. Every member of the group, including any bot admin
              present, sees a bot-authored message reading:
              "Unknown command `/summary/grant-admin`. Did you mean one
              of: /summary? See /help for the commands available to
              you." The literal string `/grant-admin` now appears in
              bot output. Longer padding tokens work identically up to
              the body cap.
           5. Why it shouldn't have been allowed: this is exactly the
              copy-pasteable admin-command-string social-engineering
              shape §LLM output sanitizer exists to suppress ("Every
              match is audit-logged (per-occurrence, not throttled)").
              Here no sanitizer runs and no audit row is written,
              because the spec exempted this class of output on the
              assumption it could not carry attacker-chosen bytes. The
              blast radius is bounded — dispatch still requires
              is_admin=true, so a copy-paste by a non-admin does
              nothing — but the deterrent and the audit trail the spec
              committed to for the equivalent LLM surface are both
              absent.
    SUGGESTED-FIX-CLASS: input-sanitization
