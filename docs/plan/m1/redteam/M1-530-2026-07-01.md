OUT-OF-MODEL:
  - Entire diff is operator-tier bootstrap-wizard shell tooling (prod/scripts/4-llm.sh,
    prod/scripts/6-adapter.sh) run by the trusted operator on the host, plus tests and
    ticket metadata. The threat model's adversaries (messaging-app senders, feed content,
    LLMs) cannot reach these scripts. security.md §Threat model classifies "operator-set
    config (properties files, bootstrap JSON)" as trusted and puts "supply-chain attacks on
    operator infrastructure" out of scope. The added credential-scrubbing (clear_remote_llm_creds
    deleting infochat.llm.*.api-key / infochat.embeddings.api-key from application.properties and
    INFOCHAT_LLM_API_KEY from secrets.env on switch-to-local; the 6-adapter.sh sed of de-selected
    adapters' INFOCHAT_SIMPLEX_ADMIN_TOKEN / INFOCHAT_SIGNAL_ADMIN_CONTACT_ID) is a hygiene
    improvement over the trusted boundary, not a change to any adversary-reachable surface.
  - Residual (already documented as accepted future work in security.md §Per-adapter admin
    threat profile): the 6-adapter.sh reconcile only removes a bootstrap-admin secret when its
    adapter is DE-selected. When SimpleX stays selected across re-runs the still-configured
    INFOCHAT_SIMPLEX_ADMIN_TOKEN is deliberately preserved (collect_admin skip-if-set path), so
    a token left set after first-admin establishment could re-arm admin if the SimpleX admin is
    later /revoke-admin'd in a multi-adapter deployment. The spec already assigns unsetting the
    token to the operator and marks durable single-use survival as future work; this is not an
    adversary-reachable path (the token is a secret only the trusted operator holds), so it falls
    outside the documented threat model rather than constituting a finding. Noted only so the user
    can decide whether the wizard should proactively unset the token post-establishment.
