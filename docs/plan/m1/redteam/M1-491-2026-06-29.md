OUT-OF-MODEL:
  - Incomplete bidi-control coverage in SafeLog.stripControls
    (infochat-core/src/main/java/app/zcat/infochat/core/log/SafeLog.java:45-49).
    The diff strips only U+202E (RIGHT-TO-LEFT OVERRIDE) among the Unicode
    bidirectional-formatting codepoints, plus the U+2028/U+2029 line/paragraph
    separators. The remaining bidi reorderers — U+202A LRE, U+202B RLE,
    U+202C PDF, U+202D LRO, and the directional isolates U+2066 LRI /
    U+2067 RLI / U+2068 FSI / U+2069 PDI — survive the strip and can achieve
    the same visual line-reordering forgery the diff's own javadoc cites as
    the reason to strip U+202E. A relay (NostrRelayConnection NOTICE) or any
    other untrusted-text log source could embed U+2067/U+2066 to visually
    rearrange a logged line for an operator reading it. This is flagged as
    OUT-OF-MODEL rather than a FINDING because docs/spec/security.md makes
    no commitment to bidi/control sanitization of log lines: the implementation
    chooses its own codepoint set, and §"User content in exceptions" /
    §"Secrets handling" only commit to dropping exception bodies and applying
    the API-key Redactor — neither of which this diff weakens. There is no
    threat-model PROMISE bullet to anchor a finding against. Surfaced so the
    user can decide whether to extend the model (e.g. strip the full
    Cf bidi-formatting category) or accept the residual as a documented
    hardening gap.
