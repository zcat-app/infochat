OUT-OF-MODEL:
  - Per-level stack-frame width vs. SafeLog's "class names only" cause-chain form.
    The threat model (§"User content in exceptions") describes SafeLog as
    "truncates the cause chain to class names (depth-capped at 5)". The
    localization logger's stackWithoutMessage is a distinct utility that renders
    FULL stack frames for each of up to 5 cause levels — more verbose than
    SafeLog's class-names-only cause form. This is a log-line-size/verbosity
    consideration, not a confidentiality gap: StackTraceElement frames and class
    names carry no user-authored prose (getMessage()/toString() are never
    invoked at any level; suppression is pinned by
    stackRenderingIncludesCauseChainFramesButNoMessages in both test classes).
    The threat model commits to no per-utility log-size budget for this surface,
    and the cause-chain DEPTH — the one attacker-influenceable dimension flagged
    in the prior round-1 low DOS finding — is now bounded by MAX_CAUSE_CHAIN_DEPTH
    (=5) with an explicit truncation marker
    (SignalJsonRpcClient.java:969-1000, SimpleXAdapter.java:790-825, pinned by
    stackRenderingDepthCapsCauseChain). Frame-count per exception is bounded only
    by JVM stack depth and is not demonstrably driven by inbound content from the
    diff. Noting for the user to decide whether a log-size budget belongs in the
    model; not a FINDING against the current threat model.

REMEDIATION ASSESSMENT (re-audit context):
  The round-1 low DOS finding (unbounded acyclic cause-chain depth bloating a
  single log line) is adequately remediated. The rewritten stackWithoutMessage
  in both SignalJsonRpcClient.java and SimpleXAdapter.java caps the walk at
  MAX_CAUSE_CHAIN_DEPTH=5, emits an explicit "... (cause chain truncated at
  depth 5)" marker, and retains the IdentityHashMap-backed cycle guard so a
  self-referential (A->A) or A->B->A cycle terminates. The core D37/§"User
  content in exceptions" confidentiality promise — no user-authored prose in
  exception messages or stack traces — holds across the entire cause chain:
  getMessage()/toString() are never called; only getClass().getName() and
  getStackTrace() (content-free) are rendered, at every level. Message
  suppression across the chain, cycle termination, and depth truncation are
  each pinned by named unit tests in both adapter test classes. No new
  INFO-LEAK, AUTH-BYPASS, INJECTION, PERM-ESCAL, or AUDIT-EVASION surface is
  introduced by the diff.
