Audit notes (not findings):

The diff adds a UTF-8 aggregate byte budget (MAX_RESULT_BYTES = 16 KiB) and
a per-title byte cap (MAX_TITLE_BYTES = 2 KiB) to GetReferencesTool.execute,
mirroring the already-shipped pattern in SearchPostsTool, ListSavesTool, and
RecallMemoryTool. This STRENGTHENS the defense the threat model demands in
docs/spec/security.md §Prompt-injection defenses ("All free-form string and
list inputs across every tool below are length-bounded by a profile-driven
cap ... Tool results are reinjected verbatim into the chat prompt") rather
than weakening any commitment.

Checked and falsified each plausible regression:

- Scope isolation (Invariant 1 / trust boundary 5): the SQL scope filter
  (GetReferencesTool.java:98-101, both p1 and p2 gated on the caller's
  source_subscription set, both required status='READY') is UNTOUCHED. The
  new `break` at line 139 only drops entries that have ALREADY passed the
  scope filter; it can never widen visibility or surface an out-of-scope or
  non-READY (quarantine-placeholder) post. No INFO-LEAK.

- INJECTION: the truncation applies only to `to_title` via the shared
  GetPostTool.truncateUtf8 helper, and the result still flows through
  jsonStr() escaping (line 130-132) exactly as before. `uid`, `url`,
  `link_type`, `score` are unchanged. Titles are vetted READY-post ingest
  content. truncateUtf8 is the same code-point-safe helper the sibling
  tools use; no new mid-sequence-split risk is introduced by this diff.

- DOS: the change reduces, not increases, worst-case context-window
  consumption. LIMIT is still 25 (line 40) and now an aggregate 16 KiB cap
  bounds the reinjected JSON. No unbounded loop or blocking introduced.

- Determinism: ORDER BY pr.score DESC, p2.uid ASC is preserved, so the
  keep/drop split under the budget is deterministic for a fixed result set.

- The 16 KiB / 2 KiB caps are hardcoded rather than profile-driven, but
  this matches the pre-existing sibling-tool implementation across the whole
  tool family (SearchPostsTool:41, ListSavesTool:43/53, RecallMemoryTool:39)
  and is not a regression this diff introduces; the bound now EXISTS where it
  previously did not. Not a gap in a threat-model promise.

No threat-model commitment in docs/spec/security.md is left undelivered by
this diff.
