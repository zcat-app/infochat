OUT-OF-MODEL:
  - Restore-integrity masking via capture-file truncation: the gate reads only the tee'd capture file ($STAGING/pg_restore.stderr) and checks only PIPESTATUS[0] (prod/scripts/restore.sh:372-373), ignoring tee's own exit status. GNU tee on a file-write error (e.g. host disk exhausted mid-restore — plausibly adversary-assisted by bloating DB content pre-pack) warns and keeps copying to the console, so the capture file can be truncated to just the two early ignorable extension-COMMENT lines while later real error lines ("No space left on device") appear only on the console. The gate then passes a genuinely partial restore (restore.sh:387-410) and the table-presence backstop (restore.sh:418-424) also passes because the schema landed. Residual risk is bounded: the subsequent image build on a full disk fails loudly anyway, and restore correctness is a design-doc promise (docs/design/07-deployment.md §7.10.1), not a docs/spec/security.md commitment — operator tooling integrity under disk exhaustion is outside the documented threat model. Flagged in case the user wants the gate to also fail on a non-zero tee status (PIPESTATUS[1]).
  - Terminal-escape passthrough to the operator console: `pg_restore: error:` lines can embed attacker-influenced DB values (e.g. constraint-violation messages quoting row data), and COPY text format does not escape ESC (0x1b), so ANSI control sequences in stored content could reach the operator's terminal via the tee (restore.sh:372) and the residue printf (restore.sh:395). This is not widened by the diff — pre-diff, pg_restore stderr already flowed raw to the same console — and attacks on the operator's terminal via deployment-script output are outside the documented threat model (security.md scopes the Provider/Collector runtime surfaces; operator infrastructure is out of scope). Noted so the user can decide whether restore/backup tooling output should strip control characters.
  - Persisted user content in the stderr capture file: on a failing data load, pg_restore CONTEXT/DETAIL lines can quote row content (chat_memory, post bodies), which now lands in $STAGING/pg_restore.stderr. D37's "user content never in non-audit logs" commitment is scoped to the application logger, the file is 0700-staging (umask 077, restore.sh:33,205) and removed by the EXIT trap (restore.sh:206), and reading it requires host access — out of the documented model.
