# Red-team audit: M1-199 (pre-commit, in-progress branch)

Verbatim threat-actor verdict:

```
RED-TEAM VERDICT: CLEAN
```

The diff is a strict tightening of `/save`: it adds an any-caller-scope
visibility filter (DM subscription ∪ active membership in approved,
non-removed groups) on top of the pre-existing `READY`-status gate, and
folds the no-access case into the same `error.save.unknown_uid` path as
a nonexistent UID. Delivery verified against the threat model's relevant
commitments:

- **Existence-vs-no-access never exposed** (mirroring the `getPost`
  contract in §Prompt-injection defenses): delivered.
  `SaveCommandHandler.java:225-229` routes invisible READY posts,
  non-READY posts, and missing UIDs through one reply; the
  already-saved check (`:236`) and cap check (`:242`) run *after* the
  visibility lookup, so neither `already_saved` nor `cap_met` can be
  used as an existence oracle for posts outside the caller's visibility
  union.
- **No cross-user / cross-adapter bleed**: both EXISTS legs bind
  `actor.id` (the per-`(adapter, contact_id)` `users.id` resolved
  inside the transaction, `SaveCommandHandler.java:213-219, 282-283`),
  so a subscription belonging to another user's DM scope or a group on
  another adapter cannot satisfy the filter — `group_membership.user_id`
  ties to the adapter-bound user row, structurally preserving
  D10/cross-adapter isolation.
- **Group-state gates**: the group leg checks `gm.removed_at IS NULL`,
  `g.approval_status = 'approved'`, and `g.removed_at IS NULL`
  (`SaveCommandHandler.java:122-123`), matching the spec sentence added
  in the same diff; pending/rejected/removed groups and departed
  memberships grant nothing, with named tests for the
  departed-membership and pending-group denials.
- **Soft-deleted sources**: the "stale subscription rows keep removed
  sources saveable" hypothesis was falsified — `/remove-source`
  cascade-deletes `source_subscription` rows in the same transaction as
  the soft-delete (`RemoveSourceCommandHandler.java:84-88`), so the
  EXISTS legs go empty for removed sources without needing an
  `s.deleted_at` predicate.
- **Injection**: all new SQL is fully parameterized
  (`SaveCommandHandler.java:280-283`); the only string-concatenated SQL
  fragment in the diff is a test-fixture boolean (`SaveCommandHandlerTest`
  seed helper), not reachable by attacker input.
- The four "fixture-only" test edits add subscription seeding and
  FK-ordered cleanup only; no assertion was weakened or removed.

OUT-OF-MODEL:

- Stale `group_membership.removed_at`: the filter's
  revocation-on-departure depends on the adapter actually delivering a
  leave signal that sets `removed_at`. On an adapter that drops or lacks
  `user_left_group` events, a departed member retains DM-side
  save-visibility into all of that group's source subscriptions
  indefinitely. The verbatim threat model makes no commitment about
  membership-departure signal fidelity, and the ticket records this as
  an accepted residual bounded by D13's snapshot semantics — flagged so
  the user can decide whether `messaging.md`'s adapter contract should
  promise leave-event delivery for adapters that enable group mode.
- `/save` cost and audit posture (pre-existing, not introduced by this
  diff): `/save` appears in no enumerated rate-limit bucket in §Rate
  limiting, and the handler intentionally writes no audit row. The new
  visibility query makes each UID-probe slightly more expensive (two
  EXISTS subqueries with joins), but the transport-level cap (step 1.5)
  bounds inbound volume; worth a glance only if per-command buckets are
  ever revisited.
