OUT-OF-MODEL:
  - Per-frame self-anchor trust. The bot's mention-recognition anchor
    (botMemberId) is now read from each inbound frame at
    chatInfo.groupInfo.membership.memberId rather than from a one-time
    trusted startup derivation. If an operator exposes the simplex-chat
    WebSocket bot-API port off-loopback (an explicit operator action that
    trust boundary 7 documents as voiding the "no authentication" safety
    property), an attacker reaching the port could inject a synthetic
    group newChatItem frame that sets BOTH groupInfo.membership.memberId
    AND a mentions{} entry's memberId to the same arbitrary value, forcing
    a byte-equality match and delivering an unmentioned group message to
    the Provider. This falls OUTSIDE the documented threat model: the WS
    channel is trusted loopback by trust boundary 7, and the prior
    queue-address model fed its anchor over the same channel via the
    /show_address derivation, so this is not a regression introduced by
    the diff. Noted only so the user can weigh whether a stability/cross-
    check of the per-frame anchor against a startup-derived value is worth
    adding as defense-in-depth before M1-516 removes the derivation
    entirely.
  - Display-name collision at the simplex resolution layer. An attacker who
    renames themselves to the bot's group display name could cause simplex
    to resolve a user's "@<botname>" to the attacker's memberId instead of
    the bot's, suppressing a legitimate mention (availability only, no
    false-positive delivery — the attacker cannot make simplex emit the
    bot's memberId for a mention they did not target at the bot). This
    resolution happens inside the trusted local simplex-chat, is identical
    in shape to the pre-diff queue-address model, and is the inherent
    simplex-layer disambiguation behavior — not an adapter-side gap the
    diff introduces.
