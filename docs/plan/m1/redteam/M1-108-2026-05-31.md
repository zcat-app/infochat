# Red-team audit: M1-108 (2026-05-31)

RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - Membership-event ACI strings from signal-cli's `memberJoined`/`memberLeft` arrays are accepted by SignalGroupHandler without UUID-shape validation (lowercased and forwarded verbatim). If signal-cli itself were compromised or buggy, a non-UUID string could land in Provider's `(adapter, contact_id)` join key. The threat model places signal-cli on the trusted side of the adapter boundary (operator-controlled subprocess), so this is not a finding, but a UUID-shape gate inside the adapter would harden the boundary if the operator's threat model widens to include signal-cli misbehavior.
  - `SignalGroupHandler.handleReceive` calls `dataMessage.getJsonNumber("timestamp").longValueExact()` as a fallback when `envelope.timestamp` is absent; a malformed envelope lacking both timestamps would NPE inside the receive dispatcher. Signal protocol mandates timestamps so the path is structurally unreachable from a well-formed signal-cli; flagging only as a robustness note since this isn't a spec-promised defense surface.
  - The body of an ACI-mentioned group message flows through to Provider with the `@mention` token still present (no in-adapter strip). The spec explicitly allows either the adapter or Provider to do the strip, so this is permitted by the threat model — assuming Provider's intake performs the strip downstream. Worth surfacing only because the audit cannot itself confirm the downstream strip from this diff.
