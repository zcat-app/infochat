RED-TEAM VERDICT: CLEAN

Audited M1-447 (working tree) against docs/spec/security.md in full.

The diff is a pure time-source refactor: it replaces decision-time
`Instant.now()` / `OffsetDateTime.now()` reads with reads from an injected
`java.time.Clock` (CDI producer `ThrottledAdminNotifier.systemUtcClock()`,
field default `Clock.systemUTC()`) in three components, and adds three
integration tests plus ticket/status/audit docs. No new code path, no new
input handling, no auth/ban/audit logic was added or removed.

Threat-model surfaces checked, all preserved byte-for-byte under the
production `Clock.systemUTC()`:

- Invite-code brute-force rate limit (§Invite-code registration). The
  window-count query (InviteCodeConsumer.countAttempts:332) changes
  `OffsetDateTime.now().minus(window)` to
  `OffsetDateTime.ofInstant(now, ZoneOffset.UTC).minus(window)`. The
  zone-offset shift is immaterial: `invite_code_attempt.attempted_at` is a
  timestamptz instant comparison, so both forms encode the same absolute
  cutoff. Threshold semantics unchanged.

- Invite-expiry inclusive boundary (§Invite-code registration: "A code
  expires at the instant NOW() >= expires_at"). The CONSUME_INVITE_SQL
  `expires_at > NOW()` gate (InviteCodeConsumer.java:101) is NOT in the
  diff — it intentionally stays on the DB clock. Boundary unchanged.

- Probation-eligibility / group auto-promote (§Authorization model:
  "first registered, non-probation, non-banned @mention wins"). Only the
  probation comparison moved to clock.instant()
  (GroupAutoPromoteService.java:169). The is_banned and
  registration-existence guards (lines 162-167) are intact and untouched.

- Admin-review TTL auto-reject (§Quarantine workflow / §Re-evaluation
  job). AdminReviewTtlJob.enumerateExpired:99 moves the cutoff to
  clock.instant().minus(adminReviewTtl); the comparison and the
  PENDING-row selection are unchanged.

- Audit logging (§ several). Both audit-insert sites in InviteCodeConsumer
  (INVITE_BRUTE_FORCE_BREACH at :230, INVITE_CONSUME at :263) are
  preserved; no audited operation lost its trail. The breach-mark write
  moving to the sampled `now` does not change which events are audited.

Adversarial angles considered and dismissed:

- Clock as attacker-controlled input: the Clock is supplied only by the
  trusted CDI producer; the QuarkusMock install is test-scoped. No
  request/adapter/LLM input reaches the Clock. No bypass surface.

- TOCTOU: sampling one `Instant now` per consume() and threading it to
  every Java-side read (InviteCodeConsumer.consume:196) TIGHTENS
  consistency relative to the prior per-method `now()` sampling; it does
  not open a new race.

- App-write / DB-read probation_until split (InviteCodeConsumer writes on
  app Clock; ProbationCheck reads on DB clock): documented in
  now-clock-audit.md, accepted because production Clock is
  Clock.systemUTC() == DB now(). Not adversary-influenceable.

No commitment in security.md is left undelivered by this diff.
