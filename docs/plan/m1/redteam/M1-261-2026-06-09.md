OUT-OF-MODEL:
  - LlmRouter case-insensitive provider keying (infochat-llm-adapter/.../LlmRouter.java)
    uses a LinkedHashMap keyed on name().toLowerCase(Locale.ROOT). If an operator
    configured two registered entries whose names differ only by case (e.g.
    "Anthropic" and "anthropic"), the second put would silently overwrite the
    first, collapsing two distinct provider entries into one. Provider names come
    from operator-set config, which the threat model classes as trusted
    ("Operator-set config ... is trusted"), so this is not a finding — flagged
    only so the user can decide whether a startup-time duplicate-name guard is
    worth adding for operator-error resilience.

## Auditor reasoning (verbatim, for the record)

The substitution in resolveAndValidate preserves the all-addresses-must-pass
semantic: firstBlocked iterates every address and returns the first blocked one
(throwing if any is blocked), exactly like the old loop. This is called per
resolution pass, so the per-redirect re-resolution TOCTOU defense is unaffected
(each hop calls this method afresh, taking a fresh DNS resolution and a fresh
host-interface snapshot).

The LlmRouter case-insensitive keying is a robustness/consistency fix aligning
router with the startup guard. No security promise in the threat model concerns
LLM provider-name casing; "Local and remote LLMs have the same trust level."
There's no privilege or isolation boundary at the provider-name resolution layer.

The test fixtures flagged in the sensitive-surface inventory (AddSourceIT etc.)
are unchanged in their security-relevant SQL — the diff only adds
`import java.util.Set` and swaps the override method in test doubles, no change
to the is_admin / 'invited' fixture SQL or the DELETE FROM audit_log cleanup.

The diff is a pure behavior-preserving consistency refactor:
- The SSRF blocklist semantics are byte-identical (full isBlockedAgainst verified
  against the old inline logic).
- Per-pass vs per-address enumeration is correctness-neutral (interface set is
  consistent within one DNS-resolution pass; freshness preserved per pass; TOCTOU
  re-resolution per redirect unchanged).
- Test doubles override the new seam isBlockedAgainst, so the loopback carve-out
  still applies to both isBlocked and firstBlocked paths — no test was weakened
  to permit a previously-blocked range.
- The LlmRouter case-insensitive keying touches no threat-model trust boundary.
- The flagged test-fixture SQL lines are not modified.

No promise in the threat model is broken by this diff.
