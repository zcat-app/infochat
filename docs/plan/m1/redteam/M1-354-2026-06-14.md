RED-TEAM VERDICT: FINDINGS

FINDINGS:
  - CATEGORY: INFO-LEAK
    SEVERITY: low
    PROMISE: docs/spec/security.md §Secrets handling — "User content in
             exceptions": "Exception messages and stack traces emitted via
             the application logger MUST NOT contain user-authored prose
             (chat-mode message bodies, post bodies, saved-post annotations,
             command arguments). The application provides a `SafeLog` utility
             that drops the exception message body, retains only the exception
             class name, and truncates the cause chain to class names
             (depth-capped at 5). The original `Throwable` is never passed to
             the underlying SLF4J logger. `SafeLog` also applies the closed
             API-key catalogue redactor to the caller-supplied message ..."
    GAP: infochat-collector/src/main/java/app/zcat/infochat/collector/eval/
         embedding/EmbeddingWorker.java lines 395-399. The new pgvector-
         rejection branch logs the raw caught `SQLException rejection` as the
         final SLF4J argument:
           LOG.error("EmbeddingWorker: pgvector rejected a ?::vector literal
             for the batch (sqlState={}); ... (error_class={})",
             rejection.getSQLState(), ERROR_CLASS_EMBEDDING_FORMAT_REJECTED,
             rejection);
         Passing the `Throwable` to `LOG.error` hands the full, unredacted
         PSQLException stack trace and server message to SLF4J, directly
         contradicting the categorical rule "The original `Throwable` is never
         passed to the underlying SLF4J logger," and bypasses the closed
         API-key catalogue redactor that `SafeLog` applies to the message.
         This same file already codifies the correct convention at lines
         416-420 of attemptEmbed ("SafeLog, never the raw Throwable: the
         provider exception can echo its request context...") and already
         imports `app.zcat.infochat.core.log.SafeLog` (line 5); the new branch
         is the only `processBatch` failure path that hands a raw Throwable to
         the logger — the sibling non-finite and dimension-mismatch branches
         (lines 331-340, 356-365) log only scalar fields. The round-1 review
         recorded `negative_space: WARN` for this ticket.
    REPRO: A pgvector literal-parser data-exception (SQLState class 22) is
           raised on the `?::vector` INSERT. The driver's PSQLException carries
           the server error text (echoing the offending literal) and any chained
           cause; SLF4J renders the entire unredacted stack trace into the log
           stream. The bound INSERT (`post_embedding(post_id, embedding,
           embedding_model, fetched_at)`) has no body column, so user prose is
           unlikely in *this* exception specifically — but the spec's rule is
           categorical precisely so an auditor need not reason case-by-case: any
           API-key-shaped token or content reachable in the exception message or
           cause chain is emitted raw, having bypassed `Redactor.redact`. The
           defense the spec promised (no raw Throwable to SLF4J; redactor over
           the message) is structurally absent on this path.
    SUGGESTED-FIX-CLASS: other
