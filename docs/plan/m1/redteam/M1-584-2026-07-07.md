OUT-OF-MODEL:
  - Guard is a literal-prefix match with no path canonicalization
    (reject_unsafe_data_dir in prod/scripts/restore.sh:264-279 and
    prod/scripts/pack.sh:212-227). A data-dir value using `..` traversal
    (e.g. `../../etc/cron.d`) or a symlinked directory would not match the
    SYSTEM_DATA_DIR_PREFIXES denylist yet could resolve to a system path
    once docker normalizes the `-v /$rel:/$rel` mount and the root untar
    (restore.sh:477) writes through it. This only bites a COHERENTLY
    tampered bundle (matching secrets.env value + matching tar member),
    which security.md §Threat model places out of scope ("supply-chain
    attacks on operator infrastructure" out of scope; "Operator-set config
    ... is trusted"). The diff's own comment (restore.sh:262) acknowledges
    the no-realpath limitation. Flagged only so the user can decide whether
    to promote the bundle to a semi-trusted surface; not a threat-model
    violation as written.
  - SYSTEM_DATA_DIR_PREFIXES omits `/usr` and `/usr/local`
    (restore.sh:263, pack.sh:211). On a merged-usr system `/bin`, `/sbin`,
    `/lib` are symlinks into `/usr`, so a data-dir under `/usr/bin` or
    `/usr/lib` is a real system-binary location that the denylist does not
    cover. Same out-of-model rationale: the data-dir originates from
    trusted operator config / a trusted bundle. Noted for completeness of
    the defense-in-depth denylist, not as an in-model adversary path.
  - The whole M1-584 surface (pack.sh / restore.sh operator clone tooling)
    lies outside the documented threat model. security.md scopes its
    commitments to the running Provider/Collector services, adapters, LLM,
    DB, ingest pipeline, authorization, invite/ban, quarantine, rate
    limiting, DB roles, and secrets handling; it makes no promise about
    restore-time data-dir validation. The diff strictly ADDS
    defense-in-depth (a denylist that partially restores the pre-M1-569
    EACCES backstop) and CORRECTS an over-claiming comment; it removes no
    protection and weakens no spec invariant. Every data-dir-derived
    writable mount in both scripts is gated by the new guard before the
    mount is built.
