OUT-OF-MODEL:
  - Operator-misconfiguration footgun (trusted-config, not adversary-reachable).
    DeepSeekProvider.customizeRequestBody (infochat-llm-adapter/.../impl/DeepSeekProvider.java:208-216)
    enables DeepSeek thinking whenever infochat.llm.<task>.reasoning-effort is set to
    a depth value, by emitting reasoning_effort with NO code-level coupling to that
    task's max-tokens. The class JavaDoc (lines ~132-137) claims enabling it for the
    security judge is "gated on ... raising that task's max_tokens so reasoning cannot
    crowd out the verdict," but nothing in the code enforces that coupling. An operator
    who sets infochat.llm.security.reasoning-effort=high on the SECURITY_JUDGE task
    without also raising infochat.llm.security.max-tokens could get reasoning tokens
    consuming the completion budget, truncating/emptying the verdict. A truncated
    verdict is a schema-violating reply, which routes to the Stage 2 infrastructure-
    failure path (security.md §Failure handling) whose DEFAULT is release-as-READY —
    i.e. a silent fail-open of the "actual security boundary."
    Why OUT-OF-MODEL, not a FINDING: (1) Operator-set config is explicitly TRUSTED in
    the threat model (§Threat model, "Operator-set config ... is trusted"), so this is
    an operator footgun analogous to the spec's own "phantom admin" blind spot, not an
    adversary-reachable path — no adapter-inbound input can set reasoning-effort.
    (2) The shipped default (key unset) sends "thinking":{"type":"disabled"}, which the
    diff introduces specifically to PREVENT this truncation, so the diff strengthens
    rather than weakens the judge path. (3) The Stage 2 infra-failure default release is
    the spec's own documented behaviour (with a profile flag to invert), not a behaviour
    this diff introduces. Flagged so the user can decide whether to add a code-level
    reasoning-effort <-> max-tokens guard (or refuse reasoning-effort on SECURITY_JUDGE
    entirely) to make the JavaDoc's stated gate structural rather than a process promise.
