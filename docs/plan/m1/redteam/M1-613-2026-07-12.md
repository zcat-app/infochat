OUT-OF-MODEL:
  - The committed spike harness docs/plan/m1/spikes/entity-eval.py reads a
    live LLM API key from the environment (INFOCHAT_LLM_API_KEY, sourced from
    prod/runtime/secrets.env) and posts real corpus bodies to
    api.deepseek.com. It reads the key from env and never commits it, so it
    respects §Secrets handling. Any residual exposure (shell history, process
    argv, an operator running it in a shared environment) is operator-side
    infrastructure risk, which §Threat model places out of scope
    ("supply-chain attacks on operator infrastructure", operator-set config
    trusted). Flagged only so the user can decide whether repo-committed
    tooling that touches a production key warrants a handling note; it is not
    an adversary-reachable weakness.

NOTES (why CLEAN, for the escalation reader):
  - Substantive change is confined to EntityExtractorWorker.parseEntities /
    the new entityArray helper (EntityExtractorWorker.java:338-412): the
    entity-reply parser now unwraps a single-array-valued wrapping object in
    addition to a bare array, still returning null on ambiguous/garbage
    replies.
  - Entity extraction is a post-security-gate stage. Pickup is
    status='RAW' AND tagger_done=TRUE AND entity_done=FALSE
    (EntityExtractorWorker.java:497-499), which mechanically excludes
    QUARANTINED posts; Stage 1/2 (the security boundary per
    security.md §Ingest pipeline) runs upstream and is untouched. Parser
    strictness never gates release, so added leniency downgrades no security
    decision.
  - §Failure handling ("Entity failure -> release without entities") is
    preserved: null still routes to releaseWithoutEntities
    (:252-253) and the retry-once policy (:235-247) is intact.
  - entity_type is still filtered against VALID_ENTITY_TYPES / the V28 CHECK
    (:350-353); INSERTs are parameterized (:453-467) — no SQLi; entity_text
    appears in no LLM-tool output shape in the §Prompt-injection tool table,
    so no new INFO-LEAK/INJECTION sink. The prompt template and rotating
    {{id}} delimiter wrapper are unchanged (:139-155).
  - The leniency adds no attacker capability the pre-existing bare-array path
    lacked; entityArray iterates object fields once (:400-410) with array
    size bounded by max_tokens — no new DoS. No auth/ban/audit/per-scope
    surface is touched (consistent with the sensitive-surface inventory).
