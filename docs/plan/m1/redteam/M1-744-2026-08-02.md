RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - docker-compose.gpu.yml passes the host's entire /dev/dri device directory
    into both llama.cpp containers with rwm rights and adds the host's
    render/video GIDs via group_add. This widens the container's host-device
    attack surface (a llama.cpp RCE or malicious-model exploit gains direct
    GPU/render-node access, and GTT pinned-memory charging couples GPU use to
    host RAM). This falls outside the documented threat model, which
    explicitly excludes "side-channel attacks against the LLM host" and
    "supply-chain attacks on operator infrastructure" (security.md §Threat
    model), treats operator-set config as trusted, and frames exposure-widening
    as acceptable when it is "an explicit operator action, never a default"
    (§Trust boundaries items 6-8 — the overlay is opt-in and the base file is
    test-pinned to declare no devices: passthrough). Flagging so the user can
    decide whether container-hardening guidance (e.g. mounting only
    renderD128/card1 rather than all of /dev/dri, read-only where possible)
    belongs in the model or the runbook.
