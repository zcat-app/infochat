RED-TEAM VERDICT: CLEAN

The diff hardens LlmRouterStartupGuard so that operator-set LLM base-urls
of the form scheme://user:pass@host are userinfo-redacted before they are
echoed into any startup WARN, the FATAL local-only conflict message, the
thrown LocalOnlyConflictException, and the URISyntaxException parse-failure
branch (which re-quotes the raw input verbatim). This strengthens the
§Secrets handling and §"User content in exceptions" commitments rather
than weakening any of them.

Audit checks performed against the threat model:

- §Secrets handling ("Stdout console logs pass through the closed
  API-key catalogue redactor"; "Audit-log writes pass through a redaction
  hook"): a base-url userinfo credential is not one of the closed
  API-key catalogue shapes, but the diff adds a dedicated userinfo scrub
  for these log surfaces. All five base-url echo sites in
  LlmRouterStartupGuard now route through LlmHttpSupport.redactUserInfo:
  line 206 (remote-embedding WARN), 226 (FATAL offender task line),
  252 (FATAL offender embedding line), 310 (per-task disclosure WARN),
  and 402-403 (malformed parse-failure WARN, redacting BOTH the raw
  baseUrl and e.getMessage()). The FATAL message and the thrown
  exception are assembled from the offenders list whose entries are
  already redacted, so they inherit the masking. No un-redacted base-url
  echo remains.

- §"User content in exceptions" (exception messages must not leak
  secrets): the LocalOnlyConflictException message is built from the
  redacted offenders list; the parse-failure branch redacts
  URISyntaxException.getMessage(), which is the only other exception
  text path that could carry the raw input. Confirmed both are covered.

- Redactor correctness (LlmHttpSupport.redactUserInfo, line 329-343):
  masks from "://" to the LAST "@", returning "scheme://***@host...".
  For a credentialed URL the user:pass span is fully masked; the
  URISyntaxException message format ("...at index N: <input>") still
  contains the literal "://user:pass@" substring, so the scrub catches
  it. For a credential-free URL with an "@" in the path the function
  over-masks the host — the safe over-redaction direction for a
  diagnostic line, never an under-redaction. No "://" or no trailing
  "@" returns the value unchanged. Null in yields null out.

- Visibility widening: LlmHttpSupport goes package-private -> public, but
  only the static redactUserInfo member is published; all HTTP machinery
  stays package-private. The change exposes a pure string-scrub function
  with no state, no auth surface, and no I/O — no new attack surface.

- The sensitive-surface inventory flagged input-validation lines, but
  those are pre-existing config reads and URI parses unchanged in
  behavior by this diff; the only behavioral change is adding redaction.

No gap between the threat model's promise and the diff's delivery was
found. No AUTH-BYPASS, INFO-LEAK, INJECTION, DOS, PERM-ESCAL, or
AUDIT-EVASION finding.
