RED-TEAM VERDICT: CLEAN

The diff delivers the M1-675 threat-model commitment in
docs/spec/security.md §LLM output sanitizer:

  "the group-visible echo surfaces (`/saved` reply, the `/summary`
   cluster headline, and the degraded group digest) are additionally
   passed through the closed-list `LlmOutputSanitizer` at render, where
   a title or tag whose canonical form is a privileged command renders
   as `[redacted command]`. ... the M1-675 render-side redaction ...
   emits the per-occurrence `LLM_OUTPUT_SANITIZED` audit row on every hit."

Verification performed:

1. Write-side reject (commands.md §/save + security.md). SaveCommandHandler
   handle() (SaveCommandHandler.java:228-233) rejects the whole /save with
   ERROR_SAVE_TAG_INVALID when any parsed personal tag contains '/', BEFORE
   any DB write (return precedes executeSave at :245). parseTagList
   (:472-484) NFKC-folds each tag and runs IngestTextNormalizer.stripMetadataField
   first, so U+FF0F fullwidth solidus folds to '/' and is caught; the stored
   value equals the checked value (no TOCTOU). Order is after the size caps,
   so over-length/over-count tags keep their own errors. Tests pin all four
   cases (plain, whole-call, fullwidth, ordering).

2. /saved render (SavedCommandHandler.java:245-281). Every
   attacker-influenceable placeholder is sanitized: title ({1}, :275),
   personal+snapshot tagJoined ({3}, :277), and the filter echo ({4}, :254).
   Bot-authored fields (postUid, counts, relative age) are correctly left
   raw. The snapshot URL is stored in Row but not interpolated into
   REPLY_SAVED_LINE. Group-scope broadcast is exercised by
   savedRedactsCommandShapedTitleAndTagInGroupBroadcast.

3. /summary cluster headline (ClusterBlockRenderer.java:87). first.title()
   is sanitized unconditionally (both degraded and non-degraded paths).

4. degraded group digest (DegradedDigestRenderer.java:38). p.title() is
   sanitized at line start.

5. Audit-row commitment. LlmOutputSanitizer.sanitize() emits one
   LLM_OUTPUT_SANITIZED audit_log row per match (emitAuditRows,
   LlmOutputSanitizer.java:404-435) and throws (fail-closed) if the audit
   write fails; the diff routes all four surfaces through this single method,
   so the per-occurrence audit commitment is inherited structurally.

Adjacent surfaces probed for gaps and found NOT reachable:

- /summary "tags:" line and /saved snapshot tags render controlled-vocabulary
  tags, constrained by the tag.name CHECK `^[a-z0-9][a-z0-9-]{0,47}$`
  (V6__sources_tags.sql:77) — a slash/command token cannot be stored as a
  vocabulary tag, so these echoes cannot carry a privileged command.
- Degraded-digest line-start URL (DegradedDigestRenderer p.url()) is
  scheme-validated at ingest: PostPersister.normalizeUrlForStorage
  (PostPersister.java:240-254) stores only http/https URIs and binds anything
  else (a bare `/grant-admin`, no scheme) as SQL NULL, so a command-shaped
  URL can never render at line start.
- The non-degraded periodic digest (DigestRenderer) renders only
  sanitizer-processed LLM prose, never raw post titles.

FINDINGS: (none)

OUT-OF-MODEL:
  - Source display name echo. The "covered by:" line
    (ClusterBlockRenderer.java:94) and the degraded digest
    (DegradedDigestRenderer.java:38) interpolate p.sourceDisplayName()
    without passing it through the sanitizer. This falls OUTSIDE the M1-675
    commitment, which names only "a title or tag," and is a much weaker
    vector than the closed surfaces: the source display name always renders
    MID-LINE (after a bundle label or after "title — "), never at line
    start, so a reader copy-pasting the whole line does not dispatch a
    command (intake step 1.7 trims leading whitespace and the parser reads
    line 1's first character). Source display names are additionally
    write-constrained on the `/add-source --name` override (M1-659 slash
    reject). Flagged only so the user can decide whether to widen the
    render-side redaction to source display names for defense-in-depth; it
    is not a gap against the documented threat model.
  - Degraded per-cluster prose (DigestRenderer.java:128-129 / degraded
    branch) ships feed-derived prose without the sanitizer. This is already
    documented as accepted residual risk in security.md §"Sanitizer output
    never contains `](`" ("the degraded per-cluster prose branch ... are
    outside it, and the residual risk §Failure handling already records for
    degraded output covers them"), so it is in-model and accepted, not a new
    gap — noted here only for completeness.
