  - CATEGORY: AUDIT-EVASION
    SEVERITY: medium
    PROMISE: docs/spec/security.md §LLM output sanitizer: "the M1-675
             render-side redaction, by contrast, emits the per-occurrence
             `LLM_OUTPUT_SANITIZED` audit row on every hit. So for now this
             exemption carries a **residual risk** on non-error deterministic
             output, not a proven-safe blanket." And: "Every match is
             audit-logged (per-occurrence, not throttled)."
    GAP: The audit row is emitted only from inside
         `LlmOutputSanitizer.sanitize` (infochat-provider/src/main/java/app/
         zcat/infochat/provider/llm/LlmOutputSanitizer.java:418-426 →
         :610-641, `emitAuditRows`, action `LLM_OUTPUT_SANITIZED`), and the WARN
         line only from :325 / :553. Because the default `/summary` form never
         calls `sanitize` on any post title (DigestRenderer.java:208-236) and
         skips the sanitizer entirely for degraded prose
         (DigestRenderer.java:223-224), a feed-supplied privileged-command
         token that reaches a user through `/summary` now produces zero audit
         rows and zero WARN lines. The pre-diff path produced one row per
         matching cluster headline via ClusterBlockRenderer.java:87. The
         threat model names this audit row as the mechanical signal that
         compensates for the write-boundary rejects having "no **mechanical
         guard**"; the diff removes the signal while the token still ships
         (Finding 1). The over-cap branch also makes zero sanitizer calls now,
         so the loss covers the deterministically-reachable branch, not just
         the outage branch.
    REPRO: Run Finding 1's sequence, then have a bot admin run `/audit`
           (or query `audit_log_view` as the operator Admin role). Before this
           diff each `/summary` that surfaced a command-shaped feed title wrote
           one `LLM_OUTPUT_SANITIZED` row carrying `match_kind` = the closed-list
           entry (`/ban`), giving the operator the only mechanical signal that a
           feed is injecting command-shaped titles into user-visible output.
           After this diff the same attack produces an identical user-visible
           delivery with an empty audit trail — the operator has no way to
           detect that the campaign is running, and no way to distinguish "no
           attack" from "attack with the detector removed".
    SUGGESTED-FIX-CLASS: audit-log-coverage
