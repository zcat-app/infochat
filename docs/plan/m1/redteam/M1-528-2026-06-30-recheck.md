RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - `/audit` window default and hard ceiling. The new `-w` flag forces every
    `/audit` query through a window: a bare `/audit` defaults to 24h
    (AuditCommandHandler AuditArgs.DEFAULT_WINDOW = Duration.ofHours(24)), and
    withinRange() caps the maximum admissible window at 1-168h / 1-30d / 1-4w,
    so the chat `/audit` command can never reach audit rows older than ~30 days
    and a casual auditor sees only the last day unless they pass `-w`. This is
    the documented D53 trade-off (ADMIN_GUIDE.md, docs/design/03-commands.md,
    decisions.md D53). It is NOT a threat-model gap: (a) audit rows remain
    append-only and unmodifiable by the actor (DB-role least-privilege,
    append-only triggers) so nothing is hidden from the forensic record itself;
    (b) the operator Admin role retains `SELECT` on `audit_log_view` via psql
    (security.md §DB roles), so older history is still reachable out-of-band;
    (c) security.md makes no commitment that the chat `/audit` command reaches
    unbounded history. An attacker (even a compromised admin per §Per-adapter
    admin threat profile) gains no AUDIT-EVASION benefit from the chat ceiling —
    they can neither delete, alter, nor suppress the underlying rows. Flagged
    only so the user can confirm the forensic-completeness trade-off (chat
    `/audit` blind beyond 30 days; psql is the documented forensic path) is
    acceptable.

  - Prior-audit low DOS (unbounded `-w` magnitude → uncaught
    ArithmeticException / DateTimeException, and silent `n*7` overflow on the
    `w` unit) is REMEDIATED in this recheck. Both parseWindow methods
    (AuditCommandHandler AuditArgs.withinRange / QuarantineCommandHandler
    ListArgs.withinRange) now bound the magnitude (h 1-168, d 1-30, w 1-4)
    BEFORE constructing the Duration, so `Duration.ofDays(n*7)` runs only with
    n<=4 (max 28 days, no Math.multiplyExact overflow), no negative-duration
    wraparound is reachable, and an over-range value returns the same friendly
    usage error as a malformed `-w` (regression tests
    audit_overRangeWindow_usageError / list_overRangeWindow_usageError). Listed
    here only to record that the previously-open item is closed, not as a new
    finding.
