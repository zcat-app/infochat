RED-TEAM VERDICT: FINDINGS

FINDINGS:
  - CATEGORY: INJECTION
    SEVERITY: low
    PROMISE: "Audit-log writes pass through a redaction hook that masks
              values matching a closed catalogue of API-key shapes"
              (security.md §Audit log); "Audit-log the intent"
              (security.md §Authorization model step 8)
    GAP: AuditCommandHandler.java:112 — the `args.actor` user-supplied
         string is embedded into a hand-built JSON string with only
         double-quote escaping (`.replace("\"", "\\\"")`). Backslash
         characters, control characters (newlines, tabs, carriage
         returns, NUL bytes), and other JSON-special sequences are not
         escaped. A value like `test\` produces the JSON fragment
         `"test\"` where the backslash escapes the closing quote,
         breaking JSON structure. PostgreSQL's `::jsonb` cast rejects
         the malformed value, causing a SQLException that aborts the
         audit write and the entire command. The same incomplete escaping
         pattern appears at AuditCommandHandler.java:114 for
         `args.action`, though `args.action` is validated against the
         `AuditAction` enum (lines 85-93) so it cannot contain special
         characters in practice.
    REPRO: A bot admin sends `/audit --actor test\` (where the actor
           value is a string ending in a backslash). The handler builds
           `{"actor":"test\","action":null}` — in JSON, `\"` is an
           escaped quote so the string never terminates correctly. The
           `::jsonb` cast fails. The audit write rolls back. The handler
           returns an internal-error reply. The actual audit query never
           executes. The command's intent is NOT audit-logged. An admin
           who discovers this pattern can make specific `/audit` queries
           that leave no `AUDIT_READ` trace (though they also get no
           data back).
    SUGGESTED-FIX-CLASS: input-sanitization

OUT-OF-MODEL:
  - The per-command rate buckets promised by security.md §Rate limiting
    for the "Parser-only + DB-read paginated commands" group (which
    includes `/audit`, `/quarantine list`, `/saved`, `/export`, and
    similar) do not exist in the codebase. Only the transport-level
    per-(adapter, contactId) cap and the newly-added per-admin
    `/quarantine approve|reject` bucket are implemented. This is
    pre-existing (not introduced by this diff) and is partially
    mitigated by the transport-level cap, but the spec explicitly
    enumerates these as separate buckets with independent caps.
