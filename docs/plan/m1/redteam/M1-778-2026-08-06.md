         adds `DisplayHeadline.displaysAsTheOriginal(postSanitizer1Text,

           * `postSanitizer1Text` is the raw chat/summarizer/roll-up model reply
             after `LlmOutputSanitizer.sanitize` (ChatAgent.java:570,580) —

           * `translated` is the translator endpoint's reply, read straight out

             infochat-llm-adapter/.../LlmHttpSupport.java:61-64 (1–8 MiB, default 8 MiB).
         `DisplayHeadline.displaysAsTheOriginal`
         (infochat-provider/src/main/java/app/zcat/infochat/provider/render/DisplayHeadline.java:493-507)
         is a word walk built on `String.indexOf(word, from)`. The CURSOR
         advances monotonically, but `String.indexOf` is a naive substring
         search: a single needle word of length m searched in a haystack of
         length n costs O(n*m), not O(n). The predicate is therefore quadratic
         in the reply length, not linear.
         Every pre-existing call site bounds its operands and the codebase says
         so explicitly; the new one does not:
           * DisplayHeadline.java:680 (`finishDisplayHit`) — operands went
             through `prepareTranslatedHeadline` → `boundForScan`
             (BODY_SCAN_LIMIT = 2000), with the javadoc at
             TranslationPipeline.java:436-441 naming this exact hazard: "the
             reply is otherwise bounded only by the provider's 1-8 MiB body cap,
             and a hostile endpoint's in-cap reply must not buy megabytes of
             NFKC + closed-list scanning ... [redteam 2026-08-03, low/DOS]";
           * DisplayHeadline.java:397 (`usesAnchor`) — operands already
             `truncate`d to MAX_LENGTH = 200.
         The new prose-leg call is the only invocation with no bound at all.

  - Roll-up fabrication guard weakened by the anchor substitution (M1-743
    regression, correctness rather than a threat-model commitment).
    `CategoryRollupGenerator.java:345-347` substitutes `p.titleEn()` BEFORE
    `DisplayHeadline.of`'s renderability test, which is the opposite of the
    rule `DisplayHeadline.anchorFirst` documents at
    DisplayHeadline.java:228-237: "The field is chosen from the ORIGINAL, then
    that field's anchor is taken. Choosing from the anchor instead would
    resurrect a headline M1-729 killed: `IngestTranslationWorker` has no
    sentinel guard ... a titleless non-English post carries
    `title = UNTITLED_TITLE` and a `title_en` that is a TRANSLATION of that
    sentinel. A translated sentinel is not byte-equal to the sentinel, so
    `titleIsRenderable` would pass it through". `UNTITLED_TITLE` is the literal
    `"untitled"` (IngestTextNormalizer.java:151) and the check is byte-exact,
    so a translator returning `"Untitled"` produces a rendered line. Effect: a
    category whose posts are all titleless (all 729 Bluesky rows in the live
    corpus per DisplayHeadline.java:31-34) on a non-English source no longer
    trips the M1-743 empty-headline-set skip at
    CategoryRollupGenerator.java:367-376, so the model is asked to "name the
    themes" across a list of translated-sentinel lines and the fabricated
    synthesis is sanitized, translated and pushed as the section prefix —
    exactly the outcome the skip exists to prevent ("asking the model to
    synthesize themes of an empty input can only fabricate", line 301). It is
    also a quiet widening of the M1-728 "titles only — no bodies" prompt bound,
    because `IngestTranslationWorker.renderPrompt` feeds the model both title
    and body, so the sentinel's "translation" can be body-derived. Flagged here
    rather than as a FINDING because the closed category set has no label for
    fabricated bot prose and the threat model makes no commitment about it.
  - `body_en` / `title_en` reaching the summarizer and roll-up prompts is
    LLM-authored text that Stage 1's prompt-injection regex set never scans.
    `SummaryProseGenerator.buildPrompt` (lines 206-211) now composes
    `body_en`/`title_en` into the UNTRUSTED_CONTENT block in place of the
    Stage-1-normalized, Stage-1-redacted `body`/`title`. An attacker who owns a
    non-English feed can phrase an injection in the source language (where an
    English-pattern Stage 1 catalogue does not match), and the ingest
    translator renders it into canonical English that no Stage 1 pass ever
    sees. The diff's own claim at SummaryProseGenerator.java:232-238 checks out
