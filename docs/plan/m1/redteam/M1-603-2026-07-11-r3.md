RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - switch-llm.sh mixed-file consent regression, carried unchanged from
    rounds 1 and 2: over an old-format MIXED file (e.g. chat remote, six
    tasks local — a shape the pre-M1-603 switcher itself created), the
    deployment-level default answer classifies as "remote" (chat.base-url
    fallback, prod/switch-llm.sh Phase 1), so an all-Enter run sweeps every
    per-task line and routes all seven tasks remote; the same unconditional
    sweep on any mutating run removes a deliberate hand-written per-task
    LOCAL pin. security.md's commitments here — per-task privacy-disclosure
    correctness and the local-only hard gate — are both delivered (the
    disclosure accurately names all seven now-remote tasks; local-only=true
    still refuses boot), so this remains a consent/expectation regression,
    not a threat-model violation. Flagged a third time for the user to
    decide whether the byte-identical no-op guarantee should be
    re-committed for mixed files.
  - Boot-time DNS TOCTOU, carried unchanged from rounds 1 and 2: the guard
    resolves the shared default base-url's loopback-ness ONCE at boot
    (LlmRouterStartupGuard.perTaskRoutes), while live calls re-resolve at
    request time — a hostname flipping loopback→remote after boot bypasses
    local-only. Pre-existing mechanism (identical semantics for per-task
    URLs); requires control of the operator's DNS for an operator-configured
    host, which the threat model places out of scope.
  - switch-llm.sh silent api-key reuse across a remote→remote provider
    switch (pre-existing at base, M1-418 semantics; NOT introduced by this
    diff): when the operator switches the deployment to a NEW remote
    base-url and secrets.env already holds INFOCHAT_LLM_API_KEY, the old
    provider's key is reused without re-prompting (prod/switch-llm.sh,
    "reused, not re-prompted" branch) and now travels to the newly entered
    endpoint — the same damage class as the closed round-1 finding, but
    operator-visible (the reuse is printed to the console) and unchanged in
    mechanics by this diff (the diff widened the per-run blast radius from
    one task to all seven only because the switch is now deployment-level).
    Flagged so the user can decide whether a provider-host-change should
    force a key re-prompt.
