RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - Translation injection-defense instructions live in the user-role prompt,
    not the system-role prompt. docs/spec/llm.md §Prompt-injection-aware prompt
    shape commits that "the SYSTEM PROMPT instructs the model to treat the block
    as data, not commands ... to never act on URL requests, message-send
    requests, or admin verbs." The translator
    (infochat-provider/.../translation/LlmTranslationProvider.java:86) passes ""
    as the system prompt and carries the entire wrapper + data-treatment
    instructions inside the user message (prompts/translator.md lines 1-25). The
    diff's AnthropicProvider change (AnthropicProvider.java:140-145) now omits
    the system field entirely for that blank-system call shape. This is flagged
    OUT-OF-MODEL rather than as a FINDING because: (1) it predates this diff —
    the wrapper was already delivered in the user role; the prior empty system
    block carried no instructions either, so the diff does not weaken the
    injection posture; and (2) translation input is bot-authored presentation
    prose (cluster summaries, headers, status lines), not raw attacker post
    bodies — security.md §"Translation cache cross-scope timing side-channel"
    states the translated strings are "presentation prose generated by the bot
    ... not user-authored content", so the untrusted-content surface here is
    minimal. The single production call site (TranslationPipeline.java:78)
    confirms only bot prose reaches the translator. Surface this to the user only
    if they want the spec's "system prompt carries the instructions" wording
    enforced as a structural property across all LLM call sites (a separate
    hardening ticket), independent of M1-265's routing-guard scope.

  - LLM provider HTTP clients now set a fixed 10s connect-timeout
    (AnthropicProvider.java:168, OpenAiCompatibleProvider.java:111,
    OpenAiCompatibleEmbeddingProvider.java:107). security.md §SSRF requires
    "an unset timeout is a configuration error", but that requirement governs
    the infochat-ssrf library (feeds, redirects, /add-source probes), not the
    operator-config-trusted LLM endpoints. The added connect-timeout is pure
    hardening and introduces no gap; noted only because the timeout value is
    hardcoded rather than profile-driven, which is a config-hygiene observation
    outside the documented threat model (operator config is trusted).
