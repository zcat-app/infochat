RED-TEAM VERDICT: CLEAN

Audited diff M1-467 (base 98f5ef9e, head m1/M1-467-bootstrap-admin-property-key-contract)
against the threat model in docs/spec/security.md.

Summary of the change under audit:
The diff renames the operator-facing bootstrap-admin property key from
`infochat.adapters.<name>.bootstrap-admin-contact-id` to
`infochat.adapters.<name>.admin` in:
  - docs/design/07-deployment.md (deployment doc / wizard step descriptions)
  - prod/scripts/6-adapter.sh (the wizard that writes application.properties)
  - prod/config/secrets.env.example (a comment only)
  - docs/plan/m1/STATUS.md + the M1-467 ticket file (process bookkeeping)
No Java/runtime source is touched.

Why this is CLEAN against the documented threat model:

1. The runtime already reads the NEW key. The bootstrap-admin minting bean
   (infochat-provider/.../startup/AdminBootstrap.java:141) and the union /
   parse gate (infochat-provider/.../messaging/AdapterRegistry.java:267,306,326)
   read `infochat.adapters.<name>.admin`. Before this diff the wizard wrote a
   key (`bootstrap-admin-contact-id`) the runtime ignored, so the wizard path
   minted no admin and left the union empty — a FAIL-CLOSED state (Provider
   refuses to start when the union is empty, security.md §Authorization model /
   last-admin protection). This diff corrects the wizard/docs to emit the key
   the runtime consumes; it removes a latent bootstrap failure, it does not
   open one.

2. No residual inconsistency. A repo-wide search for the old key
   `bootstrap-admin-contact-id` outside docs/plan/** (historical ticket and
   redteam records) returns no matches; the active provider application.properties
   uses `.admin`, the runtime reads `.admin`, the wizard now writes `.admin`.
   There is no path where the stale key is still honored to seed a duplicate or
   shadow admin row.

3. Threat-model commitments preserved. The per-adapter-optional /
   union-non-empty constraint, the global last-admin protection
   (security.md §Authorization model), and the per-adapter admin scoping
   (§Per-adapter admin threat profile) are all enforced by unchanged runtime
   code reading the same `.admin` key the diff now aligns the wizard to. The
   sensitive-surface inventory correctly reports auth/authorization/audit/ban/
   intake code as untouched.

4. The shell env-var names (INFOCHAT_SIMPLEX_ADMIN_CONTACT_ID /
   INFOCHAT_SIGNAL_ADMIN_CONTACT_ID) are intentionally unchanged; they are the
   dotenv source interpolated via ${...} into the property value, not the
   property key, so the rename does not desynchronize secrets.env from the
   wizard.

No promise in docs/spec/security.md is left undelivered by this diff.
