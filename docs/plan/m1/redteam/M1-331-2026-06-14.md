RED-TEAM VERDICT: CLEAN

The diff hardens the Signal group inbound path at the adapter→Provider
trust boundary (security.md §Trust boundaries #1). It is a net-positive
hardening change with no gap between the threat model's promises and the
delivered behavior. Audited surfaces and conclusions:

1. instanceof-guarded JSON accessors (handleReceive lines 113/116/119,
   arrayOrNull line 313, botMentioned line 63). A present-but-wrong-typed
   envelope / dataMessage / groupV2 / mentions / memberJoined / memberLeft
   field now collapses into the same silent-drop branch as an absent field
   instead of throwing a ClassCastException out of the typed getJsonObject/
   getJsonArray accessor. This strengthens the trust-boundary commitment
   (untrusted Signal-peer wire data must not escape the adapter as an
   exception). No new path reaches identity resolution, ban check, parser,
   or LLM. Mention recognition stays ACI-anchored (D10) — no display-name
   matching is introduced (security.md §"What's intentionally NOT in v1" —
   display-name mention recognition).

2. stripBotMentions span coalescing (lines 234-271). Spans are normalized
   to disjoint [start,end) intervals before deletion, and deletion runs
   right-to-left over the merged set, so overlapping attacker-authored
   bot-uuid spans can no longer make StringBuilder.delete clamp against a
   shortened buffer and silently mutilate the body. The pre-existing
   per-span validation (line 226: long-widened start+length overflow guard,
   start<0 / length<=0 reject) is retained. The merge loop is bounded by the
   mentions-array length, which is bounded by the coarse envelope-line cap
   (referenced at line 156-157) and the decoded-body UTF-8 cap; no unbounded
   loop or event-loop block (DOS) is introduced.

3. getInt("start"/"length", -1) (lines 219-220): Jakarta JSON
   getInt(name, default) returns the default for a missing or non-numeric
   value rather than throwing, so a wrong-typed start/length wire field is
   handled by the existing span-validation guard, not a CCE. Consistent with
   the codec's documented discipline.
