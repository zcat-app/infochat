RED-TEAM VERDICT: CLEAN

Audited M1-518 (remove vestigial SimpleX bot-queue-address `/show_address`
derivation) against docs/spec/security.md. The diff removes the bot's own
self-address derivation and its startup well-formedness health-check, plus
the dead `userContactLink`/`SelfAddress`/`encodeShowMyAddressCommand` codec
surface and associated tests/fixtures, and relabels the `groupHandler`
lifecycle from "derive+adopt" to a direct `buildGroupHandler()` build.

No threat-model commitment is failed to deliver:

- Trust boundary 1 (SimpleX cryptographic identity anchor): group @-mention
  recognition is byte-equality of a `mentions{}` memberId against the
  per-frame `groupInfo.membership.memberId` (D51), landed in M1-514 and
  out of scope / untouched here. The removed derivation read only the bot's
  OWN address and was already consumer-less as the recognition anchor since
  simplex-chat v6.5.4.1. Recognition is unchanged; no spoofing path opens.
- The surviving `SimpleXIdentity.isWellFormed` static validator and
  `canonicalizeContactId` / `extractQueueAddressId` (the operator
  bootstrap-admin-value accept/reject gate, M1-465) are unchanged
  (SimpleXAdapter.java:214-233).
- Authorization model: admin claim-token path (D50), invite-code gate
  (step 2), ban check (step 4), per-(user,scope) isolation, last-admin
  protection — none reachable from or altered by this diff.
- INFO-LEAK (D37): no raw queue address is logged; the one changed DEBUG
  line ("group handler not yet built") carries no sensitive value. The
  removed code's no-raw-value discipline is moot once removed.
- DOS: removal drops a blocking start-time ack-timeout wait; adds no
  unbounded loop or blocking. groupHandler lifecycle (built after WS ready,
  rebuilt on reconnect; candidates before build dropped) is preserved.
- AUDIT-EVASION: the `ALTER TABLE audit_log DISABLE TRIGGER` calls in
  MultiAdapterProductionIT are test-fixture teardown on the test database,
  not a runtime mutate path; runtime append-only triggers are unaffected.

The behavioral change (start()/reconnect no longer fail-closed on a
malformed/absent bot self-address) removed only a simplex-chat wire-contract
startup health-check (design §6.7 per-adapter resilience), which security.md
does not promise as a defense.
