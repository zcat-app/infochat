    GAP: The amended spec's stated residual is exactly two things — a fluent
         mistranslation and output in a third language. A VERBATIM ECHO
         padded with an imperceptible code point is neither, and the spec
         commits the render to refusing it. The render does not refuse it,
         because the "displays as the original" predicate models
         perceptibility as "Unicode general category Cf or Mn", which is
         itself an enumeration — the very failure mode the amendment claims
         to have escaped.

         - infochat-provider/.../render/DisplayHeadline.java:370-379
           (`displayForm`) drops ONLY `Character.FORMAT` (Cf) and
           `Character.NON_SPACING_MARK` (Mn). Its javadoc claims the result
           is "a line reduced to what a reader can actually perceive" and
           that "Naming individual code points is what fails here; the
           category is the property that matters."
         - Imperceptible code points outside those two categories therefore
           survive the reduction and make the two lines compare unequal:
             * U+2800 BRAILLE PATTERN BLANK — category So, an empty braille
               cell, NFKC-stable.
             * U+3164 HANGUL FILLER — NFKC-folds to U+1160 HANGUL JUNGSEONG
               FILLER, category Lo, no glyph.
             * U+115F HANGUL CHOSEONG FILLER — Lo, no glyph.
           None is `Character.isWhitespace`, so neither
           `DisplayHeadline.flattenToOneLine` (DisplayHeadline.java:598-600,
           a Java-ASCII `(?:\R|\s)+` plus `strip()`) nor `String.strip()`
           removes them, and NFKC does not remove them either.
         - Collector side (deliberately byte-identity only, per this diff):

           U+2800 / U+1160 are in none of them, so the padded reply is NOT

         the difference matters:
         - The STRONG harm of rounds 1-3 — one bare foreign line with the
           bracketed original SUPPRESSED — is CLOSED, and closed
           structurally rather than by `displayForm`. `subordinateFor`
           (:453-457) suppresses only on raw equality, and `usesAnchor` can
           only be true when the two rendered lines are raw-unequal, so the

OUT-OF-MODEL:
  - Operator signal for a PADDED echo is gone by design. Narrowing the
    storage check to byte identity means only an exact echo fires
    `ERROR_CLASS_TRANSLATION_ECHO` (IngestTranslationWorker.java:1129-1134);
    a padded echo stores, writes no re-drive stamp, and
    `countAwaitingRedrive` counts stamped rows only, so a source steered
    into permanent padded echo is invisible to an operator. The ticket
    states this consequence explicitly and docs/spec/security.md §Failure
    handling enumerates no ingest-translation notification at all, so there
    is no threat-model promise to breach — raised only so the user can
    decide whether the model should acquire one.
  - `docs/spec/security.md` §"LLM output sanitizer" requires every match to
    be audit-logged. On the echo path the field is dropped BEFORE
    `sanitize` runs (IngestTranslationWorker.java:687-691), so a
    command-shaped echoed title writes no collector-side
    `LLM_OUTPUT_SANITIZED` row. Assessed as NOT a finding for the same
    reason round 1 did: nothing is stored, and the original the render
    falls back to still passes the provider-side `LlmOutputSanitizer` at
    every anchored surface, which audits there. Recorded so the
    disposition stays explicit rather than assumed.
