RED-TEAM VERDICT: CLEAN

Audited diff: target/redteam-diff-M1-607.diff (M1-607 — wire chat-mode
replies into the D31 ProgressNotifier + bundled chat-timeout raise).
Threat model: docs/spec/security.md (read in full).

Summary of why no findings were raised — each security-relevant surface
the diff touches was checked against a specific threat-model commitment
and found to preserve it:

1. LLM output sanitizer (§Prompt-injection defenses — "Before any
   LLM-generated text is delivered to a user, the candidate output is
   passed through a deterministic outbound regex pass"). The chat reply
   is now delivered through StageProgressNotifier.completeDelivered
   instead of the router's sendReply, but the string it delivers is
   result.reply() from ChatAgent.handleTurn, which ChatAgent already
   sanitizes (ChatAgent.java:335 outputSanitizer.sanitize) and translates
   before returning (InboundRouter.java:1342-1351). The notifier is a
   pure transport of already-sanitized text — no LLM-authored surface
   bypasses the sanitizer.

2. No-user-input-in-progress-strings. Every stage string published by
   dispatchChatSelfDelivering (STARTED/RETRIEVING/GENERATING/FINALIZING,
   InboundRouter.java:933-948) and the STOPPED/FAILED terminals resolve
   through bundleKeyFor's enum switch (StageProgressNotifier.java:285-295)
   to fixed BundleKeys constants; user body is never interpolated. The
   new InboundRouterChatProgressTest asserts this directly
   (noPublishedStageStringContainsUserMessageOrRetrievedTitle).

3. Trust boundary 2 / ban + probation ordering (§Authorization model
   steps 2-5). dispatchChatSelfDelivering is only reachable at step 6
   (InboundRouter.java:889), after the invite gate, group approval, ban
   check, and probation gate. The diff does not move, weaken, or skip any
   of those gates; a banned/unregistered/probation user never reaches the
   chat notifier.

4. "Turn discarded as if never generated" (§Failure handling — chat-mode
   LLM-unreachable / delivery failure). runPostDeliveryCommit now gates on
   the terminal finalize's delivery outcome (delivered) instead of a
   MessageHandle (InboundRouter.java:949-977); on a permanent delivery
   abort the pending commit is dropped, so chat_session/chat_memory are
   not written. The /stop-cancelled (null reply) and LLM-unreachable
   (friendly-error reply, no pendingChatCommit set) paths both correctly
   skip the persist.

5. Error/log paths. The failure arm logs via SafeLog.error with only a
   redacted scope id (ContactIds.redact); the exception message is never
   interpolated into any outbound (InboundRouter.java:952-962). No SQL,
   no auth-state mutation, no audit-affecting change in the diff.

6. Config raise (infochat.llm.chat.timeout-ms=120000). A generous LLM
   timeout is operator-config discretion; concurrent doomed calls remain
   bounded by the per-user transport cap (step 1.5), the per-user LLM
   bucket (llmRateCap), the per-group LLM sub-bucket, and the M1-606
   circuit breaker. No documented availability budget is traded away.
