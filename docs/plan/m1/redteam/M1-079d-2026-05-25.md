RED-TEAM VERDICT: FINDINGS

FINDINGS:
  - CATEGORY: PERM-ESCAL
    SEVERITY: high
    PROMISE: "Group-admin (or bot admin acting in the group): /add-source in groups, /unfollow-source in groups, /lang in groups, /group-timezone, /follow-tag in groups, /unfollow-tag in groups." (commands.md §Permission model, closed list of privileged-tier commands)
    GAP: AddSourceCommandHandler.java:139, FollowTagCommandHandler.java:149, LangCommandHandler.java:126, UnfollowTagCommandHandler.java:163 — the group-scope permission gate checks only `groupMembershipRepository.isGroupAdmin(groupDbId, actorId)` with no fallback check for `actor.isAdmin` (bot admin). A bot admin who is not the designated group admin is denied execution of group-admin-tier commands in group scope, inverting the spec's tier hierarchy where bot-admin >= group-admin.
    REPRO: A bot admin (is_admin=true) who is a member of a group but NOT its group_admin sends `/follow-tag crypto` in that group. The handler calls `isGroupAdmin(groupDbId, actorId)` which returns false (user has is_group_admin=false). The handler returns the "group-admin-only" error. The spec promises bot admins can execute this command in groups. The group admin effectively has more power than the bot admin within that group scope.
    SUGGESTED-FIX-CLASS: missing-auth-check

  - CATEGORY: PERM-ESCAL
    SEVERITY: medium
    PROMISE: "Bot-admin only: /remove-source, /source-enable, /source-disable" (commands.md §Permission model) — these commands are bot-admin tier and should be executable by a bot admin regardless of scope.
    GAP: SourceDisableCommandHandler.java:103, SourceEnableCommandHandler.java:131, RemoveSourceCommandHandler.java:118 — the `isGroupAdmin(group)` gate returns the error reply immediately if the caller is not the group admin, before the code reaches the downstream bot-admin check. A bot admin in a group who is NOT the group admin is denied execution.
    REPRO: A bot admin (is_admin=true) who is a regular member of a group (is_group_admin=false) sends `/source-disable <id>` in that group. The `isGroupAdmin(group)` helper returns false, so the handler returns `ERROR_GROUP_ADMIN_NOT_IN_V1`. The bot admin never reaches the actual bot-admin-gated logic. The spec says these are bot-admin only commands with no group-admin prerequisite.
    SUGGESTED-FIX-CLASS: missing-auth-check

  - CATEGORY: AUDIT-EVASION
    SEVERITY: medium
    PROMISE: "Authorization evaluation order on every inbound message: ... 8. Audit-log the intent." (security.md §Authorization model step 8)
    GAP: FollowTagCommandHandler.java (line 66 comment: "writes zero rows to audit_log"), UnfollowTagCommandHandler.java (same pattern), LangCommandHandler.java (line 74 comment: "writes zero rows to audit_log") — these handlers now execute privileged group-admin state mutations (modifying the group's tag preferences or language, affecting all group members' digests) in group scope with no audit trail. Before this diff, group scope was unconditionally rejected so the lack of audit was moot. Now the code path is live and a group admin can modify shared group state with no record in audit_log.
    REPRO: A group admin sends `/follow-tag sensitive-topic` in a group. The handler modifies `scope_tag` for that group (affecting all members' periodic digests). No audit_log row is written. A later investigation cannot determine who added or removed tag preferences from the group scope, or when. The spec's step 8 requires audit-logging the intent for every inbound message that reaches execution (step 9).
    SUGGESTED-FIX-CLASS: audit-log-coverage

OUT-OF-MODEL:
  - The `InboundContext` bean exposes public `setSenderContactId()` and `setAdapterName()` setters on a `@RequestScoped` CDI bean. While CDI request-scope provides isolation between concurrent requests, any code running in the same request scope (e.g., a hypothetical injection through a CDI extension or interceptor) could override the sender identity before the handler reads it. This is architectural (CDI scope is the framework's trust boundary) and not a threat-model finding, but the setters increase the attack surface if CDI's scope isolation is ever weakened.
