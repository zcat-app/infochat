OUT-OF-MODEL:
  - Terminal echo of the remote LLM API key. prod/scripts/2-secrets.sh:356
    reads the key with `read -rp` (no `-s` flag), so the key is echoed to the
    terminal as the operator types it. This is a shoulder-surfing /
    terminal-capture exposure of a credential. It falls outside the documented
    threat model: §Secrets handling constrains how secrets appear in logs,
    audit rows, and committed files (all of which the diff handles correctly —
    git-ignored runtime dir, mode-0600 secrets.env, openssl-rand passwords,
    no-overwrite resume), not interactive entry on a trusted operator console.
    The threat model also places "supply-chain attacks on operator
    infrastructure" out of scope for v1. Flagging so the user can decide
    whether to switch to `read -rsp` as cheap hardening.

  - Whole diff is operator-trusted setup tooling. The threat model states
    "Operator-set config (properties files, bootstrap JSON) is trusted" and
    treats the operator host as out of the adversary's reach. prod/setup.sh and
    its subscripts run by the operator on their own host before the services
    start; none of the documented adversary entry points (adapter inbound,
    feed content, LLM output, the LLM tool surface, HTTP health endpoints) is
    touched. The sensitive-surface inventory correctly reports
    "(none touched)" for authentication, authorization, input validation, ban
    handling, and audit-log writes. No threat-model commitment about runtime
    behavior is in scope for this diff to deliver or break.
