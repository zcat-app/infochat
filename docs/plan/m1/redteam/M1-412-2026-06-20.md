RED-TEAM VERDICT: CLEAN

The M1-412 diff is a cleanup / comment-sweep / low-severity-parity ticket.
Every changed line was audited against docs/spec/security.md. No commitment
in the threat model is weakened; two changes strengthen documented defenses.

Audited surfaces and conclusions:

- PartitionScan.java / PerSourceUnknownTracker.java / ReEvaluationJob.java /
  NostrStreamSource.java — consolidate four/seven copies of
  PARTITION_SCAN_SLACK into one public constant on PartitionScan. The value
  stays Duration.ofDays(2) at every former and new reference site; the SQL
  INTERVAL strings produced (windowSeconds + slack, postRetentionDays + slack)
  are byte-identical to before. Behavior-preserving. No effect on the
  re-evaluation / quarantine-exhaustion commitments (§Re-evaluation job,
  §Per-source UNKNOWN auto-disable).

- SafeLog.formatSafe (infochat-core) — now applies stripControls() around
  Redactor.redact(msg). This STRENGTHENS §"User content in exceptions" and the
  §"User-content logging" log-injection surface: CR/LF/ANSI in the caller msg
  can no longer forge a second log line. Class names (the only other content
  that traverses) are not attacker-controlled. No gap introduced.

- AnthropicProvider / LlmHttpSupport.requirePositiveMaxTokens — adds a
  config-boundary guard (operator-set config is trusted per §Threat model, but
  validating a numeric property at startup is legitimate boundary validation
  per CLAUDE.md §No-defensive-code). STRENGTHENS the §Failure-handling
  contract by failing a misconfig at boot instead of masquerading as a
  recurring Stage 2 transient outage. No gap.

- SignalGroupHandler — hoists the usableTimestamp(envelope, dataMessage)
  computation above the oversize-drop branch and reuses it for both the
  oversize diagnostic id and the accepted-frame id. usableTimestamp is a pure
  function of the unchanging (envelope, dataMessage) pair; every branch outcome
  (oversize drop, mention drop, null-timestamp drop, accept) is identical to
  before. The §6.3.10 size-cap shed and the daemon-trust-boundary null guard
  are unchanged. Behavior-preserving.

- SignalAdapter — operator-precedence fix for an internal endpoint-probe
  connect timeout ((int) X * 2 -> (int) (X * 2)). The interval is
  operator-config-driven, not attacker-controlled, and the probe targets a
  co-located endpoint, not a user-supplied URL — outside the SSRF allowlist
  surface. No threat-model bearing.

- SimpleXAdapter — comment-only edit restating the documented no-session-auth
  loopback-IPC model (matches §Trust boundary 7). No code change.

- SimpleXMessageCodec.decodeError — comment-only expansion. The decodeError
  body (forwarding a RECOGNIZED errorTag verbatim into CommandError.detail())
  is UNCHANGED by this diff; only the surrounding comment block was edited. The
  comment correctly flags the residual assumption (simplex-chat error tags are
  a bounded enum-like vocabulary, not free-form prose). Verified against the
  file: the UNRECOGNIZED path already collapses to a fixed sentinel, so no
  echoed inbound bytes flow into the MessagingException / DEBUG-log path under
  the current tag vocabulary. Not a diff-introduced gap; the residual risk is
  pre-existing and already documented in-code.

- IpBlocklist.java — inlines isLoopbackV6 / isAllZeroV6 into the two call
  sites using the existing allZero(raw, off, len) helper. Same predicates
  (all-16-zero for ::, first-15-zero + last==1 for ::1). The blocklist
  coverage required by §SSRF (loopback / unspecified / IMDS ranges) is
  unchanged. Behavior-preserving.

- PinnedDnsResolver.activePinsSnapshot — javadoc-only addition documenting
  why the test-jar-consumed method stays in main sources. No code change; the
  DNS-rebind / pin machinery (§SSRF TOCTOU defense) is untouched.

- SsrfGuardedHttpClient — comment-only edit on the cross-origin redirect
  check explaining the from.getScheme() non-null precondition. No code change;
  the per-hop re-resolution and redirect cap (§SSRF) are untouched.
