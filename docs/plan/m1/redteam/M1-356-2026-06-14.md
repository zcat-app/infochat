OUT-OF-MODEL:
  - Jackson parse-failure cause chain still echoes a body snippet. In all
    three providers (e.g. OpenAiCompatibleProvider.java:206-208,
    OpenAiCompatibleEmbeddingProvider.java:190, AnthropicProvider.java:181)
    the `catch (IOException e)` re-throws with the Jackson `IOException`
    attached as the cause. Jackson `JsonParseException` messages embed a
    fragment of the offending source ("...[Source: (String)\"<body>\"...]"),
    so an attacker-controlled LLM endpoint that returns malformed JSON could
    surface a body fragment IF the resulting exception's cause message is
    ever logged raw. This is OUT-OF-MODEL for THIS diff: (a) the cause-chain
    attachment is pre-existing untouched code (unchanged at line 208), not
    introduced by the diff; (b) the threat model's §"User content in
    exceptions" mitigation is the `SafeLog` utility, which "drops the
    exception message body, retains only the exception class name, and
    truncates the cause chain to class names" — that mechanism lives outside
    this diff and is the documented closure for exactly this surface. The
    diff itself only removes the explicit `preview(responseBody)` echo, which
    is a net strengthening. Flagged so the user can confirm the LLM-provider
    exception sites are in fact routed through SafeLog at their call sites
    (not visible in this diff).

  - Startup disclosure WARN logs the raw base-url from the config snapshot
    (LlmRouterStartupGuard.java:204-205, 308-309) rather than a validated
    one. A base-url embedding userinfo credentials would be logged verbatim
    here. This is OUT-OF-MODEL: operator-set config is trusted by the threat
    model (§Threat model: "Operator-set config ... is trusted"); the
    credential-bearing-base-url surface is closed at the config boundary by
    `LlmHttpSupport.requireHttpBaseUrl` (M1-330, pinned by
    BaseUrlCredentialRedactionTest), which rejects userinfo before a provider
    is constructed; and the stdout console redactor (§Secrets handling) would
    additionally catch any token-shaped substring. Emitting the base-url on
    startup is the explicit spec intent (§llm.md "an explicit confirmation
    log line on startup so operators see when post bodies start leaving the
    host"). No promise is undelivered.
