FINDINGS: (none)

OUT-OF-MODEL:
  - EmbeddingWorker's new pgvector-rejection branch
    (infochat-collector/.../embedding/EmbeddingWorker.java lines 376-412)
    holds the post at embedding_done=FALSE and retries on later ticks rather
    than the §Failure handling commitment "Embedding failure → release without
    a vector; the post is otherwise normal and fully visible." This skip-and-
    retry behavior runs AFTER the Stage 1/2 security boundary (the actual
    security boundary per §Ingest pipeline): it cannot release un-vetted content
    and cannot hide a benign post — it only delays a vector for an already-vetted
    READY post, mirroring the pre-existing dimension-mismatch (l.331) and
    non-finite (l.356) skip paths. It is a degraded-availability / correctness
    nuance of the embedding stage, not a threat-model violation. Flagged so the
    user can decide whether the spec's "release without a vector" wording should
    explicitly cover this server-side literal-rejection skip path, or whether the
    retry-until-recovery behavior is the intended treatment for a transient
    provider-output anomaly.

AUDIT NOTES (not findings):
  - The classloader change in Stage2Worker.loadPromptTemplate (own loader, never
    TCCL) and TaggerWorker.loadResource is a STRENGTHENING of trust boundary 4
    (§Trust boundaries — "Collector ingest → user-visible store") and the Stage 2
    security boundary (§Ingest pipeline). It removes the prior TCCL-preference
    path by which a foreign classpath entry could shadow the real
    prompts/security-judge.md and silently weaken the Stage 2 injection check.
    Test Stage2WorkerPromptClassloaderTest pins this with a hostile parent=null
    URLClassLoader on the TCCL. No weakening of any commitment is introduced.
  - The pgvector-rejection branch logs scalar fields only (rejection.getSQLState())
    and does NOT pass the caught Throwable to the SLF4J logger
    (EmbeddingWorker.java lines 402-406), in compliance with §Secrets handling —
    "User content in exceptions": "The original Throwable is never passed to the
    underlying SLF4J logger." It mirrors the sibling non-finite (l.356) and
    dimension-mismatch (l.331) scalar-only branches and the SafeLog.warn
    convention at attemptEmbed (l.427). The earlier draft of this branch (visible
    in the in-repo redteam note docs/plan/m1/redteam/M1-354-2026-06-14.md) passed
    the raw SQLException as the final LOG.error argument; that INFO-LEAK was
    remediated in the diff under audit (the current head logs no Throwable).
  - The IllegalStateException catch is fail-safe, not fail-open: when
    pgvectorFormatRejection(e) finds no SQLState-class-22 cause in the chain
    (lines 391-393), the original exception is rethrown, so genuine infrastructure
    SQLExceptions (connection loss, integrity violations) still propagate as real
    failures rather than being silently coalesced-and-skipped.
  - Both finite-vector security guards (non-finite component, dimension mismatch)
    above the changed transaction block remain intact (lines 312-369); the
    formatVector refactor (now throws SQLException instead of wrapping in
    IllegalStateException) removed no guard the threat model relies on.
  - The TaggerWorker ObjectMapper lines flagged in the sensitive-surface
    inventory (193, 203) are unchanged context — this diff only altered
    loadResource's classloader and visibility; no input-validation surface was
    weakened.
