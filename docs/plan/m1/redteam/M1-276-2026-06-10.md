RED-TEAM VERDICT: CLEAN

No findings. The diff was audited against docs/spec/security.md in full.
Every changed surface either implements a hardening the threat model
already commits to, or is data-integrity/performance work outside any
spec security promise. Specific surfaces examined and cleared:

1. ReEvaluationJob.splicePlaceholders / reconstructOriginalBody
   (eval/reeval/ReEvaluationJob.java:413-79). The reconstructed
   pre-redaction body feeds ONLY stage2Worker.judgeBody — the Stage 2
   judge, which the spec (§Ingest pipeline — Stage 2) says sees the
   original pre-redaction content inside an untrusted-content wrapper.
   The DB body stays redacted (applyBenignReEval leaves body untouched;
   only /quarantine approve lifts redactions, §Quarantine workflow).
   The new single-pass splice is strictly safer than the prior
   order-dependent String.replace loop: a [REDACTED:<id>] token with no
   quarantine row is emitted verbatim ("user content wearing a
   placeholder costume"), and spliced original_html is never rescanned,
   so a placeholder-shaped literal inside quarantined content cannot
   become a substitution site. This upholds, not weakens, the §Ingest
   pipeline per-row-random-id forgery defense. Linear O(n) scan, cursor
   always advances — no ReDoS / expansion DoS. No user-visible
   de-redaction path. CLEAN.

2. checkNeedsReviewDepth / countNeedsReviewWithinScanWindow
   (eval/reeval/ReEvaluationJob.java:543-150). Spec §Re-evaluation job
   "Absolute NEEDS_REVIEW depth alert" promises operators notice a
   sustained backlog independent of per-source ratio. The change bounds
   the COUNT by fetched_at >= now() - (retention + 2d slack). Falsifier
   checked: could a real NEEDS_REVIEW row survive OLDER than that window
   and be silently dropped from the count? No — PartitionPruner.java
   drops post partitions purely by fetched_at at postRetentionDays with
   NO status exemption ("destructive by design — the rows are gone"), so
   any row older than retention is physically pruned and cannot exist to
   be counted. The slack widens the window 2 days BEYOND retention, so
   the bound is a superset of all surviving rows. Cannot undercount. The
   alert guarantee is preserved. CLEAN.

3. Kind6Handler post-plus-edge single transaction + PostPersister
   caller-connection overload (stream/nostr/Kind6Handler.java:125-187,
   outbox/PostPersister.java:92-115). Implements the §Per-source trust
   boundaries / Nostr §Repost handling commitment that a kind-6 stores
   the post_reference edge; the new atomicity (edge-write failure rolls
   the post back) strengthens it — no edgeless committed kind-6 post.
   Self-connecting overload preserved; caller's connection is never
   closed by the inner persist. CLEAN.

4. NostrStreamSource since-cursor scan window
   (stream/nostr/NostrStreamSource.java:478-507). Bounds MAX(published_at)
   by the fetched_at retention+slack floor for partition pruning, with a
   documented unbounded fallback for stale sources. Cursor-correctness:
   published_at is clamped to fetched_at at persist, so a lower `since`
   only replays events the dedup filter drops. The §SSRF reconnect
   commitments (re-resolve, peer-IP-change hard close) are untouched.
   CLEAN.

5. TagVocabulary scheduled refresh (eval/tagger/TagVocabulary.java).
   Startup load fatal; refresh keeps last-good set on transient DB
   failure, logs only exception class name (consistent with §Secrets
   handling — User content in exceptions). Volatile immutable-set swap is
   reader-safe. No spec security promise governs vocabulary freshness;
   tagger failure already falls back to source.bootstrap_tags
   (§Failure handling — Tagger). CLEAN.

6. RedditResponseParser missing created_utc -> fetchedAt substitution
   (fetcher/reddit/RedditResponseParser.java:62). Data-integrity fix;
   logs only sourceId, never the upstream-controlled item fields
   (§User-content logging). published_at ordering for searchPosts is not
   a documented confidentiality/integrity security promise; an attacker
   omitting a timestamp only dates the item at receipt-now, the same as
   every freshly fetched post. CLEAN.

7. V49 NULLS NOT DISTINCT on idx_post_ref_unique_edge. Rejects duplicate
   unresolved repost edges — mild edge-table bloat hardening, positive.
   No security promise affected. CLEAN.
