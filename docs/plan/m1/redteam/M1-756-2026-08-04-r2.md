    PROMISE: docs/spec/security.md §Secrets handling — "The post-setup
              `prod/switch-llm.sh` backend switcher records the LLM API key in

              in the same shape.
    GAP: The remediation bullet itself (docs/spec/security.md:1901-1916, new in
         this diff) asserts as fact: "every other translator caller is a user
         action (`/summary`, `/saved`, a chat turn), whereas this one recurs
         twice a day per group with no user in the loop". That claim is false
         against main source, and two of the three counter-examples sit inside
         the very render the bullet is describing:
           - infochat-provider/src/main/java/app/zcat/infochat/provider/digest/
             DigestRenderer.java:793 — `translationPipeline.run(sanitized,
             langCode)` in `appendClusterProse`: one translator call per lead
             cluster (NORMAL and FULL, `leadSize` default 3, :353-355) and, in
             FULL mode, one per cluster of EVERY surviving section with the item
             cap lifted to `Integer.MAX_VALUE` (:337-343). Reached from the
             scheduler by `DigestWorker.executeSlot` -> `renderSections`. It
             PRE-DATES this diff — the diff only adds a comment to the degraded
             arm of that method.
           - infochat-provider/src/main/java/app/zcat/infochat/provider/digest/
             CategoryRollupGenerator.java:213 — `translationPipeline.run(
             sanitized, langCode)`, one call per surviving section (up to
             `infochat.digest.max-categories`, default 8), on the same scheduled
             render, also pre-existing.
           - infochat-collector/src/main/java/app/zcat/infochat/collector/eval/
             translation/IngestTranslationWorker.java:232 `@Scheduled(every =
             "{infochat.llm.translator.poll-interval}")` -> :318
             `provider.generate(ModelTask.TRANSLATOR, "", userPrompt)` — a
             continuously polling, wholly unattended `ModelTask.TRANSLATOR`
             consumer in the Collector, with no user anywhere in the loop.
         The consequence is an understated enumeration, not merely a wrong
         sentence. The bullet's only quantification of the unattended stream is
         "up to `infochat.digest.translation-max-per-render` feed headlines
         reach `ModelTask.TRANSLATOR` at each digest slot", and it closes by
         telling the operator what they are "therefore consenting to". An
         operator sizing that consent from the enumeration gets "<=5 short feed
         headlines per non-English group per slot, everything else per-request",
         while the same slot already ships per-cluster and per-section LLM prose
         about that group's stories through the same task, and the Collector has
         been shipping every ingested non-`en` post's title and body through it
         all along. §Secrets handling is the enumeration the remote-routing
         consent rests on, and this bullet explicitly hands that text downstream
         ("M1-758 owns that text"), so the understatement propagates into the
         operator-visible disclosure rather than staying in the spec.
    REPRO: 1. Operator reads §Secrets handling (or the M1-758 disclosure derived
              from it) and routes `translator` to a remote provider, sizing the
              unattended exposure at "<=5 short feed headlines per non-English
              group per digest slot; every other translator call is something a
              user asked for."
           2. Deployment has one approved group on `/lang cs` with
              `groups.digest_mode = full`. At the first scheduled slot
              `DigestScheduler` -> `DigestWorker.executeSlot` ->
              `DigestRenderer.renderSections` generates one SUMMARIZER prose
              call per cluster of every surviving section (cap lifted,
              DigestRenderer.java:337-343) and POSTs each non-degraded result to
              the remote translator (:793), plus one roll-up translation per
              section (CategoryRollupGenerator.java:213) — tens of prose bodies,
              not five headlines. No user acted.
           3. Independently and continuously, the Collector's
              `IngestTranslationWorker` POSTs every ingested `cs` post's title
              and body to the same remote endpoint on its poll interval — it has
              been doing so since before the group existed.
           4. The remote endpoint operator receives a continuous, unprompted
              stream materially larger than the one the operator consented to,
              and the enumeration the consent was built on says the digest's
              unattended contribution is five headlines.
