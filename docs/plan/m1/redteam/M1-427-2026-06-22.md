RED-TEAM VERDICT: CLEAN

The diff under audit is operator-side backup tooling (prod/scripts/backup.sh)
plus matching documentation edits (SETUP_GUIDE.md, docs/design/07-deployment.md)
and lifecycle bookkeeping (STATUS.md, the M1-427 ticket frontmatter). It adds
no code reachable by any actor inside the documented threat model.

Audited against the threat model's commitments; no gaps found:

- Threat-model actors are adversaries on the messaging adapters, on ingested
  feeds, and the LLM black box (security.md §Threat model). backup.sh is a cron
  wrapper invoked by the operator, whose config and host actions are explicitly
  TRUSTED ("Operator-set config (properties files, bootstrap JSON) is trusted").
  None of the adversary-reachable surfaces (Provider intake, Collector ingest,
  LLM tool surface) are touched — confirmed by the sensitive-surface inventory
  (auth, authz/isolation, input-validation, ban, audit-log: all "none touched").

- §Secrets handling: secrets MUST NOT leak to non-audit logs. The script never
  reads or echoes a secret on the host. The DB password (INFOCHAT_DB_PASSWORD)
  stays inside the postgres container's environment (line 254-256: the password
  is dereferenced only inside the `sh -c` body run by `docker compose exec`,
  never on the host); the host-side echo (line 253) is a fixed string naming the
  artifact path, not the command with the password. read_dotenv_value
  (lines 225-237) only reads INFOCHAT_*_DATA_DIR filesystem paths, not secret
  material, and those values are operator-written config, not adversary input.

- §What's intentionally NOT in v1 — "DB-at-rest encryption — operator's
  responsibility." The script and docs defer backup encryption to the operator
  (script header lines 181-183; SETUP_GUIDE.md "Keep the backup folder
  encrypted at rest"). Consistent with the spec, not a regression.

- No INJECTION surface: the grep key (line 226) and the tar member list
  (lines 268-287) derive from fixed literal env-var names and from operator-
  written secrets.env values, with no path under adversary control. There is no
  eval/source of untrusted data; `source`-ing secrets.env is deliberately
  avoided (lines 219-224 document the dotenv-vs-shell escaping rationale).

- No AUDIT-EVASION gap: the threat model's audit-log requirements
  (§Authorization model step 8, §User ban, §Re-evaluation job) cover in-band
  application admin operations dispatched through the deterministic command
  path. A host cron backup is an out-of-band operator action; the Admin DB role
  grants (§DB roles) do not include or require an in-band audit row for it.
