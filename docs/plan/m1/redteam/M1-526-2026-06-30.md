OUT-OF-MODEL:
  - Cross-adapter pool free is permitted but not addressed by the threat
    model's blast-radius commitment. RecoverPoolCommandHandler.freeMode
    (infochat-provider/.../command/RecoverPoolCommandHandler.java:309-363)
    gates on the INBOUND-adapter admin row
    (lookupUser(inboundAdapter, callerContactId)) yet frees by the
    user-supplied TARGET natural key (targetAdapter, upstreamGroupId),
    which may name a DIFFERENT adapter — the code comment at
    detailsJson (lines 393-403) explicitly notes "a Signal admin can free
    a SimpleX residual." security.md §Authorization model and
    §Per-adapter admin threat profile scope ONLY /grant-admin and
    /revoke-admin to the inbound adapter ("the per-adapter scoping bounds
    the blast radius of a single-adapter compromise"), and explicitly
    carve out /invite create as intentionally cross-adapter; /recover-pool
    is not mentioned in either direction. Consequence of a single-adapter
    admin compromise: the attacker can free auto_joined_group slots
    belonging to OTHER (uncompromised) adapters, dropping each adapter's
    D47 global-cap count and re-enabling further auto-joins on adapters
    the attacker never compromised. The effect is low-impact (each extra
    auto-join still requires a genuine inbound group invitation on the
    other adapter, slots re-saturate, and the operation is admin-only and
    audit-logged) and the actor is trusted operator-tier config, so this
    is NOT an adversary-reachable path under the documented model — but
    the spec is silent on whether non-elevation admin commands inherit the
    inbound-adapter blast-radius scoping. Flagged so the user can decide
    whether to (a) scope /recover-pool to the inbound adapter, or (b)
    document cross-adapter free as an intentional carve-out like
    /invite create. Not counted as a FINDING: no quoted threat-model
    commitment is breached.
