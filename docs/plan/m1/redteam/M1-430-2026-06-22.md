RED-TEAM VERDICT: CLEAN

OUT-OF-MODEL:
  - Residual off-loopback exposure window (defense-in-depth, not a spec gap).
    The M1-430 guard is a runtime detector for trust boundary #7
    (security.md §Trust boundaries #7), which commits only that the SHIPPED
    DEFAULT binds the simplex-chat ws-port to loopback and that exposing it
    off-loopback is "an explicit operator action, never a default." The spec
    makes no commitment to detect-and-refuse an off-loopback bind at runtime;
    the new SimpleXLoopbackProbe + onStartupBindCheck wiring is voluntary
    hardening beyond the spec. A small TOCTOU window nonetheless exists: from
    the instant simplex-chat binds the port off-loopback until the supervisor's
    awaitBindThenProbe -> isExposedOffLoopback -> destroyCurrentProcess()
    completes (SimpleXSubprocess.java:305-317), an external attacker who already
    has a TCP connection to the non-loopback port could drive the bot's SimpleX
    identity. The guard closes the socket (kills the child) before latching
    FAILED, so the window is bounded by one off-loopback connect + a SIGTERM,
    and it only opens in a configuration the spec already classifies as an
    explicit operator action voiding the no-auth property. Surfaced so the user
    can decide whether the residual window warrants a pre-bind check (e.g.
    validating the binary's -p bind address before exposing the port) rather
    than the post-RUNNING probe; not a FINDING because no spec promise is
    broken.
  - Probe enumeration scope. SimpleXLoopbackProbe.nonLoopbackLocalAddresses()
    (SimpleXLoopbackProbe.java:142-173) only collects addresses on interfaces
    reporting isUp() at probe time. A bind to a non-loopback address whose
    interface is administratively down at start, or added after enumeration,
    is not probed and reads as loopback-only. This is operator-infrastructure
    territory (the operator both chose a non-loopback-binding binary AND brought
    the interface up later) and falls under the "explicit operator action"
    carve-out of trust boundary #7, so it is out-of-model rather than a FINDING.
