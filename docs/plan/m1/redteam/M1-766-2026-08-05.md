         from a field the sanitizer never sees — with no redaction marker and no
         `LLM_OUTPUT_SANITIZED` audit row, which is exactly the outcome the
         flag-position rule was written to prevent. This shape is PRE-EXISTING in
         the method (the diff does not introduce the unsanitized display-name

         (adding the LLM-authored `title_en`/`body_en` anchor), so it is reported
         here rather than assumed covered elsewhere.

OUT-OF-MODEL:
  - CPU cost of the degraded path roughly doubles: `DisplayHeadline.derive`
    (DisplayHeadline.java:260-271) now runs `boundForScan` + `flattenToOneLine` +
    `LlmOutputSanitizer.sanitize` (NFKC, link-flatten regex, 24 closed-list
    matchers, 10 tokenizer scans) TWICE per post — once for the original, once
    for the `title_en`/`body_en` anchor, each up to `BODY_SCAN_LIMIT` (2000)
    chars — on the very path chosen because the system LLM budget was already
    exhausted or the render already timed out (DigestWorker.java:243/:288). The
    work stays linear and post-count-bounded, and security.md commits no
    per-post scan budget, so this is noted rather than filed: if the threat model
    wants to keep the "degraded = cheap" property it should state a bound.
  - Spec drift, not a security gap: security.md §Failure handling describes the
    degraded fallback as "the headlines + URLs + post UIDs degraded form". The
    diff adds a second, bracketed publisher-text line per post to that form
    (DegradedDigestRenderer.java:111-113, SummaryProseGenerator.java:286-288)
    without amending that sentence. Flagged so the user can decide whether the
    spec's description of the degraded render shape needs updating.
  - Content provenance on the degraded digest: for an `en` reader the primary
    line is now the LLM-authored ingest translation rendered BARE (no bracket,
    by design per D29 (c)), i.e. group members see model-generated text where
    the publisher's headline used to be. The original follows bracketed, so
    provenance is recoverable, and no security.md clause governs this — noted
    only because it changes what "the feed said" means on an unattended group
    broadcast.
